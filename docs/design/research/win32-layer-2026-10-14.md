# Win32 layer: second opinion and import census (2026-10-14)

Author: Claude (research agent for the lead), directive context f5-00.
Subject: [win32-personality-contract.md](../win32-personality-contract.md)
(1545 lines, read in full; cited below as `contract:LINE`). No build, QEMU
or hardware run was made. The census figures come from the original
binaries of freely distributed demos and shareware. They were read with
HTTP range requests or downloaded into the session scratchpad, parsed with
a self-written PE import reader, and deleted afterwards. No payload byte
entered the repository.

## 1. Summary

1. The contract's layering is sound: a `win32` personality on the CiukiOS kernel,
   CiukiOS-written core DLLs, reused Wine DLLs for the long tail, `w32srv`, and protocol v3.
2. The census (§3) gives 596 distinct system imports for the game processes of
   Half-Life, Quake II, StarCraft, Age of Empires and Diablo.
   The split is kernel32 205, user32 183, gdi32 83, winmm 38, wsock32 20, crtdll 17,
   and 50 more across 12 further DLLs. The installers add 112.
3. 93 functions are imported by all five games. Almost all belong to the MSVC 4–6
   static-CRT startup block plus basic GDI, which makes a natural first milestone.
4. None of the 46 analysed PE images has a TLS directory, bound imports or delay
   imports. Several are DLLs based at `0x00400000`, or carry Win32s-era header
   versions (1.11, 3.10). P1 loader effort should go to relocation and header tolerance.
5. Games, not only installers, statically import `shell32`, `comdlg32`, `version`,
   `comctl32`, `ole32`, `imm32`, `msvfw32`, `winspool.drv`, `crtdll`, `dplayx` and
   `wsock32`. The contract places several of these in installer-only or F6 phases (§2).
6. Imports by ordinal are common: `wsock32`, `dplayx`, `comctl32#17` and `winmm#2`.
   Builtins need Windows-exact ordinal tables. Wine 11.18 `winmm.dll` lacks ordinal 2,
   which the Diablo installer imports.
7. Gate title 6, the Worms Armageddon demo, has an **InstallShield 5 installer with a
   16-bit (NE) `SETUP.EXE`**. As written, W24 blocks a gate title.
   The NFS II SE demo's NE stub is a plain PKZIP self-extractor.
8. 64-bit Windows solves the same problem by substituting 32-bit replacements for a
   fixed list of 16-bit installers (InstallShield 5.x, MS Setup 1.2–3.01).
   f5-19 should start there, not with a WOW subsystem.
9. The owner and lead decisions at `contract:1529-1545` were not folded into the body
   (Q3, Q6, Q8, Q9, Q10, Q15). Eight contradictions follow (§2).
10. Q10 says "FreeType", but the fonts contract chose stb_truetype and forbids
    untrusted game fonts. Q6 picks FluidR3 GM, whose Debian package alone is
    119.6 MB compressed, against a 128 MiB machine.
11. The Wine reuse closure is larger than the P4 list. Wine 11.18's upper DLLs also need
    `kernelbase`, `ucrtbase`, `combase`, `coml2`, `rpcrt4`, `shcore`, `cfgmgr32` and `sechost`.
    They total 21.4 MB of files, and the 40-function audit stop is exceeded at once (§2, row 13).
12. Wine builds its PE DLLs against Wine's own headers and CRT, with clang as the default
    cross compiler. It does not use a mingw-w64 header set, so `contract:1346` is inaccurate.
13. DirectDraw primaries need present triggers. The 8-bit titles never `Flip`. Diablo
    `Lock`s or `BltFast`s the primary, and Quake II flips. Present on Unlock, Blt,
    ReleaseDC, Flip and SetEntries, coalesced to 60 Hz, as Wine, DDrawCompat and
    cnc-ddraw do. The contract also never says who draws the system cursor under a full-screen lease.
14. Quake II and Half-Life use the `SetCursorPos`/`GetCursorPos` recentring idiom, and
    Quake II falls back to `DSSCL_WRITEPRIMARY`. user32 needs a synchronous cursor
    model, and dsound needs primary-buffer locking.
15. Recommended sequencing (§4) has four parts:
    - Freeze the `CIUKI_SYS_W32` record header first (a small f5-03a).
    - Then develop the kernel and the user-mode DLLs in parallel, with the user-mode
      side running on a Linux i386 host adapter built on `tests/host/native_samples_host.c`.
    - Add a census-driven stub generator early.
    - Split f5-10 and f5-19.
16. Option C becomes stronger under the LGPL decision (Q2). The core may lift Wine
    *source* (the DIB engine in `dlls/win32u/dibdrv`, the dsound mixer), not only reuse DLLs.
17. Host testing (§5) has four tiers: pure-C models, the w32host adapter running real PE
    images, Wine 11.18 on this workstation as a differential oracle for NT-equal
    behaviour, and Wine conformance tests built as PE fixtures, never shipped in the image.
18. Windows 98 support for SSE is documented by Microsoft
    ([press release, 1999-02-17](https://news.microsoft.com/source/1999/02/17/microsoft-products-speed-along-with-new-intel-pentium-iii-processor/)).
    This closes the open point of W6 (`contract:192-195`).
19. No primary source was found for the Windows 9x `QueryPerformanceFrequency` value.
    Wine documents 1,193,182 as the NT value
    ([commit 288ebd3](https://goma.googlesource.com/wine/+/288ebd3244fe0e00b1c9c7c4f5baa4092bb28a6c%5E%21/)).
20. Not censused: the Civilization II demo (only as a 303 MB RAR bundle) and the
    remaining gate titles 5, 7, 8, 9 and 10. The f5-02 tool should reuse the method of §3.

## 3. Import census

### Method and sources

The sources were the Internet Archive items of the contract plus three more:

- Quake II test: `QuakeII_1020/q2_test.zip`.
- StarCraft disc image: `cdrom-starcraft-shareware/StarcraftShareware.img`, Mode 2/2352.
- NFS II SE demo: `NFS2SEA/NFS2SEA.EXE`.

Extraction:

- Blizzard installers are an MPQ appended to a PE stub. The game files were
  read by range requests:
  - Diablo `AUTORUN.EXE`, ISO LBA 92, MPQ at file offset 1,019,392, 35 blocks.
  - StarCraft `INSTALL.EXE`, LBA 32436, 65 blocks, game files under `files\`.
- Decompression used a Python port of PKWARE DCL explode (zlib `contrib/blast`).
- AoE was unpacked with `cabextract`.
- The Wise installer's chained raw-deflate streams were inflated.

Counts are distinct `DLL!function` static imports. Ordinals were resolved through
Wine's export tables, and app-supplied DLLs (`storm.dll`, `diabloui.dll`) count as
importers, not exporters. Dynamic loads appear in the notes: they come from string
scans for `LoadLibrary` targets, and the COM method surface is not included.

## 4. Recommended architecture

### 4.1 Kernel versus ring 3

I agree with W2 (`contract:165-172`). Refinements:

| Concern | Placement | Note |
| --- | --- | --- |
| Address space, sections, FS/TEB, exception delivery, waits, handles, APC, message-queue objects, present lease | Kernel (`CIUKI_SYS_W32`) | As the contract says |
| System-call gate for core DLLs | A `int 0x80; ret` stub in the read-only shared page at `0x7FFE0000` | Core DLLs call through it. The host adapter (§5) maps the same page with a jump into C. Application `int 0x80` keeps W2 semantics. |
| HWND tree, z-order of a process's own windows, child-window clipping, hit testing, dialogs, controls | user32, per process | Only top-level windows reach protocol v3 |
| Top-level directory (`FindWindowA`, `EnumWindows`, `GetForegroundWindow`), atoms, registry, PROGMAN service | `w32srv` | `FindWindowA`/`EnumWindows` are cold paths: start-up single-instance checks in Diablo, StarCraft and AoE |
| PROGMAN DDE | user32 DDEML talks to the `w32srv` endpoint directly when the service name is `PROGMAN` | Removes the need for kernel `WM_DDE_*` HGLOBAL marshalling (§2 row 20). Generic cross-process DDE stays unsupported, with a W21 record. |
| Cursor model | user32, synchronous | `SetCursorPos` updates the process-local position at once and sends a warp. While captured or clipped, `GetCursorPos` = last warp + relative deltas received since, clamped to the clip rectangle. This serves the recentring idiom. |
| System cursor under lease | Kernel presenter composites the current cursor bitmap (32×32, from protocol v3 cursor ids) into each lease present | Without it AoE-style titles lose their pointer in full screen |
| Per-process audio mixer | `dsound`/`winmm` personality thread, one `/dev/audio` stream | As W16 |

### 4.2 Loader

The kernel spawn path recognises PE (W1), maps `ntdll` only, and starts it at its
loader entry with the process-parameter block. `ntdll` then maps the EXE through an
image section, resolves imports, and runs TLS callbacks and `DllMain` in order.

What the census adds:

- Relocation of DLLs whose preferred base is the EXE's (`0x400000`) is a day-one need.
- No sampled title of 1996–1999 uses TLS, delay-load or bound imports. Keep their
  fixtures, but schedule them after the relocation, forwarder and ordinal work.
- Export ordinals: generate every builtin `.def` from a pinned ordinal table per DLL.
  Wine's `.spec` files are the starting point, checked against the census. Each
  builtin's manifest entry records them, and T1 checks them.
- A census-driven stub generator (f5-02b): every census `DLL!function` absent from
  the implementation gets a W21 stub. Every title then loads from the first QEMU image
  on, and coverage becomes a number in the `[win32] stub` records.
- Images with header versions 1.0–3.10 and linker 2.x must load (NFS II SE, Smacker,
  CTL3D). Add fixtures for them.

### 4.3 DirectDraw on the presenter and compositor

- **Surfaces.** Every DirectDraw surface is personality-owned system memory. The
  primary is a pagefile-backed section shared read-only with the kernel presenter
  (exclusive) or the desktop (windowed), so a present is one conversion pass with no
  extra copy.
- **Present triggers** (Wine `ddraw_surface_update_frontbuffer`, DDrawCompat
  `PrimarySurfaceImpl`, cnc-ddraw `render.sem`):
  - Mark the region dirty on: `Unlock` of the primary (locked rectangle), `Blt`/`BltFast`
    with the primary as destination, `ReleaseDC` of the primary, `Flip`, and palette
    `SetEntries`/`SetPalette` (whole surface).
  - A personality presenter thread at `interactive` class issues at most one lease
    present per 16.7 ms tick, with a list of at most 16 rectangles, merging beyond that.
    Small dirty regions, as in Diablo and StarCraft, then cost little on a Pentium III.
- **Exclusive mode.** The lease as written (`contract:884-912`) plus three additions:
  dirty rectangles, the presenter-composited cursor, and `GetDC` on a primary in 8 bpp
  (GDI draws into the surface with the DirectDraw palette).
- **Windowed mode.** `DDSCL_NORMAL` primary operations map through the window's
  clipper onto the top-level window's protocol v3 surface, with protocol damage
  rectangles. 8-bit primaries on a 16/32 bpp desktop convert at `Blt` time with the
  current palette, as Wine's GDI path does. Quake II's windowed DIB mode
  (`SetSystemPaletteUse(SYSPAL_NOSTATIC)`) needs `GetDeviceCaps(RASTERCAPS)` without
  `RC_PALETTE` and `SetSystemPaletteUse` returning the previous value. DIB colour tables
  then carry the palette.
- **Source to reuse.** cnc-ddraw (MIT) and DDrawCompat (0BSD) are compatible with any
  licence choice and document the trigger sets. Do not reuse Wine's `ddraw`: it imports
  131 `wined3d_*` functions (§2).

### 4.4 DirectSound on the audio contract

Keep W16: one stream per process, mixer in user mode.

Additions:

- `DSSCL_WRITEPRIMARY` with `Lock`/`Play` on the primary buffer.
- Write-cursor lead equal to the queued device quanta.
- `GetCurrentPosition` derived from the consumed-frame counter (already in the contract).
- 44.1 kHz sources resampled in the personality, or passed through when `/dev/audio`
  accepts the rate (F4: 8–48 kHz).

Alternative to weigh in f5-12, since the core is LGPL:

- Reuse Wine `dsound` (imports only advapi32, kernel32, ole32, ucrtbase; mixer, 3D,
  notifications) and Wine `winmm` waveOut over a CiukiOS `mmdevapi` facade
  (`IMMDeviceEnumerator`, `IAudioClient`, `IAudioRenderClient`) that mixes every client
  of the process into the single `/dev/audio` stream.
- The facade is then the only CiukiOS-specific audio code.
- Measure latency against the ≤ 60 ms F4 budget before choosing.

### 4.5 DirectInput and window input

- DIK = set-1 code, with E0 keys `|0x80` and Pause = `0xC5` (`contract:1016-1018`).
  This is correct and can be implemented directly.
- Mouse: relative deltas from protocol v3 feed both DirectInput buffers and the user32
  cursor model of §4.1. One source avoids double counting when a title mixes
  DirectInput with `GetCursorPos`, as Half-Life does when it loads `dinput` dynamically.
- NFS II SE installs `SetWindowsHookExA` (keyboard) and calls `keybd_event`. Keyboard
  hooks need an in-process implementation: `WH_KEYBOARD` for the caller's own threads.
  Global hooks get a W21 record.

### 4.6 Reused Wine DLLs: the real closure

The P4 list must add two kinds of DLL:

1. **CiukiOS facades:**
   - `kernelbase`: forwarders to the core `kernel32`/`advapi32`, 400+ names in the
     closure, mostly documented Win32 functions.
   - `win32u`: not needed, because user32 and gdi32 are not reused.
2. **Further Wine DLLs:** `ucrtbase` (its imports are kernel32 137 and ntdll 13) or
   `msvcrt`; plus `combase`, `coml2`, `rpcrt4`, `shcore`, `cfgmgr32` and `sechost`.

`rpcrt4` imports `NtFsControlFile`, `NtReadFile` and similar calls for named-pipe RPC.
Keep it in-process only: out-of-process COM (InstallShield 6+ `IKernel.exe`) stays
out of scope until a title needs it.

Replace the audit rule "stop above 40 functions" with: "stop when a non-documented
`ntdll` function outside the list in §2 row 13 is needed". Those are the `Rtl*` string
helpers, `NtClose`/`NtOpenKey`/`NtCreateKey`, and `LdrFindResourceDirectory_U`/`RtlImage*`.

Licence: with the core under LGPL-2.1-or-later (Q2), lifting Wine source into the core
is allowed. Two candidates:

- The DIB engine, `dlls/win32u/dibdrv` (`primitives.c` 315,826 B, `bitblt.c`,
  `graphics.c`, `objects.c`), for f5-10b.
- The dsound mixer.

The GPL-2.0-only kernel (repository `LICENSE`) stays separate. LGPL-2.1 §3 would allow
conversion to GPLv2 if code ever had to move into it. Tests built from Wine's
`dlls/*/tests` are LGPL and are used only as test payloads.

How w32host runs the PE images:

- Maps the image sections with `mmap(MAP_FIXED)`.
- Loads FS with a `set_thread_area` or `modify_ldt` descriptor based at the TEB.
- Serves the `0x7FFE0000` gate page with a jump into a C implementation of the
  `CIUKI_SYS_W32` records, using `mmap`/`mprotect` for VM, futex-backed objects, and
  `clock_gettime` for the shared data.
- Converts `SIGSEGV`, `SIGILL`, `SIGFPE` and `SIGTRAP` ucontexts into
  `EXCEPTION_RECORD`/`CONTEXT` on the faulting stack and enters the registered
  dispatcher. Wine's i386 signal path does the same.

Rules:

- The adapter is host evidence only, as `native_samples_host.c` states.
- QEMU and the laptops remain the authority.
- The adapter's record handlers must share their validation code with the kernel
  (one C file compiled twice), so H1 also tests the kernel's record checks.
- Codex can build and run H0, H1 and H2 in its sandbox if 32-bit Linux execution is
  available there, as the native samples already require. QEMU stays with the lead.
