# EMU10K1 / original Audigy transport

Research and implementation boundary: 2026-10-23, directive f1-117. Host
register models are protocol evidence; analog output, clock accuracy, IRQ
timing and PCI stop behaviour still require the lead's hardware qualification.

The donor is Linux **v6.12**, not a moving branch. The audited files are
[emu10k1_main.c](https://github.com/torvalds/linux/blob/v6.12/sound/pci/emu10k1/emu10k1_main.c),
[emupcm.c](https://github.com/torvalds/linux/blob/v6.12/sound/pci/emu10k1/emupcm.c),
[emufx.c](https://github.com/torvalds/linux/blob/v6.12/sound/pci/emu10k1/emufx.c),
[io.c](https://github.com/torvalds/linux/blob/v6.12/sound/pci/emu10k1/io.c),
[memory.c](https://github.com/torvalds/linux/blob/v6.12/sound/pci/emu10k1/memory.c),
[irq.c](https://github.com/torvalds/linux/blob/v6.12/sound/pci/emu10k1/irq.c),
[voice.c](https://github.com/torvalds/linux/blob/v6.12/sound/pci/emu10k1/voice.c),
[emumixer.c](https://github.com/torvalds/linux/blob/v6.12/sound/pci/emu10k1/emumixer.c),
[kernel register header](https://github.com/torvalds/linux/blob/v6.12/include/sound/emu10k1.h)
and [FX8010 UAPI header](https://github.com/torvalds/linux/blob/v6.12/include/uapi/sound/emu10k1.h).
Intel's [AC97 2.3 specification](https://hands.com/~lkcl/ac97_r23.pdf),
sections 5.7.6–5.7.7, confirms independent left/right line-in selection
(`1Ah=0404h`) and unmuted zero-dB record gain (`1Ch=0000h`). Creative's
[Sound Blaster programming guide](https://pdos.csail.mit.edu/6.828/2018/readings/hardware/SoundBlaster.pdf),
chapters 3–4, remains the reference for the existing virtual DSP/mixer; EMU
interrupts are physical transport events and do not become guest SB IRQs.
The first nine blob identities match peripheral-driver-source-audit.md. The
additional UAPI header is blob `4c32a116e7add4a6a6808516a1d20ab1703ad553`,
GPL-2.0+ WITH Linux-syscall-note, copyright Jaroslav Kysela and Creative Labs.
Its instruction encodings and register numbers are adapted, without its ioctl
ABI. Notices and file-by-file origins are in the credits and driver notice.

Repository comparison: backend.c already owns cyclic publication, pins,
claims, shared IRQ dispatch and stop/quarantine; audio_dev.c mixes native and
virtual SB16 sources at the selected physical rate. Neither ICH BDLs nor VIA
descriptors describe EMU voices. Extend this existing private transport,
retaining the mixer and DOS clocks, and generate DSP code at activation.

* Live! 1102:0002 uses 31-bit DMA, 8192 PTEs, `(phys << 1) | index`.
  Original Audigy 1102:0004 uses 32-bit DMA, 4096 PTEs, `phys | index`.
  Every unused PTE maps one pinned zero page; stereo voices are even/odd.
* The voice cache starts 61 frames ahead (64 minus the three interpolation
  history samples). Cursor reports compensate that initial offset; publication
  still guards the current and following 256-frame period. Fixed 48 kHz output
  preserves the existing native resampler and DOS 48 kHz event timeline.
* A generated ACC3 program routes FX buses 0/1 to analog front and AC97,
  and AC97 input to ADC capture. Unused outputs are explicitly zeroed and
  every unused instruction is overwritten. No downloaded DSP firmware runs.
* A 256-sample hardware interval timer wakes refill. IRQs acknowledge only
  enabled owned causes, count PCI errors and inhibit on failure. Legacy
  SB/MPU/PIC/DMA/AdLib and joystick decoding are never enabled.
* Capture uses its separate, pinned 8 KiB ADC ring with chip-specific rate
  codes. The private kernel interface copies completed half-rings, detects
  overrun/missed wraps and shares the controller stop lifetime. It does not
  add recording to the frozen playback-only /dev/audio or virtual SB16 ABI.
  A public capture API requires a separate lead decision.
* Before reset/programming, refuse active firmware voices, ADC/MIC/FX buffers
  and enabled interrupts. Stop masks sources, stops voices/capture, locks the
  sound/tank caches, clears PCI BME, reads back those gates and verifies stable
  cursors before release. Unreadable or stuck gates quarantine all claims and
  allocations; a timeout is never idle proof. No alternate-backend fallback
  follows a detected-engine activation failure.
* E-MU 1010/0404 and CardBus/PCIe professional models need external FPGA
  firmware and a different analog topology, and are excluded. Audigy LS
  1102:0007 is a different engine. Audigy 2/ZS/Value/Rx and unknown 0004
  subsystem variants are excluded until their extra routing is directed.
  Original Audigy admits Creative subsystems 0051/0052/0053 and revision <4.

Memory is charged before programming: the existing 32 KiB playback ring,
32/16 KiB page table, 4 KiB silence page and 8 KiB capture ring, 19/15 pages
on Live!/Audigy respectively. No quota, inventory capacity or RAM floor changes.
The i686 private device record measures 548 bytes versus 500 at the worktree
base; the EMU driver object has 9222 bytes of text with the canonical flags.
The auxiliary region has one bidirectional pin and one resource claim; its
table/silence portions are CPU-written and the ADC portion device-written.

The Windows 98 Resource Kit, chapter 24, “WAV files cannot be played”
(`wrkc24_4.htm`, local read-only text), checks driver identity, IRQ resources
and conflicts separately. This supports truthful SOUND inventory; it supplies
no EMU programming constants. DOS playback remains the existing VMM-owned
virtual SB16 service, with no physical port forwarding.
