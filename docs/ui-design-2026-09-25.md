# Native desktop visual design, 25 September 2026

## Ciuki identity

The owner's explicit direction is that CiukiOS is dedicated to Ciuki, the dog
in the existing splash photograph. The OS mark is therefore his stylized
portrait, replacing the temporary stepped C. The owner selected the detailed
first proposal and rejected a hand-drawn pixel reinterpretation. The exact
approved PNG and identity guidance are in `assets/brand/`; runtime sprites
are compiled directly from it at 16, 24 and 64 pixels. `ciuki_logo.inc` uses
the existing drawing primitives, with 64 logo colours appended after the
unchanged 16 UI colours. Planar VGA maps the same pixels to its existing palette.
This identity update follows the earlier UI qualification runs below; their
screenshots and binary hashes remain evidence of those earlier builds.

## Desktop design

The desktop takes the compact window structure of late-1990s systems as its
reference: a platinum control surface, indigo active titles, inset paper
workspaces, a muted teal desktop and small, recognisable pixel icons. The
signature is a solid title tab followed by paired horizontal platinum rails.
The geometry is native pixels; no screenshots, scaled textures, transparency
or antialiasing buffers are involved.

## Palette and typography

The shared 16-color DAC palette lives in `src/com/ui_theme.inc`. Important
entries, expressed approximately as RGB hex, are ink `#242830`, active indigo
`#344978`, desktop teal `#345D61`, control platinum `#CED2D6`, shadow slate
`#717989`, and paper `#F7F7F3`. The palette is shared with graphical Setup.
Folder gold and restrained blue/green/red accents belong to icons and state.

Existing 13-pixel proportional bitmap glyphs remain the body face. The bold
variant identifies window titles, control groups and current state; regular
glyphs carry control labels and descriptions. Glyphs render directly at their
native size, including at 2560 x 1440. This avoids blurry enlargement and adds
no font dependency or generated bitmap asset. It does not claim automatic
physical-DPI scaling on monitors which do not report their dimensions.

## Composition

The command strip, desktop shortcuts, task strip, clock and application library
remain useful controls. There is no promotional hero. The existing wording
`A modern Retro OS` is preserved, as is the existing Ciuki splash image.
The library has a clear category row, recessed work area, compact places
sidebar when space allows, native icons and an action/status footer. Dialogs
keep the same 466 x 226 boundary, title hit area and keyboard actions.

The common frame has two pixel-aligned bevel steps. Workspaces and the Run
field use a recessed edge. The title tab keeps the caption legible; three
paired rails use only solid rectangles and leave window controls clear.
There is no costly wallpaper pattern or animated background. Motion belongs
to window transitions, implemented by the window/compositor integration.

The Display panel exposes 800 x 600, 1024 x 768, 1280 x 1024, 1600 x 1200,
1920 x 1080 and 2560 x 1440 plus automatic selection and Display setup.
Those buttons ask VGASetup to preview and save the desktop mode. Windows 3.1
keeps its separately supported saved mode; the interface says so directly.
A button does not imply that every physical BIOS supports the requested mode.

Native dialogs can coexist as windows. DOS applications still use the
existing full-screen launch and return mechanism. This change does not
represent a multitasking DOS runtime, a new native file manager, or invented
hardware compatibility.

## Implementation and validation boundary

Visual changes are confined to the shared palette and native drawing,
detail and dialog includes, with the parent task integrating the main frame,
control actions, setup and input/compositor changes. No kernel, audio,
filesystem or application-launch behavior is changed by these visual files.

Standalone NASM assembly of `src/com/shell.asm` succeeded after the visual
changes (50,832 bytes at that checkpoint). That check establishes syntax and
size only. Actual 128 MB QEMU interaction, captured frames, screen-boundary
and retained-pixel checks are performed by the separate validation task and
must pass before the overall desktop is described as working. The physical
Pentium III / ATI 9200 combination requires its own hardware run.

The actual `candidate-2/800` and `candidate-2/2560` desktop, Display and About
screenshots were visually reviewed. Captions, native icons, rails and all six
resolution choices fit their boundaries; no clipped labels or overlapping
controls were observed in those six static frames. The 2K screenshots show
additional workspace around controls at their native pixel size. Static
review alone does not establish animation smoothness or damage correctness.

A subsequent dialog correction removes Minimize from the transient Power,
command-error and launch-menu panels, which have no task button for restoring
them. Run, About, Display and Sound retain Minimize. That correction is for
the next candidate and was not present in the reviewed candidate-2 frames.

Text drawing also rejects a complete 16-pixel glyph row before parsing its
characters when that row is outside the compositor's current vertical band.
The bounds addition uses 32 bits, preserving the caller's color, font style
and registers. The renderer's existing 11 CPU/byte-level test groups passed
with `uv run --with unicorn python scripts/test_ui_rendering.py`, including
actual glyph clipping at five pixel depths. That fixture exercises the glyph
renderer rather than the new whole-text entry guard; the next integrated
screenshots and interaction checks cover that path.
