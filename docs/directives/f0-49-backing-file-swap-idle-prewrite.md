# f0-49 — dynamic backing file on the fixed system volume: slots and extents, page-out/page-in with prevalidated resources and a non-recursive lock order, commit backing, idle prewrite of cold modified pages, trailing shrink (contract M4)

- **Phase:** F0 (memory). **Model:** gpt-6.1-sol / xhigh. **Worktree:** `wt/f0-49` from main (after the f0-48, f1-83 and f1-84 merges).
- **Contract:** `docs/design/win98-class-resource-management.md`, section **M4** (dynamic backing file and idle prewrite) with M1–M3, C1–C3 and R1 as constraints; audit row M03; source register P01/P05/P10 and the f0-42b findings (dynamic swap growth/shrink and idle dirty-memory prewrite documented; `ConservativeSwapfileUsage` default 0 from KB Q223294; no growth increments: the numbers below are CiukiOS policy).
- **Authority:** a new `src/kernel/core/pager.c` (backing-store object, extents, slot map, page-out/page-in, idle prewrite), `src/kernel/core/reclaim.c` (the modified-page queue of f0-48 feeds the pager), `src/kernel/core/vmm.c`/`proc/uaddr.c` (swapped-page object state of f0-47), `src/kernel/fs/mount.c` (pagefile as an active volume dependency; refusal rules on removal/shutdown), `src/kernel/fs/vfs.c` only to open/extend/truncate the pagefile with reserved resources, `src/kernel/core/ledger.c` (pagefile commit, swap capacity/used), `tests/host/`, `docs/design/boot-memory.md` (backing store section).
- **Not yours:** the FAT allocator (use the existing allocation through the reserved-resource path), DOS VM pageability (f3-46), the Win32 pagefile-backed sections' API (f5-04 uses the commit interface you expose).

## Required

1. **Backing-store object.** Fixed page slots, reserved/used/free states, extent map, outstanding-I/O count, generation, sticky errors; initial allocation 16 MiB on the writable fixed FAT system volume, growth in 16 MiB extents *before* commit admission needs them, minimum disk-free reserve `max(16 MiB, 5 % of volume capacity)`; a read-only or full system reports reduced commit capacity and stays usable; no swap on removable, optical or read-only NTFS volumes; no swap-on/off user ABI.
2. **Fault and page-out paths.** Extents allocated and flushed by a sleepable manager before their slots are available; fault and page-out use prevalidated extents and reserved request/buffer resources (f1-83 pool reservations): no ordinary FAT allocation, no cache eviction, no namespace lock, no recursive fault on the faulting process's locks; define the lock order in `boot-memory.md` and assert it in host tests; pin the pager worker's code, stack and minimum I/O resources (f0-43 tokens); the pagefile is an active volume dependency until all live slots and I/O retire.
3. **Idle prewrite.** When the filesystem write queues are idle and free RAM approaches the high watermark, prewrite cold modified pages (from f0-48's queue) without reclaiming their frames until needed; cancel or deprioritise speculative page-out when demand I/O arrives (f1-83 priorities); mandatory reclaim and dirty aging still progress; after 30 s idle, free unused trailing 16 MiB extents down to the minimum without relocating live slots; growth/shrink never holds IRQ-off or a volume lock for an unbounded span (R1).
4. **Errors.** A failed page-out leaves the resident page and its dirty version intact and admits no commitment against failed capacity; a failed page-in returns a contained unrecoverable backing error to the affected process or VM (the existing fault/error containment), never fabricated zeros, never a panic of unrelated tasks; swap contents untrusted across reboot (empty ownership at start, newly exposed anonymous pages zeroed).
5. **Host evidence.** Demand beyond RAM, extent growth/shrink and exhaustion, idle prewrite vs foreground reads, every I/O failure, exit and removal races, a deliberately recursive-allocation negative control (must be caught by the lock-order assertion). `ASAN_OPTIONS=detect_leaks=0 bash scripts/test/host_kernel_tests.sh`, `bash scripts/test/host_fs_tests.sh`, `bash tests/host/audio/run.sh` (deadlines held under paging load on the host model), `python3 scripts/build_kernel.py`. Report `build/codex/f0-49-report.md`: the object and lock order, page-in/out costs, the 128/256/512 MiB profile behaviour on the host models, remaining (physical qualification is the lead's).
