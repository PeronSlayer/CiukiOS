## What to build

1. **Controller driver** (`i8042.c`): self-test and configuration byte
   handling, port 1 (keyboard) and port 2 (AUX) enable/disable, command
   writes with ACK/RESEND handling (bounded RESEND retries, all within the
   original 100 ms deadline; setup deadline 500 ms), status-polled output
   buffer reads with the 100 ms deadline, controller reset not performed
   blindly (only when the contract allows), translation disabled (scan code
   set 2 raw), AUX byte separation by the status bit, IntelliMouse detection
   optional and off by default (3-byte packets). IRQ1 and IRQ12 handlers
   registered through the existing `irq_set_handler` (edge lines, not the
   shared chain), reading one byte per interrupt into the queue; bytes that
   arrive while polling a command reply are attributed by the status AUX
   bit, never guessed.
2. **Input queue** (`input.h`): one bounded ring (256 events) of typed
   events `{type: key/rel/btn, code, value, tick}` filled from IRQ context
   under `irq_save`, drained in thread context; overflow is counted, never
   silently dropped as "latest wins"; a keyboard state machine for set-2
   make/break (E0/F0 prefixes) produces `key down/up` with a stable code
   table; the mouse packet decoder validates the first byte (bit 3 set,
   overflow bits) and resynchronises by dropping bytes until a valid header,
   counting each resync. Digest helpers: count of key transitions, text
   characters for the unshifted US layout (letters/digits), signed motion
   totals, button transitions, overflow and resync counters, as the `input`
   probe reports.
3. **Ownership and policy**: ports 0x60/0x64 and IRQ1/IRQ12 claimed in the
   registry as `i8042`, activated with a generation; the driver refuses to
   start when the boot info says firmware-first input (E500 policy,
   `CBI_F_INPUT_FORCED`): then it claims nothing, reports `backend=firmware`
   and leaves the controller untouched for the serialized BIOS service of a
   later directive. Quiescence proof: disable both ports, drain the output
   buffer, no pending command.
4. **Probes** (`i8042_probe.c`, functions `probe_input` and
   `probe_input_fault`, each `int (*)(void)` returning 0 on PASS): follow the
   contract table exactly — `input` emits `READY backend=native|firmware`
   then waits up to 120 s for the stimulus (100 `a` make/break cycles, 100
   relative moves x=2,y=-1, 10 left-button cycles) and reports counts,
   totals and a digest; it passes with 100 characters, 200 key transitions,
   20 button transitions, totals x=200 y=-100, zero loss and no stuck key.
   `input-fault` injects, through a driver-boundary test hook that exists
   only when the probe runs (no fault paths in normal operation): missing
   ACK, bounded RESEND, mixed AUX/keyboard bytes, malformed packet, queue
   overflow; each reaches its specified error or resynchronisation, no blind
   reset, and the survivor task advances 100 ticks afterwards. Do not
   register the probes in a table: expose them in `i8042.h`; the lead's
   plumbing (directive f1-03, `CIUKI_F1_PROBE`) registers them; if the macro
   already exists in your base, use it.

## Host tests (mandatory)

`tests/host/i8042_test.c` under ASan/UBSan with a fake controller (status,
data port, scripted byte sequences, time source): command ACK/RESEND
bounds and deadlines, set-2 decoding incl. E0/F0 sequences and stuck-key
detection, mouse packet validation and resync, the ring overflow counter,
firmware-first refusal path, and the contract stimulus replay giving the
exact pass counts.
