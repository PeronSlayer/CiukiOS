## Required

1. **Request model.** A bounded common pool (ledger-accounted) of requests with: operation, device and media generation, LBA and byte length, page vector with pin token (f0-43), dependency frontier (the FAT ordering barrier the request belongs to), priority class and deadline (demand read with deadline > speculative read > background write), enqueue/start/completion timestamps, result and bytes, cancellation state, completion event. Ownership is exactly one of prepared, queued, issued, completed/cancelled; completion happens once, and only then may the waiter and the pin retire. The synchronous `blkdev` read/write/flush wrappers stay for every current caller; internally they submit a request and wait on its event with the existing deadlines.
2. **Per-controller queues and admission.** One queue per controller (ATA channel, USB mass-storage device): priority order, FIFO/age within a class, no starvation of background writes (age promotion), merging only of adjacent requests with the same device generation, priority, dependency frontier and pin ownership; a fast-disk command capped at 64 KiB initially with adaptive reduction when the measured command time would consume the reader's budget (keep f1-81's 128-sector USB cap); no retry of an uncertain issued write; queue age, timeout and backpressure exposed in records (`[storage] queue …` every 5 s while non-empty: depth per class, oldest age, commands issued, merged, split, cancelled).
3. **IRQ completion.** Top halves only record/acknowledge/wake (f0-46 rules): the completion moves the request to the deferred worker, which retires the pin, signals the event and applies the I/O completion boost of f0-45 to the waiter.
4. **Same-volume reader fairness.** A reader of file B on volume C: must not wait behind the whole operation of a writer on file A: split the per-volume reservation (f1-79) into a short metadata/publication reservation and a per-file I/O phase that does not hold the volume ticket while its requests are in flight; keep every FAT ordering boundary and barrier semantics of C2 untouched (f1-84 redesigns publication; here only the I/O phase leaves the reservation). Prove with the contract's replay: 10 MiB copy from a 1 MiB/s source to a 20 MB/s destination with ≤ 5 ms flush cost while a second task reads 16 KiB every 20 ms from another file on the destination: maximum arrival-to-completion reader latency ≤ 20 ms, zero missed reads, copy throughput within ±10 % of the source; the negative control (old policy) reproduces ≥ 100 ms; repeat with fragmented chains, all-dirty cache, mixed devices (USB source), concurrent fsync, error injection and cancellation; data correctness and final durability checked (fsck/mtools comparisons as in `host_fs_tests.sh`).
5. **Verification.** `ASAN_OPTIONS=detect_leaks=0 bash scripts/test/host_fs_tests.sh` (all groups, fsck and mtools), `ASAN_OPTIONS=detect_leaks=0 bash scripts/test/host_kernel_tests.sh`, `bash tests/host/usb/run.sh`, `python3 scripts/build_kernel.py`; report `build/codex/f1-83-report.md` with the request model, queue policy with numbers, the replay tables (before/after, each variant), records, remaining (physical qualification is the lead's).
