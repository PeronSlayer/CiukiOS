- **Contract:** `docs/design/win98-class-resource-management.md`, sections **C2** (ordering, errors and removable media) and **C5** (one file identity and coherent mappings); audit rows S05, S07, S08; source register P10 (IFSMgr ring-0 file I/O), P23 (FAT specification), P26 (Mitchell: VFAT lazy-write ordering); the f1-82 and f1-83 reports (dirty budgets, request pool with dependency frontiers). - **Not yours:** the request pool and queues (f1-83), read-ahead and cache sizing (f1-85), the DOS file API (f3-49 registers as a lock owner through the interface you define), paging (f0-47/f0-49).

## Required

1. **Dependency groups.** Monotonically numbered groups per volume and device generation: data initialization → detached chain construction → link publication → directory size/name publication → advisory FSInfo; keep the operation-specific delete/rename ordering and FAT-copy divergence detection; a barrier captures a finite sequence/version frontier (later writes cannot extend it); completion = frontier and dependencies on stable media through a qualified flush or a verified disabled write cache. Until the asynchronous ordered publication passes the power-cut matrix (item 5), the current synchronous barriers stay in force: implement the groups and frontiers first, prove them, then switch the default with the evidence in the report; never weaken recovery to meet throughput.
2. **Completion semantics.** Buffered `write` completion and durable completion are distinguishable in the API (`fsync`, explicit sync, durable removal, shutdown wait for their frontier and propagate sticky per-device errors); records distinguish them.
3. **Removable media.** Write-through completion for ordinary writes on removable media by default (or the Windows 98 default if f0-42b resolved it, with the owner's conservative choice documented); surprise removal cancels unissued requests, invalidates generation-bound aliases, records incomplete durability, never reports a flush of absent media; issued DMA pins survive until stop/completion is proved (f0-43 tokens); a newly inserted medium cannot inherit an old epoch; refusal with active handles/cwd/VM/swap dependencies is preserved.
4. **Locks and identity (C5).** One node/open-description identity with LFN/8.3 alias validation; share modes (compatibility, deny read/write/all, inheritance) and byte-range locks with owner types native, Win32 and DOS (the DOS owner is registered by f3-49 through your interface); every close or death releases exactly its locks; the lock matrix tested across owner types. Mapping-page identity keyed by (volume generation, stable file identity, file-page index) prepared for f0-47: specify (in the contract section) MAP_SHARED visibility, private COW, partial pages, truncate invalidation, dirty-page fsync, close vs mapping lifetime, rename/unlink identity, raw/external writes and removal; implement the identity table and the invalidation hooks now, without enabling file-backed mappings.
5. **Host fault injection and evidence.** Cut every publication stage, reorder only permitted groups, fail every write and flush, race removal with dirty and in-flight work; the existing FAT12/16/32 fsck and mtools comparisons, crash-reboot, boot-log and per-device-error isolation tests stay green; a failed device never revokes unrelated healthy volumes. `ASAN_OPTIONS=detect_leaks=0 bash scripts/test/host_fs_tests.sh`, `ASAN_OPTIONS=detect_leaks=0 bash scripts/test/host_kernel_tests.sh`, `python3 scripts/build_kernel.py`, `python3 scripts/gen_api_reference.py` and `make CAP= apps` if a public header changed. Report `build/codex/f1-84-report.md`: the group/frontier design, the before/after of the C3 replay with the asynchronous publication (if switched) and the power-cut matrix counts, the lock matrix, remaining.
