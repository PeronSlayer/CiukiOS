# f3-47 — DOS VM disk path: a real block cache for VM disk images, enough DPMI memory for DOOM's zone, a disk indicator that lights only for device reads, INT 13h latency histogram

- **Phase:** F3 (DOS VMs), contract D2 (DOS block requests share the protected I/O infrastructure). **Model:** gpt-6.1-sol / xhigh. **Worktree:** `wt/f3-47` from main (after `a06f0dfb`).
- **Authority:** `src/kernel/vm/dosvm_disk.c` (read windows, overlay, INT 13h service), `src/kernel/vm/dosvm_bios.c` (INT 13h only), `src/kernel/vm/dpmi.c` (0500h/0501h reporting only, no allocation change), `src/kernel/vm/dosvm_perf.inc` (records), `apps/dosbox/autorun.h` and the games manifest for the DOOM command line, the desktop tray disk-activity indicator (`apps/desktop/` tray code, find it), `tests/host/` (dosvm disk tests), `docs/design/dos-dpmi-contract.md` (disk section), `docs/validation/` note.
- **Not yours:** DPMI dispatch and ISR logic (f3-45), the audio source (f4-35), the block cache policy of f1-82 (you may *use* `cache_read`/`cache_read_ahead` through the VFS; do not change cache.c), the FAT layer.

## Evidence (T23, image 4bcd1d43, `legacy/local/physical/4bcd1d43/serial.log`, DOOM VM `gen=4353`, read-only)

- The owner: "ogni volta che sparo o faccio una qualsiasi azione appare per pochissimi istanti, di continuo, l'icona del floppy in basso a destra: sembra che stia caricando di continuo".
- `group=vm_perf_v vm=1 gen=4353 n=3 path=bios vector=13 calls=27785 us=1529562 max_us=41660 ax=4229`: 27,785 INT 13h extended reads in the session, 1.53 s of monitor time, single calls up to 41.7 ms. `group=vm_perf_disk … reads=217 bytes=14091264 max=65536 hits=27555`: 217 host reads of 64 KiB (14 MB, about the whole registered WAD) and 27,555 hits in the VM's two 64 KiB read windows. DOOM re-reads lumps from the WAD on every action: its zone heap evicts cached lumps and the guest has no disk cache (CiukiDOS has no BUFFERS cache; the VM has only two 64 KiB windows), so each miss costs a 64 KiB read through the VFS (41 ms worst case under the copy/log load) and every INT 13h call, hit or miss, lights the tray indicator.
- Memory: the game VM is created with the default `DOSVM_RESIDENT_CAP` 32 MiB, pool quota 24 MiB; DPMI 0500h reports the largest free run of the pool (`dpmi.c:450–456`, `dosvm_pool_query`). DOOM 1.9 limits its zone to 6 MB unless started with `-maxzone`; the launcher starts `\DOOM\DOOM.EXE -config CIUKI.CFG` (`apps/dosbox/autorun.h:3`) with no `-maxzone`. The previous trial (`82fadce3`) showed the same pattern (`calls=27605`, 13.7 MB read) and so did `9af46936`.
- The symptom is in the VMM's I/O path and in the guest's memory configuration, not in the DOS kernel: it would be identical with FreeDOS as the guest.

## Required

1. **Measure first.** Add to the VM perf records an INT 13h latency histogram per 5 s window (< 100 µs, 100 µs–1 ms, 1–10 ms, 10–50 ms, > 50 ms), the hit/miss split of the read windows, the bytes read from the host and the number of distinct 64 KiB regions touched; emit them with the existing `vm_perf_disk` cadence. Reproduce on the host with a DOOM-like access trace (random lump reads of 1–64 KiB over a 12 MB image, 400 reads/s) and report the baseline.
2. **Block cache for VM disk images.** Replace the two fixed 64 KiB windows with a per-VM read cache of 64 KiB blocks, LRU, sized by the VM's commitment (for example 2 MiB for the default 32 MiB VM, counted in the f0-43 ledger under `MM_VM_PRIVATE` or a new category), coherent with the write overlay (a write invalidates or updates the cached block); misses read through the VFS as today (or `cache_read_ahead` of the next block when the access is sequential). Target on the host trace: ≥ 95 % hits after warm-up, INT 13h service ≤ 100 µs on hits, no read of the same 64 KiB region twice within the cache span. The disk gate and the f0-41 preemption rules stay.
3. **Memory for the zone.** Verify what DPMI 0500h returns for the default game VM (largest run, total) after boot and after DOS/4GW starts; add `-maxzone 16384` (16 MB) to the DOOM command line in the launcher if the host reports at least 20 MB free, or pass the limit through `CIUKI.CFG`/environment if the launcher supports per-game options; document DOOM's `-maxzone` semantics from the DOOM source (`i_main.c`/`i_ibm.c`, Z_Init) with a citation. Measure on the host trace how the read count changes with a 16 MB zone model (DOOM caches lumps PU_CACHE until the zone fills).
4. **Indicator.** The tray disk indicator lights only for actual host reads/writes (misses and overlay writes), not for cache hits; add a minimum on-time of 100 ms so it does not flicker; the record of hits/misses makes the behaviour checkable.
5. **Host evidence.** `ASAN_OPTIONS=detect_leaks=0 bash scripts/test/host_kernel_tests.sh` (DOS VM harness with the new cache: coherence with overlay writes, invalidation on image change, eviction, ledger accounting), the host access-trace benchmark before/after, `python3 scripts/build_kernel.py`, `make CAP= apps` if the launcher changed. Report `build/codex/f3-47-report.md` with the histogram before/after, hit rates, memory accounting and the `-maxzone` decision.
