## Owner amendment (2026-10-25 19:40)

"Il contratto deve essere 3D per tutte le famiglie di GPU integrate con i driver; ora abbiamo solo la Savage da testare ma tienine conto." The 3D design is family-neutral, like the display driver model (docs/design/display-driver-model.md: registry, families, capability bits, transport interfaces) and the universal-drivers decision of 2026-10-22. The F7 contract was written Savage-first; amend it (new section "Universal 3D driver model") so that:

- The kernel 3D interface (device owner, submission ring/fences/admission, per-family command validation, VRAM/AGP heaps, presentation/lease, loss/reset, capabilities) is a generic driver-model layer; each family supplies a backend (validator, packet emitter, memory layout, idle/flush, conversion copy) registered like the display families in src/kernel/drivers/video/registry.c.
- User space (libciuki3d / opengl32 backend interface) sees capabilities, never a chip name; the software rasterizer is the universal fallback with identical semantics.
- A family matrix covers every 3D-capable family that has a 2D driver in src/kernel/drivers/video/: 3dfx Banshee/Voodoo3-5 (tdfx), ATI Rage 128 (rage128), Radeon R100/R200 (radeon2d), Mach64/Rage Pro (mach64), Matrox G200/G400/G450 (matrox), Intel i740, i810/i815, i830-i855/i865 (i740, i810, intel2d), S3 Savage family (s3savage), S3 ViRGE (s3virge), SiS 300/315 (sis), VIA UniChrome (unichrome), NVIDIA Riva 128/TNT/GeForce 1-4 (riva128, nv2d), Trident CyberBlade/Blade3D (trident), VMware SVGA II with SVGA3D (vmwaresvga, for the VMware/VirtualBox release images). For each: the public 3D references (Mesa classic DRI driver and Linux DRM module names and the last Mesa release that shipped them, Utah-GLX, Glide3 for tdfx, nouveau nv04/nv10/nv20, Gallium svga), the fixed-function feature set (texture units, depth formats, blend/alpha, max texture size), command submission style (MMIO/BCI/PIO/DMA ring), and an implementation order. Families without 3D hardware (cirrus, chipshiqv, neomagic, s3trio64, s3legacy) are listed as software-only.
- Only the Savage backend is implemented now (the only family the owner can test); the others get their registry entries and capability descriptors marked "not implemented" so the software path is selected, with the model proven general by host tests that register a second fake family.
