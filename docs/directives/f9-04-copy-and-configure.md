Required:
1. **`setup_txn_prepare`** (no writes): validate the answers and the component selection (dependencies as f9-03 enforces them, re-checked here), compute the required bytes from the manifest for the selected components, the FAT overhead through `disk_plan_whole`, the reserve (16 MiB + `max(16 MiB, 5 % of the volume) + 16 MiB`), the free space after installation (refuse `SETUP_ERR_DEST_FULL` when negative), check source availability (every manifest path of the selected components exists on `C:`/`D:` with the manifest size), record the source hashes (`RELEASE.JSON`, the ISO manifest hash), the disk identity and fingerprint, and fill `struct setup_plan`.
2. **`setup_txn_execute`** — the phases of plan §6.1 in order, each ending with a flush and a durable marker: P1 (`disk_execute_p1`, revalidation first), P2 (`disk_execute_p2`, then `SETUP.STATE = phase=format`), P3 copy, P4 configure, P5 publish. Progress callbacks per file and per sector run; `cancel_requested` polled between files and runs; cancel stops at the next safe point, leaves the documented state and returns `SETUP_ERR_CANCELLED`; `setup_txn_state` reports the phase reached.
3. **P3 copy.** Through the VFS from `C:` (and `D:` for `\SOURCES` when selected) into the published volume at the manifest paths with the manifest attributes and long names, directories created from the manifest's directory set, bounded buffers (≤ 256 KiB total, allocated once), `fsync` per file; then the volume flush (`DISK_FLUSH`) and **verification by raw reads**: for every copied file, walk its FAT chain through a read-only VFS query (cluster list) and hash the clusters read through `disk_read_raw` (cache bypassed) against the manifest SHA-256; sizes/attributes/names compared through the VFS; the pagefile is never copied. Write `SETUP.STATE = phase=copy done=<files>` and flush. Retryable errors as plan §6.4 (`SOURCE_READ`, `MEDIA_REMOVED`: on Retry after a media change, re-open the source volumes, check `RELEASE.JSON` and the ISO manifest hash against the recorded ones, `SOURCE_MISMATCH` when different); hash mismatch → `SOURCE_MISMATCH`; `ENOSPC`/write/flush errors → the `DEST_*` classes; never skip a required file; a failed source read after `SETUP_RETRY_MAX` leaves the install incomplete.
4. **P4 configure.** Through the same writers the Control Panel pages use: user name and computer name (registry), keyboard layout, time zone and the clock convention; **the RTC is written here from the answers** (local or UTC per `Clock=`), network mode (DHCP/static/none), IPX, lobby; bundled game registration data (the f2-87 catalogue entries for the selected games); `\SYSTEM\SETUP.LOG` (the in-memory ring: every phase, file counts, errors, retries, timestamps) and `\SYSTEM\HARDWARE.TXT` (the hardware report text from f9-03); `fsync` each; `SETUP.STATE = phase=configure`; flush. The configuration never launches a personality, game or soundfont.
5. **P5 publish.** `disk_consistency_check` (fail on `CORRUPT`/`COPIES`/`LOST`/`IO_FLAG`); then `disk_execute_p5` with the loader image bytes read from `C:` (the manifest records their hash: compare before use) and the destination `BOOT.CFG` (canonical template without `setup=1`), `SETUP.STATE = phase=installed release=<sha> firstboot=pending`, FAT clean bit, the final MBR last; raw read-back of the loader and the MBR; `SETUP_PHASE_COMPLETE`.
6. **Restart path (D10).** `setup_restart(policy)`: `eject` → `MEDIA_CD_TRAY` open on the boot CD's drive, wait for the media-removed state up to 60 s, then the kernel restart syscall; `wait` → wait without limit for removal (f9-03 shows the countdown/prompt); `force` → restart after 60 s regardless. The installed `BOOT.CFG` never contains `setup=1` (test).
7. **Record formats** (propose in the report; the lead folds them into the plan): `SETUP.STATE` as ASCII `key=value` lines (`phase`, `release`, `disk_signature`, `firstboot`, later `step=` lines from f9-05), ≤ 4 KiB, written whole and `fsync`ed; `SETUP.LOG` lines `<ms> <phase> <event> …`; `HARDWARE.TXT` as rendered by f9-03.
