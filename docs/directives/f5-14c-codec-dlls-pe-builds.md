- **Phase:** F5 (reused DLLs, milestone C). **Model:** gpt-6.1-sol / high, `--search`. **Worktree:** `wt/f5-14c` from main (after the f5-06 and f5-10B merges; in parallel with f5-14B, sharing `scripts/win32/build-wine-dlls.sh`: whoever merges second rebases on the other's recipe changes).
- **Contract:** `docs/design/win32-personality-contract.md`, sections "DLL set by phases" (P5 row: `msacm32` with IMA and MS ADPCM, `msvfw32`/`avifil32` with Cinepak, MS RLE and MS Video 1), "Audio" (codecs of phase P5), the directive definition **f5-14** (line 1435) and the cross-review row "f5-14A/B/C"; the f5-14A findings (line 2344) and audit. Read the f5-14A report, the f5-14B directive (shared recipe and notice rules), the f5-02 census (which codec functions the acceptance set imports; which AVI/WAV fixtures of the titles use which FourCC), the Wine 10.0 sources of `dlls/msacm32`, `imaadp32.acm`, `msadp32.acm`, `msvfw32`, `avifil32`, `msrle32`, `msvidc32`, `iccvid`, the IMA ADPCM and MS ADPCM specifications (cite), the Cinepak format description and the MS Video 1/MS RLE descriptions in the Windows bitmap/AVI documentation (cite).

- **Not yours:** MCI, AVI playback and CD audio (f5-12B consumes these DLLs), the mixer (f5-12A), `winmm` itself (CiukiOS, f5-12A/B), DirectShow (not in the contract).

## Required

1. **Builds or implementations.** For each of the eight DLLs: the Wine 10.0 PE build with the f5-14B recipe (two-run identical hashes, imports verified against the CiukiOS core and `winmm` export inventories; missing exports listed) or, where the audit shows a unixlib/wineserver dependency or an unacceptable size, a CiukiOS implementation of the same exports (the ACM driver interface `DriverProc`/`acmDriverMessage` for the two ADPCM codecs; the VCM `ICM_*` message interface for the three video codecs) with the specifications cited; the decision per DLL recorded with the numbers.
2. **Conformance.** Sample-exact decodes of authored IMA ADPCM and MS ADPCM fixtures (mono/stereo, 8/11.025/22.05/44.1 kHz, block alignments of the specification, truncated final blocks), pinned frame digests of authored Cinepak, MS RLE (4/8-bit, delta frames) and MS Video 1 (8/16-bit) clips decoded through `ICDecompress` with keyframe/delta sequences, malformed-input fuzz (ASan/UBSan, truncated and overlong frames, invalid chunk sizes) with clean error codes; `acmFormatSuggest`/`acmStreamSize` behaviour pinned; the selected Wine conformance tests of these DLLs run on the Linux adapter where executable (skips recorded).
3. **Notices and inventory.** LGPL notices, source offer and patches per f5-14B; image inventory hash and licence entries; the builtin manifest entries.
4. **Evidence.** The decision table, hash identity, import audit per DLL, conformance and fuzz results, sizes and load-time resident pages on the store model; `make CAP= apps`, `python3 -B -m unittest discover -s tests/host/win32 -t .`. Report `build/codex/f5-14c-report.md` with remaining (QEMU/T23 are the lead's).

## Constraints

Use `rg` and `sed`, never `semble`. No QEMU, no `systemd-run`, no image builds, no commits, no diary edits, host tests one at a time with `nice -n 19`. Only the pinned Wine 10.0 sources; no MinGW; no `wineserver`/unixlib; no SSE/MMX in CiukiOS implementations (i686 baseline); no commercial media as fixtures (authored clips only). No new `panic()` paths; English.
