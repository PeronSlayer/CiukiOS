
The suite declares the fixtures as
`{"injection": "postboot-driver-boundary", "subcase": "bad-bpb"}` (and
`dirty`, `error-flag`, `fat-divergence`, `chain-corruption`,
`torn-sector`); `mount-crash-reboot` declares `boots` and no fixture. The
runner's `prepare_fixtures` only generates `mkfs.fat` fixtures or attaches
`path` fixtures, so nothing is attached and the probe counts zero fixture
disks. The probe (`fat_probes.c`, `probe_mount_crash`) expects: one or more
IDE disks after the boot disk whose volumes mount with an error (bad BPB)
or mount read-only with a corruption reason and refuse a create with
`EROFS` and zero writes; for the crash case an on-disk marker
`C:/F109CUT.ARM` placed in the overlay by the runner, after which the probe
runs a traced replace/rename workload (`event=ARM action=crash_cut …`,
`case=cut index=… lba=… durable=…` records) that the runner must cut at a
declared point; on the next boot of the same overlay the probe reports
`case=crash_reboot reasons=… lost=… scan_corrupt=…` and the host checker
(`fsck.fat -n`, `mtools`) must find no cross-links and only the declared
interrupted-state outcomes.

## What to do

1. Implement the six corrupted fixtures as deterministic host-side
   modifications of a generated FAT fixture (seeded `mkfs.fat` image, then
   patched sectors): invalid BPB, dirty flag set, hardware-error flag set,
   FAT copies that diverge, a cluster chain cross-link or loop, a torn
   sector (half-written directory sector with a known pattern). Declare
   them in the suite in the form the runner supports and attach each as
   IDE disk 1 of its case. Record the patched sector list and the fixture
   SHA-256 in the result manifest.
2. Implement `mount-crash-reboot` end to end: boot 1 places `F109CUT.ARM`
   in the overlay's boot volume before launch (host tools on the overlay,
   never a privileged command), waits for `ARM action=crash_cut`, cuts the
   guest at the declared `cut` index (the existing cut-point machinery or
   blkdebug), exports the overlay, runs the checker; boot 2 of the same
   overlay collects `case=crash_reboot`; the predicates compare both boots
   and the checker report.
3. Align the seven cases' predicates with the probe's real records (as
   f1-17 did), including the `case=mount … write_refusal=-30 writes=0`
   shape and the `coverage` record; add a contract-required record to the
   probe only if one is missing.
4. Host tests: each corruption generator (verify with `fsck.fat -n` that
   the intended defect is detected and nothing else), the marker placement,
   the cut sequence against the fake QEMU, predicate tests with record
   shapes produced by the probe's own formatting.
