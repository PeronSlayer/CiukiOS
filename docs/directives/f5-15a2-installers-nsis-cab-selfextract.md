## Amendment 6 (lead, 2026-10-21): findings of the Codex read-only cross-review of the amendment-5 delivery (61aceecf)

Apply this amendment only; everything else stays. Lead decisions on the review's premises: ordinary writes to `C:\WINDOWS` and to registry keys other than Uninstall/RunOnce are permitted by the Windows 98 contract and are **not** refused; the tests observe them as exact deltas (item 9) instead. The RunOnce deletion-before-handoff rule stays (at-most-once behaviour, as agreed in f5-07D); it is documented and its interruption outcome is tested, not changed.

1. **Licence file dependency (P1).** `third_party/nsis/COPYING` and `third_party/nsis/README.md` are untracked, so a clean checkout cannot generate the fixtures. Decision: they become tracked files (small zlib/libpng notice and the inventory distinguishing the zlib installer from the host compiler's bzip2/CPL components); `git add` them in the worktree (the lead commits). `scripts/win32/installer_fixture.py` verifies that the tracked `COPYING` is byte-identical to `nsis-2.51/COPYING` inside the pinned source archive before copying it, and fails with a clear message otherwise. Record the inventory in the report's licences table.
2. **H1 loader reaches host files outside the fixture tree (P1).** `tests/host/win32/installers/h1_services.c:223`: `original_open` is used only for the exact, fully qualified builtin-provider paths (an allow-list of the provider DLL paths, compared after normalisation); every other path, including slash-prefixed and drive-less ones, resolves through the fixture service and its authority checks. Add refusal tests for an absolute Linux path, a `..` traversal and a slash-prefixed DLL path.
3. **Cancellation destroys an existing installation (P1).** `tests/win32/fixtures/nsis/fixture.nsi`: `.onUserAbort` and the rollback remove only the objects **this** invocation created (payload, child, uninstaller, shortcuts, registry values, tracked as they are written); pre-existing state is preserved. Each write checks its result. Tests: cancel over an existing installation (nothing of the earlier installation is lost) and cancel at a later checkpoint (after the uninstaller and the registry values exist), both asserting the exact remaining state.
4. **Observer publishes an incomplete manifest as success (P1).** `src/probes/win32_installers/controller.h` and `src/kernel/probes/installer_probe.inc`: the success predicate of every stage requires the complete stage-specific manifest: the installed payload and executables present **and** matching the fixture manifest's identities (size and the content hash the probe already computes elsewhere, or a header-and-size identity if hashing is too costly in the kernel; say which in the report), the links valid, the restart marker, journal and backup checked by **content** (schema fields present and consistent), not by presence. INI parsing is section-aware: `NUL=` counts only as a key line inside the `[rename]` section, never in comments or other sections. Add one negative mutation per fact now checked (corrupt payload, stale marker, journal with a wrong entry, `NUL=` under another section).
5. **H1 protected-store bypasses (P2).** `tests/host/win32/installers/host_services.py`: protect `C:\System` (and the other protected roots) themselves, not only their descendants: moving, renaming or deleting the directory is refused; handle-based attribute and metadata changes re-check authority against the current path of the object, not the stored handle name. Tests: parent rename into TEMP then write through the new path (refused), handle-based attribute change on a protected file (refused).
6. **Failure paths leave partial files or children (P2).** `tests/win32/fixtures/installers/selfextract.c`: on wait timeout terminate and reap the child before deleting the tree. `infchain.c`: every early return goes through one cleanup path that removes the temporary tree. `apps/desktop/installer_fixture.c:66`: unlink the partial temporary uninstaller when the copy fails. H1 teardown attempts every child and every temporary tree, collecting errors, and raises once at the end.
7. **Self-delete semantics (P2).** `tests/host/win32/installers/flow_driver.py` and `host_services.py`: exercise the original uninstaller performing its own copy, start and exit delegation (the `_?=` temporary-copy path stays as a second case). Delete-on-close: implement it for files the H1 service opened with that flag, or make the service refuse the flag with a clear error and the report say so; no silent ignore. Before teardown assert no surviving descendant processes and no unexpected temporary files.
8. **Cached NSIS data outside the verified closure (P2).** `scripts/build_nsis.py`: at extraction record a manifest (relative path and SHA-256 of every file of the extracted stubs, includes and resources consumed through `NSISDIR`); on a cache hit verify the tree against that manifest and re-extract from the verified archive on any mismatch. Still no download and no fallback.
9. **Dry-run deltas and interruption (P2).** `flow_driver.py`: each stage compares the exact filesystem and registry deltas against an independent manifest (every path and key written, nothing else), asserts child cleanup before teardown, and adds interruption and recovery cases around WININIT retirement, journal persistence and the RunOnce handoff (service recreated after the interruption, outcome asserted). The timing test executes the RunOnce command it consumes, or is renamed to say it only measures consumption.
