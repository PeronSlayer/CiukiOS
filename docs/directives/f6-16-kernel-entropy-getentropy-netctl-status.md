# f6-16 — kernel entropy facility with `getentropy` (syscall 91), and the `netctl` status query (syscall 90) for offline classification before DNS

- **Owner:** Codex, `gpt-6.1-sol`, effort `xhigh`, `--search`
- **Written:** 2026-10-21 by the lead from the f6-15 report's two decisions: TLS in the browser (BearSSL) needs cryptographic entropy and currently fails closed because the SDK's `getentropy()` returns `ENOSYS` (f6-10 decision 3 describes only a non-cryptographic per-boot mix for lwIP, which must not be reused as a TLS seed); and the browser needs a native way to classify "offline" before issuing DNS. Lead reservations: **syscall 91 = `getentropy`**, **syscall 90 = `netctl`** (already reserved `ENOSYS` in `docs/design/execution-abi.md`, now defined with a read-only status sub-operation). Nothing else in the ABI changes.
- **Worktree:** `../CiukiOS-wt-f6-16`, branch `wt/f6-16`
- **Read first:** `docs/design/execution-abi.md` (syscall table, records), `docs/design/network-contract.md`, `src/kernel/net/lwip/stack.c` (`net_stack_entropy`, `ciuki_lwip_seed`), `src/kernel/net/lwip_handoff.c`, the stack-protector guard initialisation (grep `stack_chk_guard`), `src/kernel/include/ciuki/net.h` (`link_state`), the f6-10 directive and report, `sdk/` libc (`getentropy`, `arc4random` if present), `docs/design/resource-management-win98.md` (IRQ-context rules).

## Required

1. **Research, cited:** entropy sources available on a 1998–2004 PC without RDRAND (Pentium III, no TPM): interrupt timing jitter (TSC low bits at keyboard, mouse, disk completion, network receive, timer vs TSC drift), CPU jitter entropy (the Linux `jitterentropy` approach by Stephan Müller: documented, measurable), disk seek timing; conditioning and health tests (NIST SP 800-90B repetition and adaptive proportion tests), a DRBG (ChaCha20-based as in Linux `random.c` and OpenBSD `arc4random`), and the seeding policy (no output before the pool is initialised with the required min-entropy estimate; `getentropy` blocks or returns `EAGAIN` with a documented contract before that point). Cite Linux `drivers/char/random.c` documentation, the jitterentropy paper, SP 800-90A/B, OpenBSD `arc4random(3)`.
2. **Kernel:** an entropy pool fed from the interrupt paths that already exist (bounded work in IRQ context: only a TSC read and a mix into a per-CPU buffer; the conditioning runs in a worker), a jitter collector run at boot until the estimate is met, a ChaCha20 DRBG with reseeding, health tests, and `[entropy]` records (`sources`, `estimate_bits`, `initialised_ms`, `health=ok|fail`, `reseeds`). The lwIP per-boot mix and the stack guard are fed from the DRBG once initialised, never the reverse.
3. **Syscalls:** 91 `getentropy(buf, len)` (len ≤ 256 as POSIX/OpenBSD; `EFAULT`, `EINVAL`, `EAGAIN` before initialisation with the documented wait helper in the SDK), and 90 `netctl(op, ...)` with `NETCTL_STATUS` only: primary netif present, link up/down, IPv4 bound (DHCP state), DNS servers configured; read-only, no privileges needed. SDK: `getentropy()`, `arc4random()`/`arc4random_buf()` over it, `ciuki_net_status()`; `docs/developer-api.md` and the ABI document updated.
4. **Tests:** host model of the pool and DRBG (known-answer ChaCha20 test vectors from RFC 8439, health-test fixtures with stuck and biased inputs, reseed schedule), the syscall surface in the kernel host harness (f5-21 style registration if a probe is added), a statistical sanity test (not a proof) on host jitter output, and the SDK wrappers. No new `panic()` paths; `host_kernel_tests.sh` must reach its end.
5. **Not yours:** the browser's use of `getentropy` (the lead amends f6-15 after both merge); the per-boot MAC/TSC mix remains for lwIP until item 2 replaces it at initialisation.

Report `build/codex/f6-16-report.md` with the research citations, the entropy estimate method and its justification, verification table. `rg`/`sed` only; no QEMU, no `systemd-run`, no image builds, no commits, no diary edits; English.

## Amendment 1 (lead, 2026-10-21): the network status query already exists

The f6-15 cross-review found that the read-only `/dev/net` `NET_GET_STATE` interface already exposes `address_configured` (and the link state). Therefore: do **not** implement a `netctl` status sub-operation; syscall 90 stays reserved `ENOSYS` as before, and the SDK `ciuki_net_status()` wrapper (if you keep it) is a thin helper over the existing `/dev/net` interface, documented as such. Everything else of this directive (entropy pool, DRBG, `getentropy` syscall 91, tests) stands. If you already wrote `netctl` status code, remove it and say so in the report.

## Amendment 2 (lead, 2026-10-21): findings of the Codex read-only cross-review of the delivery (e4dcaf5f) and the lead's decisions on the two open policies

Apply this amendment only; the DRBG, syscall, SDK surface and records stand.

1. **High — unsupported entropy credit (`src/kernel/lib/entropy_pool.c:104`, `docs/design/kernel-entropy.md:20`).** Decision: the home-made jitter collector is replaced by a port of the upstream **jitterentropy-library** (Stephan Müller; dual BSD-3-Clause/GPL-2.0, published SP 800-90B assessment; the lead pins the release tarball under `build/downloads/jitterentropy/` with its SHA-256 and you record it in `config/jitterentropy.json` and the licence inventory). Port the core (`jitterentropy-base.c`, the hash (SHA3-256) conditioning, the RCT/APT health tests and the memory-access and loop-count randomisation) as a kernel library unit with our timer source (TSC), no libc; keep its entropy-rate rule (one bit per output byte at the oversampling rate the library uses, no extra credit) and its startup self-test (`jent_entropy_init`): the pool is **ready only when the library reports a successful init and has delivered 256 bits**. Interrupt TSC samples stay as uncredited additional mixing. Add a raw-sample capture record (`[entropy] raw ...`, bounded, off by default, `BOOT.CFG` token `entropyraw=1` reserved by the lead) so the lead can run the SP 800-90B non-IID assessment on T23 captures later; document that qualification as pending in the design note.
2. **High — `arc4random_buf()` can wait forever (`sdk/libciuki/entropy.c:38`, `src/kernel/core/entropy.c:42`).** Decision: `arc4random*` call `getentropy()` with a finite deadline of 5 s of `EAGAIN` and then **abort the process** with a clear diagnostic (OpenBSD semantics: the API cannot fail, so it must not return weak bytes); the indefinite wait stays only in an explicitly named helper (`ciuki_entropy_wait()`); persistent-EAGAIN termination fixture.
3. **Medium — collection after saturation (`src/kernel/core/entropy.c:76`).** Stop jitter collection when the fresh credit is full, resume on reseed demand (the 60 s / 1 MiB rule), retire the worker after permanent failure; record boot cycles and attempts (`[entropy] boot rounds=… cycles=… ms=…`) so the T23 cost is measurable; cap the boot collection by time as well as rounds.
4. **Medium — host gate depends on host noise (`tests/host/entropy/model_test.c:111`, `scripts/test/host_kernel_tests.sh:11`).** Deterministic fixtures (ChaCha20 vectors, state machine, health-test fixtures with synthetic streams, DRBG reseed) stay mandatory in the kernel suite; the measured-jitter sanity run becomes a separate script (`tests/host/entropy/run_qualification.sh`) that prints availability and results and is not part of the gate.
5. Verification by the lead outside the sandbox as before. Report section "Amendment 2".

## Amendment 3 (lead, 2026-10-21): lead run of the kernel suite on e7c3e17b, re-review findings, two decisions

Apply this amendment only.

1. **Kernel suite link failure (lead run, `build/lead/hkt.log`):** the harness rule that links `src/kernel/lib/stackprot.c` now needs `entropy_boot`, `entropy_get`, `entropy_erase` (undefined references at `stackprot.c:28`); add the entropy unit or its stub to every harness rule that links `stackprot.c`, so `scripts/test/host_kernel_tests.sh` reaches its end.
2. **Decision — pinned-version fidelity accepted:** jitterentropy-library v3.7.0 uses SHAKE-256/XDRBG conditioning and removed loop-count shuffling (upstream CHANGES.md). The port keeps the pinned implementation exactly; rewrite `docs/design/kernel-entropy.md` and the directive's wording where they say SHA3-256 conditioning or loop shuffling, and record this acceptance with the changelog citation. Fix the inaccurate comment at `src/kernel/lib/jitterentropy/port.c:29` (the yield's work does contribute to the measured delta; describe it correctly or move the yield outside the measured span if the upstream structure allows).
3. **Decision — SP 800-90B capture:** with the reserved `BOOT.CFG` token `entropyraw=1`, after boot the collector streams raw timing deltas (one byte each, hex, framed in `[entropy] raw` records of bounded length) to the serial port until 1,048,576 samples have been sent, then stops; the normal DRBG path stays enabled meanwhile; without the token nothing is streamed. Document the lead's procedure (T23 serial capture at 38400, the NIST `ea_non_iid` run) in `docs/validation/f6-16-entropy.md` as pending hardware qualification.
4. Verification by the lead outside the sandbox. Report section "Amendment 3".
