- **Written:** 2026-10-20 by the lead from two failed T23 trials (images `3d18f2db…` and `5b74e640…`, logs read-only under `legacy/local/physical/`, never copied into the tree)

## Evidence the current records cannot explain

1. `[storage] vfs_wait drive=C ms=100..1415 holder=C reason=volume` 144–232 times per session (`src/kernel/fs/vfs.c` `reserve_request`/`wait_report`), concentrated while Files is open and during a DOS game. The record names the waiting drive and the holder's drive, not the holding task, the mutation it performs, nor how long the reservation was held. Older T23 images (builds `763eefa6`, `56d41c09`, `99fefbcd`, `3357582f`) show zero such waits; `287551c6` (2026-10-18) shows 50. QEMU never shows them (instant disk).
2. Disk throughput about 2.8 MB/s for sequential 64 KiB reads (`[launch-io] disk_bytes=23795712 disk_requests=440` in about 10 s) on an mSATA SSD behind a PATA adapter configured `udma2` (`[ata0] dma mode=udma2 … bm=1860`). Nothing in the log proves a DMA transfer actually ran: `[launch-io] dma_*` counts user-space DMA bounces (`syscalls_proc.c`), not ATA bus-master commands, and `[storage] queue` has no DMA/PIO or service-time fields.
3. The DOS VM task runs at 50–70 % CPU, all kernel time (`[cpu] top=dosbox#35:700k700s7`), after DOOM has read its WAD, without presenting a frame; `stretch_max_ms=11 task=dosbox eip=kpreempt_point`. The VM exit profile (`src/kernel/vm/dosvm_perf.inc` `vm_perf_exits`, `vm_perf_cost`, `vm_perf_port`) is written only through `rec_diag_disk_bootlog` under a test probe, so a normal boot on hardware records nothing about what the VM traps on.
4. `[kernel] irqoff_section=schedule site=c0138a6b irqoff_max_us=2137..2398 violations=808 … unclassified=808` and `[work] budget exceeded site=timer_work us=2116` repeat on both trials (the Pentium III has no SMI count MSR, so firmware attribution is impossible: `smi_attributed=0`). The record gives the site that disabled interrupts, not what the 2 ms were spent on.

## Required (host-testable; the lead builds the image and runs the T23)

1. **Reservation hold accounting** (`src/kernel/fs/vfs.c`, `vfs.h`, the FS request context). When a volume reservation (mutation) is released after a hold of at least 50 ms, log `[storage] vfs_hold drive=C ms=N task=<name>#<id> op=<tag> waiters=N`, where `op` is a short tag passed by the mutating entry point (`write`, `truncate`, `create`, `rename`, `unlink`, `mkdir`, `log_write`, `log_reserve`, `commit`, `mount`, `other`); add the waiting task's name and the holder's task name and `op` to the existing `vfs_wait` record. No new lock, no allocation, bounded string copies; the existing `vfs_wait_observer` host hook gains a `vfs_hold_observer`. Host tests in `tests/host/fs` (the real stack, a slow fake device) prove both records with exact fields.
2. **DMA proof and service time** (`src/kernel/drivers/ata.c`, `src/kernel/fs/blkreq.c`, `blkdev.h`). Per device: commands completed by DMA and by PIO, and service-time buckets (<2, <8, <32, ≥32 ms) and the maximum, exposed in the periodic `[storage] queue` record as `dma=N pio=N svc=<b1>/<b2>/<b3>/<b4> svc_max_ms=N`; one `[ata%u] dma first-completion unit=%u elapsed_us=%u` record at the first successful DMA completion of a boot, and `[ata%u] dma fallback …` when a device drops to PIO (the existing quarantine record stays). Host tests: the ATA register model and `test_blkreq.c`.
3. **DOS VM exit profile without a probe** (`src/kernel/vm/dosvm.c`, `dosvm_perf.inc`). While a VM runs, every 2 s (the cpustat period) emit through `klog_periodic` one `[dosvm] perf vm= gen= exits= gp= pf= db= timer= other= pm= busy_pm= idle_2f= idle_28= idle_16= idle_hlt=` record and up to three `[dosvm] perf_port vm= port=%04x exits= us=` records for the costliest ports of the window, plus one `[dosvm] perf_cost vm= cause= exits= us=` for the costliest cause. Deltas per window, no probe required, same numbers as the disk records. Host test: the existing VM perf fixture extended to the periodic path.
4. **Long IRQ-off attribution** (`src/kernel/core/cpustat.c`, `task.c` `schedule`, `include/ciuki/cpu.h`). Inside `schedule`, keep TSC phase marks (pick, fpu, address space, ldt/debug, vm-enter, other) and, when a section of at least 1 ms ends, log once per window `[kernel] irqoff_long site= us= phase=<name> phase_us= from=<task> to=<task>`. If the measured phases account for less than half of the section, mark `phase=gap` (an unmaskable event such as an SMI; the PIII has no counter). Bounded cost: a handful of `rdtsc` per switch. Host test in the cpustat unit tests with a fake clock.
5. `docs/validation/`: a short note listing the new records and how to read them (English), referenced from `docs/design/test-architecture.md` only if that document lists records.

## Amendment 1 (lead, 2026-10-21, from the Codex cross-review `build/lead-scratch/f1-86-review.md` in the main checkout: verdict "merge with these fixes")

Apply before integration, in this order, each with a host test:

1. **Publish outside the locks.** Hold and wait records are captured (release time, bounded field values) under the existing FS locks but formatted and published only after the namespace/volume locks are released and the waiters woken; admission-side wait records are deferred to the unlocked boundary. The observer fixture asserts that no publication happens while a namespace or volume lock is held.
2. **Contention record budget.** At most 8 hold records and 8 wait records per 2 s window per drive, then a suppressed count and the maximum hold/wait of the window in the next report; the VM summary stays at 2 s without accelerating any other disk record family; the former verbose-only wait record stays verbose on disk (protected slots unchanged). A stalled-drain test with four VMs plus contention records the slot/byte budget.
3. **Scheduler entry with IF clear.** `schedule()` entered after `cli()` with no active timing section (the syscall-return path, `task_exit`) starts an inactive section so the phase marks are recorded; keep an existing outer section; test both entries through the real hooks, not the manual `cpu_irqoff_begin()` stub.
4. **Deferred phase arithmetic.** Raw phase timestamps only; duration and ranking computed only when the section end passes the 1 ms threshold; minimal initialization for sections without phases; the ATA first-completion timestamp taken only when DMA is enabled.
5. **Idle publication.** Completion marks the queue statistics dirty; the next periodic report publishes dirty counters even when the queue is idle; test a completed burst followed by an idle interval.
6. (P3, optional) Bounded generation validation of the namespace snapshot with `unknown` on overlap.

Report the changes in `build/codex/f1-86-report.md` (section "Amendment 1").
