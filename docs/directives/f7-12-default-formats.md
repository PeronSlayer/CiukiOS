# f7-12: Quake III on the Savage without command-line overrides (accelerated pixel formats first, D24/S8 research)

- **Written:** 2026-10-26 15:43 by the lead. Implementer: Codex gpt-6.1-sol, effort xhigh. Base: main after the f7-11 merge.
- **Problem (f7-11 report, "H1 default framebuffer"):** Quake III's `GLW_InitDriver` (id Software `code/win32/win_glimp.c`) asks for 24-bit depth on a >16-bit desktop when depth is automatic and stencil only with D24. Ciuki `ChoosePixelFormat` then selects index 9, XRGB32 D24/S8. The Savage provider refuses D24 and every stencil attachment, so a game started normally from the Start menu stays entirely in software. Only `+set r_depthbits 16 +set r_stencilbits 0` reaches the Savage.

## Scope
1. **Research first and cite it.** On Windows, how do `ChoosePixelFormat`/`DescribePixelFormat` rank ICD (accelerated) formats against generic ones (PFD_GENERIC_FORMAT, PFD_GENERIC_ACCELERATED, the matching rules in Microsoft's ChoosePixelFormat documentation)? What did period Savage ICDs expose (S3 Savage4/SuperSavage Windows 9x drivers in the supplied driver pack under third_party/, Mesa savage `savage_xmesa.c`/`savagecontext` visual setup, X.Org savage DRI)? Does the Savage4 class support Z24/S8 (Mesa savage driver: savage4 Z-buffer formats and stencil)?
2. **Accelerated formats first.** When the boot qualification admits hardware for the current mode, the accelerated formats (today D16/S0 in 16/32-bit colour) must be what a Windows ICD would make `ChoosePixelFormat` return for Quake III's request, following the documented Windows rules. Software-only formats stay available by explicit index (DescribePixelFormat) and remain the choice when the Savage is not qualified (QEMU, other cards). No change in behaviour on unqualified machines.
3. **D24/S8 on the Savage, if the chip has it.** If the sources show that the Savage4 class (and the T23's SuperSavage) supports 24-bit depth with 8-bit stencil, implement it in the f7-03 backend, validator, fake engine, boot qualification and admission. Use the same precision and fault rules as D16 and run differential tests against the scalar reference. If it does not, document why and keep D16.
4. **Evidence.** The H1 `--hardware-quake3-default` replay (default Quake III request) must run on the Savage model when qualified, with GPU/CPU counts as in f7-11. Run the existing GL/GDI/render3d/Savage suites, the ABI section if any public record changes, and API reference generation.

Report to build/codex/f7-12-report.md, including the updated T23 procedure: plain Start-menu launch, timedemo command without format overrides, and the census. Leave changes uncommitted.
