- **Read first:** the plan (sections 2, 4, 7), `scripts/build_image.py` (the canonical MBR/FAT32 geometry: 512-byte sectors, 8 sectors per cluster, reserved sectors, two FATs, FSInfo, active partition type 0x0C at the canonical LBA, loader at LBA 1–62, `BOOT.CFG`), `src/kernel/fs/partition.c`, `fat.c`, `blkreq.c`, `cache.c`, `src/kernel/drivers/ata*.c`, `blkpart.c`, the fs host suite (`scripts/test/host_fs_tests.sh`, fsck classification, mtools comparisons), `docs/design/resource-management-win98.md` (I/O budgets), `docs/design/boot-memory.md`.

Research first and cite: Microsoft FAT32 File System Specification (BPB/FSInfo fields, cluster count thresholds for FAT32, backup boot sector), the MBR partition table conventions (CHS/LBA fields, type 0x0C, active flag, the first partition at the canonical LBA), Windows 98 FDISK/FORMAT behaviour as the model for free-space use and alignment.

Required:
1. **Userland library `sdk/libdisk`** (C, used by Setup and future tools): enumerate disks (model, size, existing partition table and types), plan a layout for the three modes of the plan (whole disk; free space after existing partitions, minimum 2 GB; advanced: choose an existing primary partition or create one in free space, keep foreign partitions untouched), write the MBR (preserving foreign entries in the free-space and advanced modes), format a partition FAT32 with exactly the canonical geometry of `build_image.py` (so the fs suite's fsck classifications and mtools comparisons apply unchanged), install the loader bytes and `BOOT.CFG` at the canonical LBAs, create the system directories, and **verify** by reading back every written sector and running the fsck checks. All device I/O through the kernel block layer with the writer budget (no busy loops), progress callbacks for the UI, a dry-run mode that produces the exact sector plan without writing (used by the tests and by Setup's preview screen).
2. **Kernel**: the raw whole-disk device nodes with the authority gate (reads for every process class that may enumerate disks; writes only with the Setup authority), bounded transfers through the existing block request layer; nothing else in the kernel.
3. **Tests**: host harness that runs `libdisk` against a file-backed disk model: every mode's plan, MBR bytes against `build_image.py`'s, the formatted volume byte-identical to an empty volume formatted by `build_image.py` with the same parameters, loader install read-back, fsck green, mtools comparison, dry run equals the written result, refusal paths (disk too small, foreign partition overlap, write failure mid-way leaves a documented state), the authority gate (a non-Setup process cannot write).
