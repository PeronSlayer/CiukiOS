Required:
1. **Raw device nodes.** `/dev/ata0`…`/dev/ata3` (one per ATA slot; absent slots fail `open` with `ENXIO`; ATAPI slots are not exposed here): 512-byte-sector whole-disk access through the block request layer with the writer budget (bounded transfers ≤ 128 sectors per request, no busy loops, `pread`/`pwrite` at sector-aligned offsets only). **Reads** for every process. **Every mutating operation** — `pwrite`, `fsync`/`DISK_FLUSH`, `DISK_LEASE_ACQUIRE`, `DISK_LEASE_RELEASE`, `DISK_PUBLISH` — requires `setup_capability` on the calling process **and** a held lease on that disk; the check runs on each call (not at open), so a descriptor inherited, duplicated or passed to a process without the capability is read-only there, and `exec` clears the capability. Process death releases the lease. Records: `[disk] lease disk=<n> pid=<p> state=held|released|revoked reason=<…>`.
2. **Lease semantics (plan §5.3).** `DISK_LEASE_ACQUIRE`: refuses `EBUSY` while any volume on the disk is writable, has open handles, dirty pages, a pagefile, a disk log or an existing lease; otherwise detaches the disk's volumes (they were read-only in Setup mode), invalidates the cache for the device, marks the disk leased (discovery and media services skip it), returns the disk identity (`DISK_GET_INFO`: model, serial, firmware, capacity, sector size, 28-bit limit, `write_cache_state`). `DISK_LEASE_RELEASE`: releases without rescanning (the disk stays unmounted until the next boot or `DISK_PUBLISH`). `DISK_PUBLISH`: invalidates partition/cache state, rescans the table, mounts partition 1 writable **for the lease holder only** (other processes read-only; the storage writer task becomes active for that volume) at the first free letter, returns the letter and the mount reasons; on any failure the lease stays held and nothing is published. `DISK_LEASE_STATE` reports holder, disk, phase hint (set by `libdisk`, free text ≤ 32 bytes) for diagnostics.
3. **`sdk/libdisk`** (C, used by `libsetup` and future tools), header `sdk/libdisk/include/libdisk.h`:
   - `disk_enumerate()`: for each ATA disk: identity, capacity, partition table (primary/logical/extended entries, types, bootable flags, `0xEE` and overlay refusals), the volumes the kernel found (letters, labels, filesystem), the stub-MBR/`SETUP.STATE` detection ("a previous installation did not complete"), the table fingerprint (SHA-256 of the MBR and every EBR), and `installable` (only disk 0, capacity ≥ 1 GiB in the UI's rule, no `0xEE`, 512-byte sectors) with the refusal reason otherwise.
   - `disk_plan_whole(disk, out)`: the only layout: canonical MBR table (entry 1 active `0Ch` at LBA 2048, count `min(capacity, 2^28) − 2048`, saturated CHS markers as `build_image.py`), fresh random disk signature (from `getentropy`), loader at 1–1023, zero 1024–2047, FAT32 geometry (512 B sectors, 8 sectors per cluster, 160 reserved, 2 FATs of `ceil((clusters+2)×4/512)` sectors, FSInfo 1, backup 6/7, root 2; FAT size computed with the FAT specification's formula and checked against the loader's `fat_sectors × 128 ≥ clusters + 2` rule), erased-partition list, required/overhead/reserve sizes for a given payload byte count and file count (FAT overhead = clusters' slack + directories + FATs), and the **exact sector plan**: every LBA range to be written with its content hash (the dry run). `disk_plan_whole` performs no writes.
   - `disk_execute_p1(plan)`: acquire the lease, revalidate identity/capacity/fingerprint against the plan (refuse `DISK_ECHANGED` otherwise), write the **stub MBR** (item 4) with the plan's table and signature, zero 1–2047, flush, raw read-back.
   - `disk_execute_p2(plan)`: write reserved sectors (boot sector, FSInfo, backup 6/7, blackbox descriptor `CBB1` at 8, zero ring 32–159), both FATs (media byte, EOC, root chain; copy 1 → barrier → copy 2 as f1-26), the root directory with the volume label `CIUKIOS`, flush, read back every written sector raw and compare; then `DISK_PUBLISH` and create `\SYSTEM` with `SETUP.STATE` = `phase=format` through the VFS, `fsync`, flush. FAT[1]'s clean bit is **clear** here (set only at publication).
   - `disk_execute_p5(plan)`: the publication step called by `libsetup` after its own checks: loader bytes at 1–1023 (from the image bytes `libsetup` passes; read back raw), `\SYSTEM\BOOT.CFG` (through the VFS, `fsync`), set FAT[1]'s clean bit (copy 1 → barrier → copy 2), `SETUP.STATE` = `phase=installed …` (through the VFS, `fsync`), flush, **then the canonical MBR code bytes over the stub** (table and signature unchanged), flush, raw read-back.
   - `disk_consistency_check(letter)`: request the kernel's read-only remount of the published volume and return the `FAT_RO_*` reasons and the mount scan counters; any of `CORRUPT`, `COPIES`, `LOST`, `IO_FLAG` is a failure. (Define the kernel request as part of `DISK_LEASE_STATE`/a `DISK_RECHECK` ioctl in the same group.)
   - Raw read helpers for verification (`disk_read_raw(disk, lba, count, buf)`) that bypass the FAT cache (through the node, after `DISK_FLUSH`), used by `libsetup` for per-file verification.
   - Progress callbacks (sector ranges done/total) and a cancel poll between ranges; every function returns the `setup_error_class`-compatible codes listed in plan §6.4 (`DISK_E*` mapping documented in the header).
   - Bad-sector policy (D7): any read or write error on a planned or verified sector is a refusal (`DISK_EIO` with the LBA), never a bad-cluster mark; no surface scan.
