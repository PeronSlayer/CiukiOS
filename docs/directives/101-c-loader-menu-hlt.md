# 101-c — loader boot menu waits with HLT instead of busy polling

- **Written:** 2026-10-25 by the lead. Implementer: Codex gpt-6.1-sol, effort high. Worktree `../CiukiOS-wt-101-ldrhlt`, branch `wt/101-ldrhlt`.
- **Finding:** `src/boot/ciukldr/menu.inc` (`menu_getc`, `deadline_start`/`deadline_expired`) polls INT 16h AH=01, the COM1 line-status register and the BIOS tick at 0:046Ch in a tight loop without HLT. On real hardware the 3 s boot-menu countdown spins the CPU at full power; under QEMU TCG with `-icount shift=1,sleep=on` it costs about 270 host seconds (guest time advances only per executed instruction unless the CPU halts; QEMU manual, -icount).
- **Task:** research the BIOS-era idiom (BIOS INT 16h with interrupts enabled and HLT between polls; RBIL INT 16h AH=00/01, INT 15h AH=86h trade-offs; how MS-DOS/IO.SYS and boot managers wait for keys) and make each poll pass execute `sti; hlt` (woken by the 18.2 Hz timer IRQ0 or the keyboard IRQ1), so the countdown costs ~3 host seconds under icount and idles the CPU on hardware. Keep COM1 serial selection working (check the 16550 status once per tick; the receive FIFO/buffer covers 55 ms), keep the `menu_polls` safety bound meaningful (count ticks, not polls), keep every key path (Ctrl/F8 startup menu, S safe, L logged, H hardware check, N normal, timeouts) and the loader size budget (`loader keeps N free bytes` checks in the loader tests). Ensure interrupts are enabled with a valid IVT/BIOS state at that point, and that HLT is never executed with IF=0.
- **Tests:** the loader host tests (tests/host/test_loader_menu.py, test_startup_menu.py, the loader size/budget tests and any emulator-based loader harness); add a check that the menu loop contains the HLT idle path and that the safety bound counts ticks. The lead verifies under QEMU TCG+icount (expect `L:SELECT_SOURCE=menu` a few seconds after boot instead of ~270 s).
