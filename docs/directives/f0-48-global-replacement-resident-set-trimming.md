# f0-48 — global second-chance page replacement with accessed/dirty sampling, bounded reclaim slices, per-owner resident statistics, clean-cache-first reclaim order (contract M3)

- **Phase:** F0 (memory). **Model:** gpt-6.1-sol / xhigh. **Worktree:** `wt/f0-48` from main (after the f0-47 and f1-85 merges).
- **Contract:** `docs/design/win98-class-resource-management.md`, section **M3** (global replacement and resident-set trimming) with M1 (watermarks and pressure flag, f0-43), M2 (page descriptors and objects, f0-47), C4 (cache reclaim hooks, f1-85) and R1 (≤ 64 pages or 1 ms per slice) as constraints; audit rows M04, S03; source register P21/P25 and the f0-42b findings (the Resource Kit documents dynamic cache shrink under paging and idle prewrite, no sampling constants: the scan/decay constants below are CiukiOS choices).
- **Authority:** `src/kernel/core/vmm.c` (accessed/dirty sampling with correct TLB invalidation), `src/kernel/core/pmm.c` and `ledger.c` (reclaim state, per-owner statistics, pressure episodes), a new `src/kernel/core/reclaim.c` (the scanner worker), `src/kernel/proc/uaddr.c` (resident-set links, alias invalidation), `src/kernel/fs/cache.c` only through the f1-85 reclaim hook, `src/kernel/core/cpustat.c` (records), `tests/host/`, `docs/design/boot-memory.md` (replacement section).
- **Not yours:** the backing file and page-out I/O (f0-49: this directive only *selects* and queues modified pages into a bounded writeback queue interface that f0-49 implements; until then, cold private pages with valid backing = none, so only clean pages are reclaimed), DOS VM pools (f3-46).

## Required

1. **Sampling.** Global second-chance over resident pages with accessed/dirty bit sampling and correct TLB invalidation (a sampled clear bit is not proof of no users; shootdown before reuse), per-owner resident/hot/cold statistics in the ledger, fairness limits per owner so one streaming copy cannot evict all recently accessed interactive or DOS pages.
2. **Reclaim order and slices.** Unused speculative cache → clean unpinned file/cache pages (through the f1-85 hook) → cold private pages with valid backing (deferred to f0-49; implement the selection and the bounded modified-page queue interface, frames stay owned until completion and alias invalidation). Scan at most 64 pages or 1 ms CPU per slice; the scanner runs as a bounded worker woken by the M1 pressure flag and stops above the high watermark.
3. **Pressure episodes.** Each episode records pages scanned/reclaimed, dirty/in-flight/pinned rejections, owner resident changes, stall and fault counts; a protected record per episode (bounded one per second) and counters in the 30 s ledger record. Under an admitted working set that fits after clean-cache reclaim, no anonymous page-out is needed and none is attempted.
4. **Host evidence.** Controlled accessed-bit traces for hot/cold owners, alias invalidation, fault coalescing (with f0-47), pressure hysteresis, shared cache pages counted once; progress and no double-free under concurrent write/exit/reclaim; a streaming copy model that must not evict the interactive working set; slices within the R1 bound. `ASAN_OPTIONS=detect_leaks=0 bash scripts/test/host_kernel_tests.sh`, `bash scripts/test/host_fs_tests.sh` (cache hook), `python3 scripts/build_kernel.py`. Report `build/codex/f0-48-report.md`: the algorithm with its constants (labelled CiukiOS policy), the trace tables, CPU per slice, remaining.

## Constraints

Use `rg` and `sed`, never `semble`. No QEMU, no `systemd-run`, no image builds, no commits, no diary edits, host tests one at a time with `nice -n 19`. No cap or admission change; no page-out I/O; no new `panic()` paths; no production-behaviour change under `#ifndef NDEBUG`.

## Amendment 1 (lead, 2026-10-19 20:50, before launch): PFN descriptor array sized to the installed RAM

f0-47 delivered the per-PFN descriptors as a fixed array covering the 768 MiB direct-map limit (196,608 × 24 B = 4.5 MiB of kernel BSS on every profile: 3.5 % of a 128 MiB machine). This directive, which consumes the descriptors for replacement, also sizes them to the machine: at boot the PMM allocates the descriptor array for the installed RAM reported by E820 (rounded up to the direct-map granule, plus the fixed reserve for hot-plug-free systems: none), places it in the first NORMAL pages after the kernel image, records its size in the `[mm]` boot record and in the f0-43 ledger as `MM_PFN_DESCRIPTORS`, and keeps the 768 MiB direct-map limit as the upper bound. Host tests cover 128/256/512 MiB and the maximum; the 128 MiB cost becomes 768 KiB. No other f0-47 interface changes.
