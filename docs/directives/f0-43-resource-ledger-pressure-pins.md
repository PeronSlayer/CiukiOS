- **Phase:** F0 (memory). **Model:** gpt-6.1-sol / xhigh. **Worktree:** `wt/f0-43` from main (after `47b6ea6f`).
- **Contract:** `docs/design/win98-class-resource-management.md`, section **M1** (accounting, pressure and pins) and the audit rows M01, M05, D01 in `docs/validation/f0-42-resource-management-audit.md`. Read both before code.
- **Authority:** `src/kernel/core/pmm.c`, `src/kernel/core/vmm.c` (accounting hooks only), `src/kernel/include/ciuki/mm.h`, a new `src/kernel/core/ledger.c`/`include/ciuki/ledger.h`, `src/kernel/core/cpustat.c` (periodic record), `src/kernel/probes/` (H page item and a probe), `src/kernel/fs/cache.c` and `src/kernel/vm/dosvm.c` only for registering their owner categories, `src/kernel/drivers/ata_dma.c` and `src/kernel/audio/` only to adopt pin tokens for their existing DMA buffers, `tests/host/`, `docs/design/boot-memory.md` (ledger section).
- **Not yours:** caps and admission values (no cap increase, no new reclaim), the block cache policy (f1-82), the scheduler (f0-45), paging (later directives).

## Required

1. **Ledger.** One structure with per-zone physical totals, free, reserved; owner categories: kernel image, heap, stacks, page tables, DMA pins, device pins, cache data/metadata/workspace, user private resident, user shared resident (a shared PFN counted once physically, each mapping counted separately), VM private/pool resident, commit promises (RAM-backed and, as a placeholder, pagefile-backed = 0), swap capacity/used = 0 for now. Reservation, commitment and residency are distinct counters. Snapshots are consistent (taken under the PMM lock or by a seqlock) and never traverse objects whose lifetime can end outside protection.
2. **Reconciliation.** A host test and a kernel self-check at boot and on demand: usable PFNs = free + sum of owner categories, zero missing and zero double-counted pages; failures emit a protected `[mem] ledger mismatch …` record and count in a statistic (no panic). The H page gains a "Memory ledger" item printing the snapshot; a protected `[mem] ledger …` record every 30 s and at the lifecycle points below.
3. **Profiles.** Make the ledger printable at: boot end, settled desktop, audio active, copy active, maximum-VM created, VM teardown (hook points exist for the first and last; add the others as records triggered by the existing lifecycle records). The lead collects them on the T23 (256 MiB) and in QEMU later for 128/512 MiB; no cap is changed in this directive.
4. **Watermarks.** NORMAL zone low = `max(4 MiB, U/32)` with U = usable NORMAL pages, high = 2 × low, computed at boot and exposed in the ledger; below low: a `pressure` flag the cache (f1-82/f0-48) and VM admission can read, plus a protected record on each crossing (bounded one per second); no reclaim action yet. DMA-zone headroom tracked independently.
5. **Pin tokens.** `struct mm_pin` {object generation, PFN range, constraints: address mask, alignment, segment boundary, direction}; `mm_pin()/mm_unpin()` with double-unpin detection, late completion (unpin after owner exit keeps the pages until completion or proven stop), and a count in the ledger. Adopt the tokens for the existing ATA bus-master PRD buffers, the AC'97/SB16 audio rings and the DOS VM pool as the first clients (no behaviour change: the pages were already pinned by construction).
6. **Rules.** No reclaimable allocation or page fault in IRQ or audio-refill critical work (assert with the existing `irq_save` depth and a new `ledger_assert_pinned_context()` in debug builds); PMM never sleeps with IF clear. Document in `boot-memory.md`.
7. **Host evidence.** Tests: zone exhaustion, fragmented runs, double unpin, failed admission rollback, aliases (one PFN mapped twice counts once), late completion; reconciliation on every host memory test. `ASAN_OPTIONS=detect_leaks=0 bash scripts/test/host_kernel_tests.sh`, `python3 scripts/build_kernel.py`; the ledger adds no more than 16 KiB of kernel data.
8. **Report** `build/codex/f0-43-report.md`: the ledger layout, the reconciliation result on the host models, the watermark arithmetic for 128/256/512 MiB, files changed, remaining.

## Amendment 1 (lead review, 2026-10-19 14:40)

The delivery is accepted except for one point. `ledger_assert_pinned_context()` calls `panic()` under `#ifndef NDEBUG` when a reclaimable allocation or a page fault happens in IRQ or audio-refill context; the production kernel is not built with `NDEBUG` and the next image goes straight to the T23 without QEMU. A new panic path on an unqualified rule is not acceptable for a hardware-only cycle. Required:

1. In the kernel the guard never panics: it counts (`bad_context`), emits one protected record `[mem] pinned_context violation task=%s irq=%u site=%08x` per second at most (with the return address of the allocation call), and the allocation proceeds as before. The rule becomes fatal only when a build-time option `CIUKI_LEDGER_STRICT` is defined, which the host tests set for the "debug context failure" case; no production build defines it.
2. The same for the vector 14 check in `trap.c`: count and record, never a new panic.
3. Keep everything else. Rerun `ASAN_OPTIONS=detect_leaks=0 bash scripts/test/host_kernel_tests.sh` and `python3 scripts/build_kernel.py`; append an "Amendment 1" section to the report with the record format and the test change.
