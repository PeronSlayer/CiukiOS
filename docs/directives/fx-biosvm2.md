# fx-biosvm2: DOS full screen through the BIOS VBE state of real panels, recovery after a refused full screen, APM CMOS access (T23 trial 6c3b7800)

- **Written:** 2026-10-27 09:45 by the lead. Implementer: Codex gpt-6.1-sol, effort xhigh. Base: main 0b9381696.
- **Evidence:** owner's T23 (SuperSavage 5333:8c2e, 1024x768 panel), image 6c3b7800 (main 21fa0e975). Private logs in the lead's checkout: `legacy/local/physical/6c3b7800/disk/LOGS/BOOT.LOG` (session 2) and `BOOT1.LOG` (session 1). Read them; never copy them into tracked files.

## Findings

1. **No DOS game reaches full screen on the T23** (DOOM, Warcraft II, Quake, Duke Nukem 3D; Wolfenstein 3-D worked full screen on image 5bb73dba through the native path). BOOT.LOG lines 2840-2919 and 3664-3694: `native_supersavage state result=-95` (the native path now declines the panel, fx-biosvm amendment 1), then the BIOS path runs `INT 10h AX=4F04 CX=000F DL=00`, which returns `AX=004F BX=003B`: the T23 VBE BIOS needs 0x3B*64 = 3776 bytes of save/restore state. `biosvm_video_fullscreen_begin` (src/kernel/vm/biosvm.c, `fullscreen_saved[2048]` and the 2 KiB tail of the one-page scratch at `BIOSVM_SCRATCH+0x800`) refuses anything over 2048 bytes with -EOPNOTSUPP, so every request ends `fullscreen=0 continuation=windowed error=-95`.
2. **Duke Nukem 3D stops after the refusal.** BOOT.LOG: `[dosvm] fullscreen_request vm=1 mode=19` then `fullscreen_refused ... error=1 continuation=windowed`; from then on the VM runs only real-mode interrupts (`pm=0`, `rm_int` 20-40 thousand exits per window), audio underruns climb to 1995 and the game no longer advances until the owner ends it. Before the request it ran in protected mode (`pm=47078`).
3. **APM connect still faults.** Both sessions: `INT 15h AX=5301` faults with #GP at f000:4633, `fault bytes=e471e6ed` (`in al,71h; out 0edh,al`), so the APM family is quarantined (`family_quarantine family=apm`). The 0xED fix of fx-biosvm is reached only after the CMOS read. Power off now works through ACPI S5, but APM status and suspend are lost.

## Scope

1. **VBE state of any conforming size.** Research VBE 3.0 function 04h (the state buffer size is BIOS-defined, reported in 64-byte blocks) and how X.Org `vbe.c` (`VBESaveRestore`, `xf86AllocateRealModePages`/real-mode memory sized from the reported block count) and Linux `uvesafb`/`v86d` size it; cite them in `docs/design/supersavage-fullscreen.md` or the biosvm design document. Give the BIOS VM a real-mode state area large enough for real BIOSes (at least 16 KiB, bounded), placed in reserved low memory the BIOS VM already owns or can own safely; check `reserved_ram`, the mapping table (`BIOSVM_MAP_COUNT`), the stack page and every other user of `BIOSVM_SCRATCH`. Keep a hard upper bound and refuse only above it. Save and restore use the same area. Host regression: a VBE BIOS reporting BX=003B (3776 bytes) completes enter and exit with byte-identical state.
2. **Refused full screen leaves the game running.** Find why the DOS VM stays in real-mode interrupt handling after `fullscreen_refused ... continuation=windowed` (look at the guest INT 10h mode-set path that raised the request, the reflection back to the DPMI client, IF/VM state and the held IRQ model). A refused request must complete the guest's mode set in the window, exactly as if full screen had never been requested, and return to the protected-mode client. Host regression replaying the Duke Nukem 3D sequence (DOS/4GW client, mode 13h request, refusal) where protected-mode execution resumes.
3. **APM CMOS access.** Research how Windows 9x VPOWERD / the APM 1.2 real-mode interface and Linux `apm.c` treat CMOS index/data ports 0x70/0x71 during BIOS calls. Let the BIOS VM perform the ThinkPad's CMOS access during APM calls without racing the kernel RTC/CMOS users (serialize on the existing CMOS/RTC lock, restore the index port, keep NMI-disable bit semantics). Host replay of the T23 bytes `e4 71 e6 ed` at f000:4633 with no quarantine.
4. **Tests:** the existing biosvm, display, dosvm full screen, apm/power and SuperSavage suites stay green; the new cases above.
