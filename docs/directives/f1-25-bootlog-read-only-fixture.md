## Observed on image `593b18b5…` (commit `e85e0be`, `f2-all` batch, 2026-10-11)

The combined batch ran 142 cases PASS up to `bootlog` and failed
`bootlog-read-only` with `missing evidence: group=bootlog case=readonly
… result=-30 disk_log=unavailable`: the probe booted normally (volume
qualified, one log write, `END status=PASS`), because the case's fixture
declaration `{"injection": "driver-boundary", "mount_mode": "read-only"}`
is not implemented by the runner (the same class of declaration f1-22
replaced for the `mount-*` cases). The failure left the 45 F2 cases of the
batch `not_run` by prerequisite. The probe's read-only branch
(`fat_probes.c`, `probe_bootlog`) is taken when the boot volume has a
mount error, its read gate is closed, or its block device is not durable
(`blkdev_durable`), and then expects `bootlog_activate(…, false, 0)` to
return `EROFS` with zero storage calls.

## What to do

1. Choose and implement the run-time mechanism that puts the boot volume
   in that state for this case without a build variant and without touching
   the canonical image: candidates are the existing safe-mode selector
   key (`safe=1`) if the kernel keeps the read gate closed in safe mode, a
   QEMU block configuration that makes the device non-durable in the
   kernel's sense (verify what `blkdev_durable` checks and whether a QEMU
   IDE property can produce it), or a deterministic patch of the overlay's
   boot volume that yields a mount error (not just a read-only reason).
   State which condition of the probe's branch the mechanism triggers and
   prove it with the storage host harness.
2. Declare the fixture in the suite in the form the runner supports and
   write the predicates against the probe's real records (`case=readonly
   result=-30 write_count=0 storage_calls=0 disk_log=unavailable`, the
   `before` record, the metadata record).
3. Host tests: the mechanism (fake QEMU or fixture generator), the
   predicates with records in the probe's own format, and the case's
   position in the suite (it must not gate the F2 suites when it is
   not_run for an operator reason, but a FAIL still must).
