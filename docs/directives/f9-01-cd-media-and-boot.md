3. **Component eligibility and corresponding source (D12):** `config/cd-components.json` lists every component of plan §10 with its payload path prefixes, licence class, licence files and required source archives; the build fails when a payload path has no component, when a `copyleft` component is present without each required archive, or when a `bundled-shareware` row lacks its conditions text. 5. **Kernel: Setup mode and read-only storage start (D2).** Parse `setup=1` from `g_boot.options` into a kernel flag before `storage_init`; in Setup mode `storage_init` takes the read-only path of the probe gate (no writer task for the disks, no `storage_enable_write`, no `bootlog_activate`, no pagefile bind, no blackbox bind, no dirty-volume repair: `fat_mount` with the read-only request), discovers every ATA disk and its FAT/NTFS volumes read-only from `E:` onward, and records `[storage] setup_mode=1 writable=0`. `CBI_F_TEST_REQUEST` boots are unchanged. Add the integration assertion: a kernel record `[setup] writes disk=<n> count=<writes>` emitted for every ATA disk at the end of discovery and on request (an existing read-only ioctl or the `hw` record path), so the smoke test can assert zero.
6. **Kernel: `cdview` and the boot-CD identification (D1).** `src/kernel/fs/cdview.c`: a `struct blkdev` with 512-byte sectors over the optical device's 2,048-byte `request_read` path, bounded bounce buffer (≤ 64 KiB), translation `cd_block = image_start + floor(sector/4)`, slice `(sector mod 4) × 512`, bounds `capacity = image_sectors`, no `write`/`flush`, `media_generation` captured at bind and checked on every read (mismatch → `-FS_EQUARANTINED` and a `[cdview] detached generation=<n>` record). Identification exactly as plan §3.3 (session sector 17 → catalogue → initial entry → MBR signature, entry 1, BPB via `fat_mount`, `\SYSTEM\BOOT.CFG` equal to `options`, `VMM.ELF` build identity equal to the running kernel's). Bind the qualifying image as `C:` through the existing storage volume table (read-only; `v->disk` marks the optical slot) and the ISO 9660 tree of the same disc as `D:` through `storage_add_ro`; keep the existing `optical_bind` for other discs. No match → `[setup] media missing` and the console message of plan §3.2, no process spawn.
7. **Kernel: memory refusal and the Setup spawn (D11).** In Setup mode, before any process: usable E820 RAM < 128 MiB → console text "CiukiOS Setup needs at least 128 MB of memory", serial `[setup] refused reason=memory usable_kib=<n>`, halt. Otherwise `supervisor_bootstrap` spawns `/Programs/setup` (from `C:`) instead of `/Programs/desktop` with the Setup capability flag set on that process only (`struct process` field `setup_capability`, set by the supervisor at that spawn, never inherited, cleared on `exec`; f9-02 consumes it); on `-ENOENT` the stand-in console is used as today. Until f9-03 exists, a placeholder `apps/setup` (console, no libdeskui) prints the boot info, the volumes (`C:`, `D:`, `E:`…), the disks with their write counters and the serial record `[setup] media ok iso=<sha> image=<sha> payload=<n files> mode=placeholder`, then waits for a key and halts without writing anything.
