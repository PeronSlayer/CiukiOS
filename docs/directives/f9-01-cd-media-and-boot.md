# f9-01 — Setup CD: ISO 9660 media build and El Torito boot of the unchanged loader

- **Owner:** Codex, `gpt-6.1-sol`, effort `xhigh`, `--search`
- **Written:** 2026-10-21 by the lead from the approved plan `docs/design/cd-setup-plan.md` (owner approval 2026-10-21, dev diary 2026-10-21-06). Parallel with f9-02; no UI.
- **Worktree:** `../CiukiOS-wt-f9-01`, branch `wt/f9-01`
- **Read first:** the plan (sections 3, 5, 7), `scripts/build_image.py` (payload set, licence inventory, T1 checks, manifest), legacy `scripts/build_full_cd.sh` and `src/boot/full_cd_mbr.asm` (method only, in the tree on `main`; do not restore the legacy variants), `docs/design/boot-memory.md` (loader extent, `BOOT.CFG`, boot info `source`), `src/kernel/drivers/optical*.c`, `media_cd.c`, `src/kernel/fs/iso9660.c`, `mount.c` (how volumes are mounted and how the system volume is chosen), `scripts/test/run.py` (how QEMU is launched; the `-cdrom` option exists for the optical tests).

Research first and cite: El Torito specification (hard-disk emulation entry, boot catalogue, 2048-byte sectors), ISO 9660/ECMA-119 (primary volume descriptor, path tables, Joliet is not required; Rock Ridge not required), SeaBIOS and period BIOS behaviour for HDD-emulation boots (drive number 80h, INT 13h geometry of the emulated disk), the `xorriso`/`genisoimage` command lines and their reproducibility options (fixed timestamps, `-boot-info-table` not needed for HDD emulation).

Required:
1. `scripts/build_image.py --cd` (or a sibling `scripts/build_cd.py` sharing its code) produces `build/f0/ciukios-setup.iso` deterministically from the same pins and payload set as the disk image: an El Torito **hard-disk-emulation** boot image (small FAT16/32 image with MBR, `ciukldr`, `BOOT.CFG` carrying the lead-reserved token `setup=1`, and `VMM.ELF`), plus the ISO 9660 tree `\CIUKIOS\` (the complete payload set the disk image carries, same paths, same bytes), `\LICENSES`, `\SOURCES` (unified DOS kernel source archive when f3-55 is merged; the recipe tolerates its absence with a recorded reason), `\SETUP.INF.sample`. Deterministic: fixed volume id and dates, sorted entries, a manifest `build/f0/cd-manifest.json` with every file's SHA-256 and the ISO's own hash; two builds byte-identical (test).
2. Kernel: when boot info says the boot volume is the emulated CD image (the loader passes the drive and `BOOT.CFG` options; `setup=1`), the kernel mounts the emulated FAT image read-only as the system volume for the loader/kernel bytes, enumerates ATAPI devices, mounts the ISO 9660 volume read-only as `D:` (or the first free letter) through the existing optical driver, and the supervisor spawns `/Programs/setup` from the ISO (`\CIUKIOS\Programs\setup`) instead of the desktop; until f9-03 exists, a placeholder `setup` prints the boot info and the mounted volumes to the console and the serial record `[setup] media ok iso=<hash> payload=<n files>` so the smoke test can assert the path. No write to any ATA disk in this directive.
3. Tests: host tests on the ISO layout (descriptors, boot catalogue, path tables, file bytes equal to the payload set, manifest), on the emulated boot image (loader bytes identical to the disk image's loader, `BOOT.CFG` token), reproducibility; a QEMU boot-smoke definition for the runner (`f9-cd-smoke`: boot with `-cdrom build/f0/ciukios-setup.iso -boot d`, expect the `[setup] media ok` record; the lead runs it: QEMU is allowed for this suite by the owner's decision on the Setup plan).
4. Size: the ISO stays under 650 MB; the manifest reports the total.

Report `build/codex/f9-01-report.md` with citations, exact commands and results. `rg`/`sed` only; no QEMU, no `systemd-run`, no image builds (`make build-full`; building the ISO with your script on the existing `build/f0` payloads is allowed if the payloads exist in the worktree, otherwise test with synthetic payloads), no commits, no diary edits; English.
