## Required

1. **Finish runtime integration (M1).** Implement runtime selector `f3:dos-conformance run=<8 hex> guest=freedos|ciukidos` in the existing test framework. Reject unknown/duplicate keys and absent reference media explicitly. Use the same canonical full image, same VMM hardware profile and same COM binaries in both runs. Prepare the private DOS fixture with C:\D48 probes/helper, disposable C:\D48TEST scratch and unchanged initial files. Run each case in a fresh child/scratch directory, wait for its result, return to shell, and reclaim handles/searches/locks before the next case. FreeDOS 1.3 reference has SHARE loaded, ANSI and network redirector absent, the existing native DPMI/XMS host enabled, and **the new DOS bridge disabled**; CiukiDOS has the bridge enabled. A reference run served by the candidate bridge is invalid.
2. **Pin the reference (M1).** Obtain the official FreeDOS 1.3 distribution/kernel, record download URL, license, package SHA and actual KERNEL.SYS/COMMAND/SHARE hashes/version; no arbitrary current master build. Preserve the distributable reference separately from the default guest. Install the reference/probe files through the canonical build with existing reproducibility checks, never a special build variant or rebuilt-per-case image. The lead may build once after integration. Runtime selection/private overlays choose behavior; no copies of the full image. The integration evidence manifest contains `dos_conformance_adapter:1`, `image_sha256`, `probes_sha256`, `freedos_release:"1.3"`, `freedos_kernel_sha256` and the actual shell/SHARE/profile identities. This is generated from the built image read-back, not a manually asserted qualification flag.
3. **Controller/serial/fault fixtures (M1).** Emit `D48 BEGIN run=<id> guest=<name>` before cases and `D48 END run=<id> guest=<name> count=<N>` only after all results and teardown are checked. Forward existing VMM guest hex records faithfully; no fabricated PASS. The programs also write bounded COM1 output for standalone reference use. `keys-XY` injects X,Y only after `DOSKEY READY`. For critical cases provide E:\D48FAULT.DAT, at least 4096 known nonzero bytes on disposable removable media; inject exactly one read failure for `critical_retry`, persistent read failure for `critical_fail`/`critical_abort`, **after open and before its first data read**. Reference faults are below FreeDOS file services (virtual block/INT13 backend); candidate faults are at equivalent private/native-volume provider completion, through real media records/INT24. Never simulate INT24 merely by calling the handler directly. Reset injection/generation/cache between cases. A missing fixture causes a failed case, never a skip or synthetic identical result.
4. **Differential closure (M2).** Run all delivered COM programs unchanged, add cases for any newly traced service/subfunction not yet covered, and complete H49/H50 edge matrices in the production host harness. The lead runs the standalone qemu_reference.py suite inside the prescribed memory scope, one QEMU at a time under the common/all-slot locks, against identical base SHA. Schema 48 deliberately prevents the old generic runner from treating the suite's empty `cases` as a successful run; either retain this runner or teach the canonical runner the differential schema explicitly. Reject missing/duplicate/unknown results, partial logs, wrong run/guest/hash, exhausted log budget, timeout, dropped trace records or nonzero teardown ledger. Identical unsupported-function errors are failures. Produce the exact function → FreeDOS result → CiukiDOS result → verdict table. Any allowed implementation difference must be documented and individually approved by Claude, not normalized away globally.
5. **Exact inventory closure (M2).** Use f3-49's no-drop entry/return trace to cover each title's loader/start/menu/demo or play/save/config/exit path. Resolve f3-48 static candidates with reachability/disassembly of actual decompressed loader/body and DOS/4GW's translation table; do not call adjacent byte patterns executed instructions. Quake is DJGPP/go32, Wolf3D real mode/LZEXE; qualify the corresponding runtime libraries too. Distinguish observed calls, supported translation possibilities and unexecuted branches in final counts. Map every reachable/observed selector and register convention to a concrete test; close 2F 11h/12h/1Ah review without claiming an installed network stack. DOS/32A is qualified only if present in an owner-approved pinned game; it is absent from the original f3-48 corpus. Do not invent its use.
6. **Game and client closure (M3).** All three pinned original shareware titles launch unchanged from the desktop and execute their existing demo/play/input/sound/normal-exit acceptance. Include config write/reopen, save/load when supported by that package, directory enumeration, focus loss/restore and two VM/native file contention. Run existing 16/32-bit DPMI clients, COM/MZ/overlay EXEC, DOS/4GW probe and SHELL built-ins on the same image. No `-nosound` run can replace sound acceptance. Reference the existing game-profile requirements for graphics/audio thresholds; do not weaken them. Fullscreen/IRQ/audio defects outside this file API are reported with attribution and not silently repaired as a scope expansion.
7. **Performance closure (M3).** Measure DF6 on T23-class hardware: 10,000 warm 4 KiB reads, max monitor time 60 µs; 100 FindFirst scans of a 300-entry directory, max 2 ms. Report cold/warm min/p50/p95/max, monitor/wall/ready-wait and guest IF time with calibrated clock and image/source hashes. Verify zero post-map guest INT13 calls for file reads, physical miss traffic versus f3-47 cache hits, bounded 2000 ms wait/callback/cancel behavior under native copy and audio load, and all VM/cache/handle ledgers returning to baseline. Host timing and QEMU TCG are diagnostic only; they cannot close the T23 numbers. If a target fails, retain the exact evidence and report the failed criterion; do not revise the target without lead/owner review.
8. **Per-game fallback (M4).** Add an English setting `DOS kernel` with `CiukiDOS (default)` and `FreeDOS 1.3` for each game, stored through the launcher's existing configuration path. Default/missing/invalid values select CiukiDOS; a one-game override cannot alter another title or the system shell. FreeDOS starts the same original executable/arguments/data in its own private image/overlay with the candidate bridge disabled, existing VMM devices/DPMI and share/media permissions intact. Do not rewrite a CiukiDOS overlay with FreeDOS metadata; keep overlay namespaces by game/kernel/base hash. A missing/corrupt reference reports an actionable launch error and preserves the selected setting; never silently switches guest. Stop/close/relaunch releases the old guest fully. Include hashes/kernel choice in launch evidence without exposing private game paths. Preserve Ciuki portrait/icons/tagline and all existing English copy conventions.
