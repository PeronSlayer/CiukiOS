## fx-1 VGA legacy ports and LPT1 at 0x3BC (accelerator never started)

Evidence: `[registry] conflict: savage-vga wants 0:3b0-3e0 held by lpt1 reason=overlap` then `[accel] summary accelerated=0 driver=savage reason=port_claim_failed`. The T23's LPT1 is at 0x3BC (BDA), inside the range the display drivers claim. Windows assigns VGA 0x3B0–0x3BB and 0x3C0–0x3DF and leaves 0x3BC–0x3BF to a parallel port. Required: every display driver, fbdev and the display model claim the VGA legacy I/O as those two ranges (mono 0x3B0–0x3BB only when needed), never 0x3BC–0x3BF; the LPT driver claims only its own base..base+2 (+ ECP base+0x400 range when ECP) and nothing else; a conflict still refuses honestly. Tests: an LPT at 0x3BC plus each accelerated driver's claim succeeds; LPT at 0x378/0x278 unchanged; a real overlap still refused. Model/effort: Sonnet, high.

## fx-2 Windows repaint over other windows (software engine)

Evidence: owner report "le finestre ridisegnano sopra altre finestre"; the trial ran on the software engine (`accel fills=0 copies=0 caps=0`, `pointer=sw`). Find which path lets an application's update reach screen pixels covered by another window: the f2-98a/f2-98b Windows 9x update model (clipped update regions, retained scrolling, engine move/scroll copies), the f2-101d part C client commands (KEYED/MONO/SCALED/LINE, batches) and the software engine swdib, the desktop compositor's visible-region clipping. Fix the root cause so every draw is clipped to the window's visible region (Windows 9x: an application only paints inside its visible region; the window manager repaints exposed areas). Tests: overlapping windows with the lower window animating, scrolling, moving and using each command type; screen pixels of the upper window unchanged; goldens. Model/effort: Opus, high.

## fx-3 ThinkPad volume keys out of step and i8042 interrupt-off sampling

Evidence: `[ec] thinkpad gate=ec_handshake_failed stage=probe error=-19` (the volume poll of f2-96 never starts, so the hardware volume buttons and the system mixer diverge); `[kernel] irqoff_section=i8042_sample site=c01c6cce irqoff_max_us=2156 violations=749`. Since f1-110 the ThinkPad EC sits behind the generic EC service; find why the handshake fails on the T23 (compare with the pre-f1-110 path that worked, dev diary 2026-10-22), restore the volume synchronisation (hardware buttons change the system volume shown in the tray and the mixer; system volume changes do not fight the buttons), and remove the interrupt-off i8042 sampling (bounded, interrupt-on or event-driven, as the f1-103/f1-122 contract requires). Tests: EC handshake on a T23-shaped fixture, volume event round trip, i8042 sampling never disables interrupts beyond the kernel budget. Model/effort: Opus, high.

## fx-4 DOS VMs fail at vm-create with EIO

Evidence: `[launch] name=dosbox pid=8 error=-5 stage=vm-create window=DOOM` (also Quake; CiukiDOS window `error=-4`); one VM did start and close earlier (`[dosvm] close vm=1 … reason=owner-gone`). Zone 1 at boot: `usable=3840 free=574 reserved=3001`, `owner=image resident=2482`, `owner=net resident=519` (the kernel ELF is 15.6 MB after ACPICA, 22 display drivers and new audio engines). Find the exact EIO source in VM creation, confirm or refute low-memory exhaustion with the ledger, and fix the root cause the Windows 98 way (low/DMA memory reserved for what needs it, kernel image and pools placed above it when possible, honest refusal records). The fix must hold on 128 MB–512 MB machines of the hardware baseline. Tests: VM creation with the trial's zone figures, repeated create/close cycles, the refusal record. Model/effort: Opus, xhigh.
