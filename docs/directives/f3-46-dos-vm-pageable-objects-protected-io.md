## Required

1. **Quota, commitment, residency, pins split.** The VM admission formula distinguishes address quota (pool size visible to the guest), commitment (RAM or pagefile backing promised), residency (resident now) and pinned pages (device/model/DMA); XMS/EMS/DPMI handles point to memory objects (f0-47) whose pages may be non-resident when unpinned; alternate aliases (EMS frame, DPMI mappings) share page identity and access/dirty history; the eager zeroing of the whole pool at creation becomes demand-zero commitment unless the owner's compatibility flag requires eager backing (keep a per-game option; measure creation time with f0-41's model).
2. **Pins.** Pin before virtual DMA, VGA model harvest/exchange and device emulation work; unpin only after the VM/device completion boundary; trap and fault handling may block only at a published safe continuation (never mid-instruction); the f3-45 ISR/IRET rules and f3-40 DMA cadence are preserved and re-verified by their existing tests.
3. **Disk path.** Private FAT16 image reads and the future host-volume bridge go through the f1-83 request framework and the C5 identity (the f3-47 per-VM cache becomes shared file-page references with the same batching and lookup benefit; its memory is a reclaimable VMM category under f0-48, never guest-visible); the overlay's 1024-row copy-on-write index is accounted separately and never dropped as cache debt; seek+transfer atomicity preserved or replaced by explicit-offset requests (justify); no double mounting with incoherent caches.
4. **Scheduling boundary.** Virtual PIT/SB advancement, pending IRQ delivery, VIF/shadow and exact host-saved ISR returns stay independent of host scheduling; idle VMs sleep; foreground preference bounded by R2; page-in or disk waits never stop the desktop or the physical audio timeline; a guest with IF clear delaying its own interrupt is recorded separately from host-ready wait.
5. **Combined host gate.** Maximum-quota admission and failure/exit return every commit/resident/pin/swap/overlay counter to baseline (ledger reconciliation); page faults through EMS/XMS/DPMI aliases preserve data; termination with I/O and IRQ pending leaves no stale completion; replay DOS/4GW start, DOOM's flat-stack ISR case (f3-45 fixture), guest IF-off periods, disk traffic (f3-47 traces) and host audio together: no `late-grow`, no underrun, no deadline miss. `ASAN_OPTIONS=detect_leaks=0 bash scripts/test/host_kernel_tests.sh`, `bash tests/host/audio/run.sh`, `bash scripts/test/host_fs_tests.sh`, `python3 scripts/build_kernel.py`, `make CAP= apps` if the launcher's per-game option changed. Paged creation 23.6 ms vs 134.3 ms locked; combined replay `late-grow=0 lead=8 max_gap_us=1772`; DOS audio clock 248/250 µs. This closes item D1 and the resource-management contract sequence (M1–M4, R1–R3, C1–C5, D1). Decisions:

1. **Admission stays RAM-based.** A second VM is refused on 128 MiB as before; pagefile-backed admission would put a game VM's working set on the swap device, which Windows 98 avoided for V86 VMs too.
2. **Paged is the default**, locked per game through `launch.memory` and the F12 key, until the T23 acceptance says otherwise; the per-game setting is recorded in the launcher settings line.
3. The VM disk cache stays in `MM_VM_PRIVATE` (no new owner); C5 shared page identities stay recorded as not implemented.
4. Low memory (conventional, UMB, VGA) stays resident: accepted as a recorded departure from Windows 98 (device access and V86 trap latency).
5. The `launch.memory` ABI amendment and the `core/vmm.c` sampler and `probes/f3_probes_vm.c` edits outside the file list are accepted (the sampler change fixed VGA/VBE dirty harvest under pressure).
6. DPMI 0703h no longer zeroes locked pages, per the DPMI 0.9 text: accepted.
