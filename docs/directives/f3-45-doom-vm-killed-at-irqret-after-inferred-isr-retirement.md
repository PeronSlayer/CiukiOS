# f3-45 — DOOM (DOS4GW) killed at the host IRQRET stub after f3-44 retired its live hardware-interrupt record by inference

- **Phase:** F3 (DOS VMs). **Model:** gpt-6.1-sol / xhigh. **Worktree:** `wt/f3-45` from main (after `0aad7c2a`).
- **Authority:** `src/kernel/vm/dpmi_dispatch.c` (`dpmi_irq_resync`, `pmint_return`, `dpmi_deliver`), `src/kernel/vm/dpmi_internal.h` (record fields), `src/kernel/vm/dosvm_perf.inc` (records only), `tests/host/dosvm_dpmi_test.inc`, `tests/host/dosvm_test.c`, `docs/validation/f3-42-guest-isr-latency.md` (new section F3-45), `docs/design/execution-abi.md` (policy text).
- **Not yours:** the IF/IOPL libx86emu seam, the two-tick pending-IRQ fallback, PIC programming, the audio subsystem.

## Evidence (T23, image c2d2a237, serial capture `legacy/local/physical/c2d2a237/serial.log`, read-only; first physical trial with the BIOS serial port enabled)

- DOOM in VM 1 (`gen=8317`, DOS4GW, flat model) ran from 95 s, entered full screen at tick 114014 and was killed at tick 133209 after about 19 s of play. The owner reports: "finalmente DOOM a schermo intero con audio non lagga ma poco dopo è crashato (dopo 20/30 s di gameplay)".
- Last heartbeat: `group=vm_heartbeat vm=1 gen=8317 n=14 tick=132960 pm=1 cs=01df eip=0024ed67 if=1 vif=1 arm=0 sh=0 depth=0`.
- The kill: `group=vm_fault_pc vm=1 gen=8317 pm=1 vec=13 cs=1fff eip=00000120 linear=000f1320 address=00000000 error=0`, then `[dosvm] lifecycle stage=stop vm=1 generation=8317 reason=2 vector=13 eip=000f1320`, `fullscreen_watchdog … reason=return-or-fault`, clean restore (`native_supersavage phase=restore result=0`, `fullscreen=0 … result=0`).
- `cs=1fff` is `DPMI_HOST_CS` (`DPMI_SEL(DPMI_IDX_CODE)`), `eip=0x120` is `DPMI_PM_IRQRET`, linear `F1200h + 120h`: the guest returned from a hardware-interrupt handler through the host's own IRQRET HLT stub, exactly as designed (`dpmi_internal.h:44–49`). `dpmi_stub_trap` → `pmint_return` found no matching `DPMI_REC_PMINT`/`DPMI_RF_HWINT` record on top of the record stack (`d->stats.stale++; return -EFAULT`) and the VM was ended as "forged or stale".
- The record had been removed earlier by `dpmi_irq_resync` (added by f3-44, `dpmi_dispatch.c:936–985`, called from `dpmi_deliver` at every IRQ delivery): a record is retired when `returned` (exact interrupted context) **or** `consumed` = same SS selector and stack base as at delivery and `sp >= r->isr_stack_end`. DOS4GW runs every stack on one flat selector; a handler that switches to a private stack at a higher address, or any nested delivery while the guest's ESP sits above the original frame on the same selector, satisfies `consumed` while the handler is still running. The later real return then hits a stack without its record.
- Health before the kill, same session: `cadence blocks=430 … irq_latency_avg_us=720–963 if_clear=5–97` and the transport `published=1898 retired=1890 lead_periods=8`: the f3-44 fallback and f4-31/f4-32 audio are working on the hardware; this directive must not undo them.
- Verbose VM rows (`vm_perf_if`, `vm_fault` registers, `vm_stack`) were dropped on this boot (`bootlog … dropped=48607`): they are not available for this kill. The serial `vm_if` rows (n=57–64) show ordinary fallback activity (`restore=1 matched=1`) right before.
- Quake in VM 2 (`gen=14548`) in the same boot ran full screen and exited normally (`lifecycle stage=stop … reason=1`).

## Required

1. **No retirement by inference.** Remove the `consumed` inference from `dpmi_irq_resync`. A hardware-interrupt record is retired only by (a) the host-owned return stubs (`pmint_return`, RM `DPMI_RM_RETURN`), or (b) the exact `returned` match of the interrupted context (CS:EIP and SS:ESP equal to the saved frame, same mode). Keep the 50 ms expiry as it is (expired records stop suppressing IF recovery but remain continuations for the late return). Keep `dpmi_lock_below` for the `returned` case. Document in `execution-abi.md` why a stack-pointer comparison cannot prove consumption for a flat-model client.
2. **A stale-looking IRQRET must not end the VM when a continuation exists.** In `pmint_return`, if the top record is not the matching `PMINT/HWINT` one, search the record stack downward for the most recent `DPMI_RF_HWINT` record of the current client; if found, unwind to it (retire everything above it with `dosvm_isr_end`) and return normally; count the event in a new `v->perf.isr_late_return` and emit a protected `[dosvm] isr late_return vm=%u gen=%u depth=%u skipped=%u cs=%04x eip=%08x` record (bounded: once per second per VM). Only when no hardware record exists at all does the return remain a forged/stale fault. State in the report why this cannot be abused to escape a real forged frame (the host still owns the saved contexts).
3. **Evidence for the next trial.** Make the fault stop path emit the `vm_fault` register row and the first `vm_stack` part as protected records (not verbose) when a VM is ended by a fault, so the next physical kill has registers even if the verbose ring overflows. Add the record stack depth and the top record kind/flags to `vm_fault_pc`.
4. **Regressions.** Host test that reproduces the kill with the f3-44 code: flat-model client, IRQ delivered at ESP = X on selector S, handler switches ESP to a private stack above X + 12 on the same selector, a nested IRQ is delivered there (resync runs), then the handler returns through IRQRET → with the fix the VM survives and the record is retired exactly once; the old `consumed` cases of f3-44 (`dosvm_dpmi_test.inc` 770–807 and whatever else asserts `isr_retired` or edited-frame retirement) are adapted to the new policy, never deleted silently: say in the report which assertions changed and why. Keep the nested IRQ7/IRQ0, 49/50 ms expiry and late-return cases green.
5. **Verification.** `ASAN_OPTIONS=detect_leaks=0 bash scripts/test/host_kernel_tests.sh` complete and green, `python3 scripts/build_kernel.py`, `python3 scripts/gen_api_reference.py` if a public header changed. Report `build/codex/f3-45-report.md`: the mechanism as confirmed on the host model, before/after, the changed assertions, remaining.
