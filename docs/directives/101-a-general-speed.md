1. **Desktop CPU share.** With the Control Panel and the Music Player open, the 2-second statistics show the desktop process threads (`desktop#38`, `#44`, `#47`) at 33–55 % of the CPU together (e.g. `top=desktop#47:318k283s8,desktop#44:125k123s8,…`), `interactive_pm=327`, `switches=11594` per 2 s window. Identify which desktop threads these are (compositor, worker, input, tray/clock, shell) and what they do while nothing visibly changes (repaints of unchanged regions, timers, polling, clock/tray redraw, music progress repaint, full-window repaints for small changes). Bring idle/steady-state desktop CPU close to zero in the Windows 98 model (paint only invalidated regions, timers only when visible, no polling). Build a host replay from these figures that fails on the current code.
2. **Interrupt-off sections.** `irqoff_section=schedule site=c019bd31 irqoff_max_us=4259 violations=2363 unclassified=2363`, `irqoff_long site=c019bd31 us=2129 phase=ldt/debug` and several `phase=gap` records of 2.1–4.2 ms at other sites. Determine (with the kernel map of build/f0/VMM.ELF at 60d029c9 built in your worktree via scripts/build_kernel.py) which are firmware SMIs attributed to the nearest kernel section (the log also has `smi count=1 … max_us=2117 … ec_near=2`) and which are real long kernel sections; fix any real one (e.g. LDT/debug-register work done with interrupts off on every switch) and correct the attribution so firmware time is not reported as `schedule` violations.
3. **Storage writer overruns.** `[sched] device_overrun task=storage-writer#15 count=22 consumed_us=3787`, `device_top task=storage-writer#15 us=142172` per window while the boot log writes 33 MB in a session. Reduce the boot-log volume in normal boots (statistics records every 2 s are useful for trials but must be budgeted: Windows 98's BOOTLOG.TXT is written only on request) and keep the writer within its device budget; do not lose trial evidence: keep the records the T23-style trials rely on, but make the verbose 2-second statistics a "logged boot" option (the startup menu already has Logged boot) or throttle them.
