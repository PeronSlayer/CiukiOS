# f0-46 — interrupt top halves and deferred work with budgets, an ordered timer queue with generation-safe cancellation, raw/firmware/unclassified attribution (contract R1 interrupts, R3 timers)

- **Phase:** F0 (kernel core, real-time). **Model:** gpt-6.1-sol / xhigh. **Worktree:** `wt/f0-46` from main (after the f0-45 merge).
- **Contract:** `docs/design/win98-class-resource-management.md`, sections **R1** (IRQ-disabled software work ≤ 100 µs, deferred work ≤ 1 ms per turn and ≤ 2 ms service span, attribution) and **R3** (timer queue, 1 kHz PIT kept, audio deadlines unchanged); audit rows R02, R06; the source register P08, P11, P15, P16.
- **Authority:** `src/kernel/arch/trap.c`, `src/kernel/arch/pic_pit.c`, `src/kernel/core/irq_budget.c`, `src/kernel/core/timing.c`, `src/kernel/core/sync.c` (`deadline_after_ms` and the timer queue), `src/kernel/core/task.c` (`sched_tick` timer walk only), the IRQ handlers of `src/kernel/drivers/` and `src/kernel/usb/` and `src/kernel/audio/` only to move work out of the top half into preallocated deferred state, `src/kernel/core/cpustat.c` (records), `tests/host/` (latency, timer, IRQ budget, audio), `docs/design/execution-abi.md` (interrupt and timer section).
- **Not yours:** the audio refill policy numbers (R3 keeps them), scheduler priorities (f0-45, merged before you start), the ledger (f0-43), DPMI dispatch, PIC programming beyond what exists.

## Required

1. **Top halves.** Every IRQ handler acknowledges and captures into preallocated state and wakes deferred work; no cache scan, filesystem access, formatting, buffer zeroing or mix operation with interrupts disabled. Audit each handler (ATA, USB UHCI/OHCI, AC'97/ES137x/SB16 period IRQs, e100/rtl8139/ne2k, i8042, PIT) and list the software work it does with IF clear; move anything above the budget to deferred work. Target: IRQ-disabled software work ≤ 100 µs outside identified firmware execution; keep shorter existing device budgets.
2. **Deferred work.** One bounded mechanism (the existing device workers or a small deferred-work queue): at most 1 ms before yielding or requeuing, 2 ms maximum service CPU span, and a guard against repeated notifications turning one callback into an unbounded chain (coalescing with a count).
3. **Timers.** Replace the per-tick task walk in `sched_tick` with an ordered timer queue (sorted list or wheel): entries carry the absolute deadline, callback kind and owner generation, armed/in-flight/cancelled state; the timer IRQ only moves due entries to bounded work; cancellation and owner destruction prevent an old callback from touching a reused owner (generation check). PIT divisor 1193 and the calibrated monotonic timestamps stay. Tests: wraparound, rearm, concurrent cancel/expiry, tick loss, firmware pauses, 1000 timers.
4. **Attribution.** Records separate raw IRQ-off maximum, charged software work, interrupt owner and site, firmware attribution (the f0-39 SMI heuristic) and unclassified gaps; the existing `irqoff_section`, `[irq] budget exceeded`, `stretch_max_ms` and `[cpu]` records keep their names and gain the new fields. The T23's 2.1 ms IRQ 11 pauses stay reported as raw; they never relax the software budget.
5. **Host evidence.** Host replay showing ≤ 100 µs modeled IRQ-off software work for every handler, deferred turns ≤ 1 ms, timer queue costs independent of the task count (measure 10 vs 1000 timers), and the audio deadlines (R3: wake-to-execution ≤ 2 ms, 2 ms service) intact under the combined load. `ASAN_OPTIONS=detect_leaks=0 bash scripts/test/host_kernel_tests.sh`, `bash tests/host/audio/run.sh`, `bash tests/host/usb/run.sh`, `python3 scripts/build_kernel.py`. Report `build/codex/f0-46-report.md` with the per-handler table (before/after IF-clear work), the timer queue design and costs, remaining raw overruns.

Use `rg` and `sed`, never `semble`. No QEMU, no `systemd-run`, no image builds, no commits, no diary edits, host tests one at a time with `nice -n 19`. No new `panic()` paths; no production-behaviour change under `#ifndef NDEBUG`.
