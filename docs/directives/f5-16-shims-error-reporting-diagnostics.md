## Required

1. **Shim engine.** `SHIMS.INI` grammar (sections per executable name, match keys, `shims=` list of `name@version(params)`), parsing with bounds, matching precedence (SHA-256 > `TimeDateStamp`+`SizeOfImage` > file size; conflicts recorded and the most specific wins; override layer beats the file), application at process start before the EXE's first instruction, the `[win32] start ... shims=<list>` field, the initial set: `version` (reported Windows version/`GetVersion(Ex)`/`VerifyVersionInfo` where present), `ddraw-555`, `ddraw-scale`, `ddraw-windowed` (parameters validated and handed to f5-11), `heap-zero`, `heap-pad` (N bytes), `memstatus-cap` (N MiB for `GlobalMemoryStatus(Ex)`), `io-pit`, `io-gameport` (privileged `IN`/`OUT` emulation of PIT channel 0 reads with a monotonic model and port `201h` returning no joystick; any other port → the original exception), `dll-native` (named DLLs preferred from the application's directory over builtins), `fpu-cw` (initial x87 control word for the main thread and new threads), `w-stubs` (named `W` exports fail with `ERROR_CALL_NOT_IMPLEMENTED`); each shim with a stable name, integer version and a unit test; the version-bump rule enforced by a test that pins the version table.
2. **Crash and refusal paths.** Unhandled exception → the Details data (exception code, module name and offset, EIP, registers, eight stack words with safe reads of a possibly invalid stack) → the f5-09 dialog ("NAME has performed an illegal operation and will be shut down.", Details, Close) → termination with the exception code; the `[win32] crash` record (one line, serial and boot log) and the `C:\WINDOWS\CRASH\` text file (≤ 16 KiB, eight files rotated, no memory contents beyond the eight stack words); loader failures (f5-05B reasons) → the "no server"/"missing DLL"/"not a valid Win32 application" dialogs with Windows 98 wording; `.msi`/`msiexec`/`msi.dll` → "This program uses Windows Installer, which CiukiOS does not support" + `[win32] refuse msi`; driver installs (`.vxd`/`.sys`/`.drv` copy into the Windows directory by installers, `CreateService` of a kernel driver) → refused with a record and the documented error; unsupported runtimes (`.NET`, 64-bit PE, console-only subsystems if not supported) → the loader's refusal dialog.
3. **Records and budgets.** `[win32] stub DLL!FUNCTION` once per process per function with the documented failure value per convention (BOOL FALSE + `ERROR_CALL_NOT_IMPLEMENTED`, HRESULT `E_NOTIMPL`, MMRESULT `MMSYSERR_NOTSUPPORTED`, LSTATUS `ERROR_CALL_NOT_IMPLEMENTED`, NULL handles with last error), a stub never returns success without performing the operation (audit of every W21 stub in the builtin set against this rule: table in the report), warnings rate-limited to 64 per process with a final "suppressed N" record, redaction (names of DLLs, functions, title files and window classes only), `[win32] start pid exe pe=<timestamp>:<sizeofimage> shims=`, `[win32] exit pid code reason=<normal|crash|killed|restart> peak_commit peak_handles threads`, Task Manager shows the executable name (through the f5-09 interface).
4. **Evidence.** Match/version/precedence/hash-conflict tests, each shim's unit test, the stub audit table, crash tests for every exception class (access violation, divide, privileged instruction, breakpoint, illegal instruction, stack overflow with guard page, FPU exceptions) with the Details data pinned and the malformed-stack case, the record budget and redaction tests, the refusal paths, the desktop dialogs through the f5-09 harness (pinned frames); `make CAP= apps`, `python3 -B -m unittest discover -s tests/host/win32 -t .`, `python3 -B -m unittest discover -s tests/host/desktop -t .`, `ASAN_OPTIONS=detect_leaks=0 bash scripts/test/host_kernel_tests.sh` if a kernel file changed.
