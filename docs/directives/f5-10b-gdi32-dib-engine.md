# f5-10B — `gdi32` drawing engine: device contexts on protocol v3 surfaces, DIB engine for 1/4/8/16/24/32 bpp, DIB sections, bitmaps, pens, brushes, regions, clipping, ROPs, `BitBlt`/`StretchBlt`/`StretchDIBits`, palettes, coordinate mapping, text output through the FreeType boundary

- **Phase:** F5 (USER/GDI, second reviewed hand-off of the contract's f5-10; starts in parallel with f5-10A). **Model:** gpt-6.1-sol / xhigh, `--search`. **Worktree:** `wt/f5-10b` from main (after the f5-06 and f5-08 merges; f5-09 merged for the surface format).
- **Contract:** `docs/design/win32-personality-contract.md`, sections "Display model → Windowed programs", "Formats, palettes, scaling and pacing" (the f5-08 conversions the compositor reuses), "Memory budget at 128 MiB" (fonts and rasteriser ≤ 2 MiB shared; surfaces reported), the directive definition **f5-10** (line 1417) and the dependency row (line 1991: independent DIB/ROP/region/palette/reference frames and object lifetime tests). Read the f5-08 report (surface format, damage rules, conversion/scaling helpers), the f5-09 report (surface sharing), `docs/design/fonts-contract.md` (section "2026-10-14 — F2-63: FreeType everywhere": FreeType 2.13.3 pinned, modules, interpreter v35, grey coverage; section "Fonts and F5 aliases"), the f5-02 census (`gdi32` import list), `tests/host/win32/wine_specs/dlls/gdi32/` if present (inventory only).
- **Authority:** the user-mode `gdi32` of the personality in the f5-05B builtin store (DC model, DIB engine, objects, regions, palettes, text output calling the FreeType boundary), the shared-surface client helpers agreed with f5-10A, `tests/host/win32/gdi32/` (new, with pinned reference frames under `tests/host/win32/gdi32/frames/`), `tests/suites/f5-core.json` (a `w32-gdi32-qemu-t23` case written, unrun). The FreeType build of the SDK (`sdk/` fonts backend of f2-63) is consumed, not changed: if a new entry point is needed, define it in the report and ask the lead.
- **Not yours:** `user32` (f5-10A: it calls your `HDC` creation on a window surface and your `DrawIcon`/`DrawText` helpers), font selection, enumeration and metrics for dialogs (f5-10C owns `CreateFont(Indirect)`, `EnumFontFamilies(Ex)`, `GetTextMetrics`, `AddFontResource`; you provide the glyph rasterisation and `TextOut`/`ExtTextOut` geometry over an interface you define together in the first hour), DirectDraw surfaces (f5-11, which will wrap your DIB engine for `GetDC` on a DirectDraw surface: keep the engine callable on an arbitrary pitch/format buffer), printing (none).

## Required

1. **Device contexts.** Display DCs on a protocol v3 surface (XRGB8888 or the f5-08 format of the window), memory DCs (`CreateCompatibleDC`, `SelectObject` of bitmaps and DIB sections), `CreateDC("DISPLAY")`, DC state (`SaveDC`/`RestoreDC`), current pen/brush/font/bitmap/palette/region, colours (`SetBkColor/Mode`, `SetTextColor`, `SetROP2`, `SetStretchBltMode` with `COLORONCOLOR`/`HALFTONE`/`BLACKONWHITE`/`WHITEONBLACK` per Windows 98), mapping modes `MM_TEXT`, `MM_ANISOTROPIC`, `MM_ISOTROPIC`, `MM_LOMETRIC`… with `SetViewportOrg/Ext`, `SetWindowOrg/Ext`, `DPtoLP`/`LPtoDP`, `GetDeviceCaps` reporting the desktop's resolution, 96 dpi logical, `BITSPIXEL`/`PLANES`/`RASTERCAPS`/`SIZEPALETTE` of the current mode, `GetDCOrgEx`.
2. **DIB engine.** Source and destination formats 1, 4, 8 (palette and indexed), 16 (555/565 masks), 24 and 32 bpp, top-down and bottom-up; `CreateDIBSection` (shared pixel memory the program writes directly; `GdiFlush` no-op semantics), `CreateBitmap`/`CreateCompatibleBitmap`/`CreateDIBitmap`, `GetDIBits`/`SetDIBits`/`SetDIBitsToDevice`/`StretchDIBits`, `BitBlt`/`StretchBlt`/`PatBlt`/`MaskBlt` subset with the 256 ternary ROPs (table-driven, exact), `TransparentBlt` if in the census, integer and fractional stretching matching Windows 98's `COLORONCOLOR` pixel selection (document the rule and pin it), pixel functions (`SetPixel(V)`, `GetPixel`), `ExtFloodFill`, lines and curves (`MoveToEx`/`LineTo`/`Polyline`/`PolyBezier`/`Arc`), filled shapes (`Rectangle`, `Ellipse`, `RoundRect`, `Polygon`/`PolyPolygon` with alternate/winding fill, `FillRect`, `FrameRect`, `InvertRect`), pens (cosmetic widths, styles, `PS_INSIDEFRAME`), brushes (solid, hatched, pattern 8×8 with `SetBrushOrgEx`, `DC_BRUSH`), `GetObject`, `DeleteObject`, stock objects, object lifetime on process exit. Clipping: `SelectClipRgn`, `IntersectClipRect`, `ExcludeClipRect`, `GetClipBox`, the visible-region clip provided by f5-10A (children/siblings), `OffsetClipRgn`.
3. **Regions.** Rectangular, elliptic, polygonal and combined regions (`CombineRgn` with all modes), `OffsetRgn`, `PtInRegion`, `RectInRegion`, `EqualRgn`, `GetRgnBox`, `GetRegionData`/`ExtCreateRegion`, `FillRgn`/`FrameRgn`/`InvertRgn`/`PaintRgn`, `SetWindowRgn` support for f5-10A (shape applied at surface publication).
4. **Palettes.** Logical palettes (`CreatePalette`, `SelectPalette`, `RealizePalette`, `AnimatePalette`, `SetPaletteEntries`, `GetNearestPaletteIndex`, `GetSystemPaletteEntries`, `GetNearestColor`), the Windows 98 20 static colours, `PC_RESERVED`/`PC_NOCOLLAPSE`, `WM_PALETTECHANGED`/`WM_QUERYNEWPALETTE` hooks for f5-10A; on the desktop's true-colour surface a realised palette maps 8-bpp sources through the f5-08 palette conversion; the contract's 8-bit full-screen path (f5-11) will reuse the same tables.
5. **Text output boundary.** `TextOut`/`ExtTextOut` (`ETO_OPAQUE`, `ETO_CLIPPED`, dx array), `DrawText(Ex)` layout helpers used by f5-10A/f5-10C (`DT_*` flags: single/multi-line, tabs, prefix underline, ellipsis, calc-rect), `GetTextExtentPoint32`, `SetTextAlign`, `GetTextAlign`, `SetTextCharacterExtra`; glyphs come from a face handle that f5-10C selects through the interface you define together (grey coverage from FreeType with interpreter v35 per the fonts contract, composited with the text colour and background mode); code page 1252 to Unicode for glyph lookup.
6. **Evidence.** Pinned reference frames for every ROP class, stretch mode, format pair (1/4/8/16/24/32 source × 16/32 destination), region operation, palette realisation and text alignment case, produced by the engine on the host and compared by digest; object lifetime tests (leaks on `DeleteDC`, process exit); cost per frame of a 640×480 `StretchDIBits` 8→32 bpp and of a 640×480 `BitBlt` `SRCCOPY` on the host (-O2) with the i686 audit (no SSE); `gdi32` census coverage = 100 % implemented or W21 stub with the per-export table; `make CAP= apps`, `python3 -B -m unittest discover -s tests/host/win32 -t .`, `python3 scripts/gen_api_reference.py` if a public header changed. Report `build/codex/f5-10b-report.md` with the `HDC`/surface interface (shared with f5-10A), the text boundary (shared with f5-10C), the ROP/stretch rules with their sources (Windows 98 DIB engine documentation of the Platform SDK/DDK era, cited; the Resource Kit book in `build/rskt/` for the display model), costs, remaining.

## Constraints

Use `rg` and `sed`, never `semble`. No QEMU, no `systemd-run`, no image builds, no commits, no diary edits, host tests one at a time with `nice -n 19`. No Wine `gdi32` source is copied (inventory only); no SSE/MMX in the engine (i686 baseline, the kernel audit rules extend to this user-mode engine by directive); fixed-point only where the ROP/stretch rules need fractions. No new `panic()` paths; English.
