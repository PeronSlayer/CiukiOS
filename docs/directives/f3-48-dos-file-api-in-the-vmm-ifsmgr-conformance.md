## Why

CiukiDOS already implements INT 21h functions 00h–10h, 19h–1Ch, 20h, 25h, 29h–3Ah, 3Bh–4Fh, 50h–59h, 5Dh, 60h, 62h, 66h–68h, 88h, 89h, C2h, F1h (195 `int21_*` routines, 25,246 lines), with COM/MZ loading, PSP/JFT/SFT, basic FCBs, directories, FindFirst/FindNext, attributes, IOCTL and vectors. It lacks the FCB I/O family (11h–17h, 21h–24h, 26h–28h), 5Ah/5Bh, 5Ch (record locking), 65h, 6Ch, and every file operation goes through INT 13h sector emulation on a private FAT16 image. Windows 95/98 kept the real-mode kernel for processes and memory and served file calls through IFSMgr/VFAT in ring 0 (32-bit file access). CiukiOS follows that model: the VMM intercepts the file and directory functions and serves them from the native VFS with documented MS-DOS semantics; CiukiDOS stays the project's DOS and keeps everything else. FreeDOS is the conformance reference and an optional per-game fallback guest, never the default kernel.

## Required

1. **Primary sources, cited:** MS-DOS Programmer's Reference (functions 00h–6Ch, error codes, SFT/JFT/PSP/SDA/SysVars layouts, DTA FindFirst format, extended error 59h, critical error INT 24h, share/lock semantics 5Ch and the SHARE conventions), Ralf Brown's Interrupt List (INT 21h, INT 2Fh 11h redirector interface and 12h DOS internal services, INT 2Fh 1Ah), the Windows 95 DDK IFSMgr topics (P10 of the f0-42 audit: `IFSMgr_Ring0_FileIO`, the IFS hook chain, how real-mode INT 21h is reflected to ring 0 and how the DOS box's SFT is kept coherent), the FreeDOS kernel source for cross-checking behaviour only (cite file and function when a behaviour is taken from it), DOOM/Quake/Wolfenstein source (file access patterns: `open`/`read`/`lseek` through DOS/4GW's DOS extender translation, `findfirst`).
2. **Inventory.** From the three library games and their extenders (DOS/4GW, DOS/32A if present, the game loaders) and from CiukiDOS's own needs: the exact set of INT 21h/2Fh functions, subfunctions and flag/register conventions each title uses, obtained by static analysis of the binaries (DOS/4GW's INT 21h translation list) and by the VMM's INT 21h trace (add the trace if the existing `vm_perf_v` records are insufficient: function, AL/BX/CX/DX, result, time). Table: function → used by → CiukiDOS status (present/absent/partial with line reference) → target implementation (VMM/VFS or real-mode kernel) → conformance test id.
3. **Contract: "DOS file API in the VMM".** Written as acceptance criteria and interfaces:
   - interception: which INT 21h functions the VMM takes before the real-mode kernel (3Ch–47h, 4Eh/4Fh, 56h, 57h, 5Ah–5Ch, 6Ch, 68h, 43h, 39h–3Bh, 47h, 0Eh/19h drive selection, the FCB family 0Fh–17h/21h–28h either served or emulated on top of handles, as MS-DOS did), which stay in CiukiDOS (00h–0Ch console, 25h/35h vectors, 48h–4Ah memory, 4Bh/4Ch/4Dh exec/exit, 30h–34h, 50h–52h, 62h, IOCTL subfunctions on devices), and how the VMM hands a function it does not serve back to the kernel (chain to the saved vector in the same V86 frame, no re-entry);
   - state: one DOS SFT per VM owned by the VMM, mirrored into the guest's SFT for programs that read it; the PSP JFT stays in guest memory and is read/written by the VMM; open-file identity is the VFS node (share claims per MS-DOS SHARE rules: compatibility/deny modes, inheritance bit, record locks 5Ch); current directory and default drive per PSP as in DOS (kept in the SDA the VMM owns);
   - name space: the DOS box sees the VM's private image as C:, and the native volumes (the stick E:, the system disk) as additional drive letters through the VFS, with 8.3 names generated deterministically for long names (document the algorithm, MS-DOS style `~1`), read-only where the owner's policy says so; the DTA format of FindFirst/FindNext is exact (attribute, time, date, size, name, 21 reserved bytes holding the VMM's search cursor);
   - errors: DOS error codes and the extended error (59h) table, INT 24h critical error for removable-media failures (Abort/Retry/Fail semantics through the existing media records), no DOS call may block the VM worker indefinitely (every VFS wait is bounded and reported through the existing `vfs_wait` evidence);
   - performance targets: a 4 KiB read served from the VFS cache in ≤ 60 µs of monitor time on the T23 class, FindFirst over a 300-entry directory ≤ 2 ms, no INT 13h traffic for file reads once the image's clusters are mapped (the VMM reads the image through the VFS/block cache of f3-47, or the image is mounted as a volume: decide and justify);
   - compatibility invariants: everything CiukiDOS passes today keeps passing (its SHELL.COM built-ins, exec of COM/MZ, DPMI clients), the three library games run unchanged, the DOS/4GW extender's INT 21h translation works for every function in the inventory.
4. **Conformance battery.** Small real-mode test programs (NASM or Open Watcom C, built by the host toolchain already in the SDK, or hand-assembled COM files checked into `tests/host/dos/`) exercising every inventoried function with edge cases (handles exhaustion, deny modes, seek beyond EOF, FindFirst on empty/absent paths, attributes on directories, rename across directories, record locks, DTA preservation, critical errors), each printing a deterministic result line. Two runners: (a) the host harness that drives the VMM's DOS API implementation through the existing DOS VM host model where possible; (b) a QEMU runner (`tests/suites/f3-dos-conformance.json`, unrun) that boots the same programs under FreeDOS 1.3 (reference) and under CiukiDOS+VMM, captures the result lines on the serial port and diffs them. The lead runs (b) under the development exception. Expected outcome format: a table function → reference result → CiukiDOS result → verdict.
5. **Implementation directives, written completely:** `f3-49` (the VMM DOS file API: interception, SFT/JFT/SDA ownership, handle functions, FindFirst/Next, attributes, dates, directories, rename/delete, 5Ah–5Ch, 6Ch, errors, INT 24h; with its host tests and its own acceptance numbers), `f3-50` (CiukiDOS side: hand-off of the file functions to the VMM through a documented hook, the FCB family on top of handles, 65h, cleanup of the sector-level paths that become unused, SHELL.COM unchanged), `f3-51` (conformance closure and games validation: the battery green on host and QEMU against FreeDOS, the three games and the DPMI clients passing, performance targets measured, the per-game FreeDOS fallback switch in the launcher). Each with phase, model, authority, required, evidence, constraints, in the house format of the existing directives, sized honestly.
