# fx-is5boot: InstallShield 5 setups start without Win16 (Half-Life reference CD)

- **Written:** 2026-10-27 10:50 by the lead. Implementer: Codex gpt-6.1-sol, effort high. Base: main 29587e240 or later.
- **Owner decision 2026-10-27:** implement the InstallShield 5 start path now; the Win16 subsystem stays after the 1.0 Beta (dev diary 2026-10-20-08).
- **Reference media:** the owner's original Half-Life CD (Sierra, 23 Nov 1998), mounted read-only on the lead's workstation at `/run/media/peronslayer/Halflife`. It is commercial: read it only, never copy any of its files into the repository, fixtures, images or logs. Tests that use it run only when it is mounted and skip otherwise.

## Facts measured by the lead (Wine 11.20 on the workstation, +process/+file/+profile traces)

- `SETUP.EXE` (60,416 bytes) and `_ISDEL.EXE` are NE executables for Windows 3.1; `_SETUP.DLL` is an NE DLL; `autorun.exe`, `hlinst.dll` and the `dsetup*.dll` are PE32. No SafeDisc/SecuROM files on the disc.
- The NE stub reads `SETUP.INI` (`[Startup]` `IsdelName` default `_ISDEL.EXE`, `AppName`, `CmdLine`, `EnableLangDlg`; `[Mif]` `Type`), `SETUP.LID` (`[Languages]` `Default`) and `system.ini` `[Boot]` `Shell`.
- It picks the engine archive for the CPU: its strings list `_INST32I.EX_` (Intel), `_INST32A.EX_`, `_INST32M.EX_`, `_INST32P.EX_` and `_INST16.EX_`. `_INST32I.EX_` starts with bytes `2a ab 79 d8 00 01 00 00` followed by `Copyright (c) 1990-1995 Stirling Technologies`; its directory names `ZDataI51.dll`, `_WUTL951.DLL` and `zdata.dll`.
- It writes to `%TEMP%`: the engine as `_INS5176._MP` (547,840 bytes, PE32 GUI), `ZDataI51.dll` (53,760 bytes, PE32 DLL) and `_WUTL951.DLL` (46,592 bytes, PE32 DLL).
- It writes `%TEMP%\_INS0432.INI`, which is not an INI but one line of engine arguments (84 bytes): `  -fD:\SETUP.INS  -z1 -cx -x<TEMP>\ -x1D:\ -q10010` (CD at `D:\`, `<TEMP>` the temp directory with its trailing backslash).
- It writes `%WINDIR%\_isenv31.ini` (the process environment as one line of space-separated `NAME=value` pairs), `%WINDIR%\_iserr31.ini` (`[SharedErrors]` with keys 7068, 7063, 7064, 7110: localized startup error texts) and `%WINDIR%\_delis43.ini` (cleanup list for `_ISDEL`: sections `[fileN]` with `main=<engine path>`, `exeostype=1`, `alt0=<TEMP>\ZDataI51.dll`, `alt1=<TEMP>\_WUTL951.DLL`).
- It starts the engine with `WinExec(<TEMP>\_INS5176._MP, "")` (empty command line, current directory the CD root). The engine reads `_INS0432.INI`, `_iserr31.ini`, `_isenv31.ini`, then `D:\layout.bin`, `D:\os.dat`, `_sys1.cab`, `_user1.cab`, `data1.cab`, and extracts its support files into `%TEMP%\_ISTMP0.DIR\`.

## Scope

1. **Research and record.** Find and cite the InstallShield 5 bootstrap behaviour (InstallShield 5 documentation of `setup.exe` command-line options such as `-s`, `-f1`, `-f2`, `-SMS`, `-z`; the 32-bit replacements and analyses written for 64-bit Windows, which has no Win16; otvdm/winevdm; Wine bug reports) and the Stirling Technologies archive format of `_INST32I.EX_` (open-source unpackers, and zlib `contrib/blast` for the PKWARE DCL "implode" coding, zlib source in build/downloads/zlib). Write `docs/design/installshield5-bootstrap.md` with the format, the handoff files above, the decisions and the links.
2. **Native bootstrap.** When CiukiOS is asked to start an NE executable that is an InstallShield 5 bootstrap (from `CreateProcess`/`WinExec`/`ShellExecute` of a Win32 program such as `autorun.exe`, from the desktop, Files, Run or the Start menu), it runs a native 32-bit implementation of the stub instead of refusing the NE file. Identify the stub conservatively (NE header plus the InstallShield files beside it: `SETUP.INS` and an `_INST32*.EX_`); every other NE file keeps today's behaviour. The implementation reproduces the measured behaviour: reads `SETUP.INI`/`SETUP.LID`, picks `_INST32I.EX_`, unpacks the engine and its DLLs to the temp directory with unique `_INSnnnn._MP` names, writes the four handoff files with the exact formats, honours `[Startup] CmdLine` and the user's own arguments (pass them where the original stub does), starts the engine with an empty command line and the CD root as current directory, and reports errors with the `_iserr31.ini` texts. Put it where the Win32 subsystem starts programs (look at how `sdk/win32/ldr` and the w32 process creation refuse NE images today, and at `sdk/win16/ne`); explain the choice in the design document.
3. **`_ISDEL.EXE`.** The engine and the uninstaller may start `_ISDEL.EXE` (NE) to remove the files listed in `_delis43.ini` after the engine exits. Recognize it the same way and perform that cleanup natively.
4. **Tests.**
   - Host unit tests for the archive decoder and the handoff writers with synthetic fixtures generated by the test (no commercial bytes): a test-side encoder may emit literal-only DCL streams.
   - A local-only host test (skipped when `/run/media/peronslayer/Halflife` is absent) that unpacks the real `_INST32I.EX_` and checks the three output sizes above.
   - The Win32 host harness used by the Quake III installer tests (`tests/host/win32/installers/`) runs the Half-Life setup from the mounted CD through the native bootstrap until the engine has extracted `_ISTMP0.DIR` and shows its first dialog; go further (to a completed install) if the harness allows it, and record exactly where it stops.
   - The existing Win32 loader, installer and process suites stay green.
