# fx-uafind: logarithmic user-address extent lookup

- **Written:** 2026-10-25 by the lead. Implementer: Codex gpt-6.1-sol, effort xhigh. Base: main 921156a97. Evidence: the T23 trial of image c42f556e (owner, 2026-10-25 evening) showed w32srv at 68-119 permille (67-97 in kernel mode) and a Win32 installer thread at 189 of 213 permille in kernel mode while four Quake III installers (48 MB self-extracting PE) ran; the system was saturated and the desktop starved. The rendering agent's analysis (docs/validation/t23-render-netsurf-2026-10-25.md, section 2.5, in worktree ../CiukiOS-wt-t23-render) points at `ua_find` (src/kernel/proc/uaddr.c and callers): every user-memory copy and user page fault looks up its address with a linear walk of the process's extent list, up to one walk per 4 KB page; at ~500 extents the repository's 32x T23 model gives up to ~50 us per page (~0.65 s of kernel time per pass over a 48 MB archive). Quake III Arena (next workload) maps and copies far more.

## Scope
1. Measure first: a host benchmark in tests/host/proc (or the existing uaddr/proc test) that builds an address space like the trial's (500-2000 extents: image sections, heaps, VirtualAlloc reservations, mapped views, stacks, guard pages) and times ua_find, user copy in/out of 48 MB in 4 KB and 64 KB chunks, and the page-fault path, with the T23 cost model the repository uses.
2. Replace every linear extent walk on hot paths (ua_find, the fault handler's lookup, protect/query (VirtualQuery) walks, the copy helpers, anything else rg shows walking `extents` per page) with a logarithmic structure (balanced tree or sorted array with binary search, plus a per-address-space last-hit cache), keeping the extent semantics exactly (overlap rules, split/merge on protect/free, guard pages, shared views, COW, locking and pin rules, ua_pin), bounded memory, no allocation in IRQ context, and the existing lock order. Windows NT uses a balanced VAD tree for the same purpose; cite it.
3. Tests: all existing proc/uaddr/win32 kernel_core/section/loader tests unchanged and green (scripts/test/host_kernel_tests.sh sections for proc, uaddr, win32 core, fs tests that use user copies), new tests for split/merge/overlap edge cases and the new structure's invariants (checked after every mutation in a randomized test against the old linear implementation as an oracle), and the benchmark with before/after numbers.
Report to build/codex/fx-uafind-report.md: measurements before/after, design, files, tests, risks. Leave changes uncommitted.
