# f0-44 — bounded teardown, allocation and transaction/chain walks: every formerly unbounded kernel path gets an iteration bound, a safe point and a host-model worst span (contract R1 / M06)

- **Phase:** F0 (kernel core). **Model:** gpt-6.1-sol / xhigh. **Worktree:** `wt/f0-44` from main (after `24bdfb5c`).
- **Contract:** `docs/design/win98-class-resource-management.md`, section **R1** (bounded kernel work) and the audit rows R01, M06, S05 in `docs/validation/f0-42-resource-management-audit.md`; the f0-41 report (`build/codex/f0-41-report.md`, "Remaining") lists the sites it could not bound: `core/vmm.c::as_destroy` page walk on failed/normal VM teardown, `fat.c::chain_at` cached chain walks, `dosvm_vga_model` harvest/exchange, cleanup after a failed creation.
- **Authority:** `src/kernel/core/vmm.c`, `src/kernel/core/kheap.c`, `src/kernel/proc/uaddr.c` (`free_pages`, `protect_pages`, process exit), `src/kernel/fs/fat.c` (`chain_at` and the chain/census walks: service points only, no format or ordering change), `src/kernel/fs/cache.c` (dirty scans: service points only), `src/kernel/vm/dosvm.c` and `dosvm_xms.c` (teardown), `src/kernel/vm/dosvm_vga.c` only to bound or document the harvest/exchange transaction, `src/kernel/core/task.c` only for a `kpreempt_point` cost model helper if needed, `tests/host/` (kernel latency, VM lifecycle, fs), `docs/validation/f0-40-reliability-audit.md` (section F0-44) with the per-site table.
- **Not yours:** scheduler priorities (f0-45), IRQ/timer budgets (f0-46), the cache writeback policy (f1-82), DPMI dispatch.

## Required

1. **Inventory first.** List every loop in the authority files whose iteration count depends on memory size, VM size, file size, directory size or cache size, with its current bound (none, or a fixed count without a cost model). For each, give the conservative per-iteration cost on the T23 class (use the f0-41 arithmetic: 18 µs per allocate/zero/map page, 8 µs per bulk page copy, 1 µs per cached FAT entry, the measured numbers where the f0-41/f1-82 reports have them) and the physical maximum iteration count (maximum VM 24 MiB = 6144 pages, maximum process address space, maximum FAT32 chain on a 512 MiB volume = 131072 clusters, 8 MiB cache = 2048 blocks).
2. **Bound every site.** Target ≤ 1 ms between safe points and no span > 2 ms with preemption disabled outside IRQ-off paths. Insert `kpreempt_point()` or `fs_service()` with an explicit batch size derived from item 1 (comment with the arithmetic), only where no spinlock or IRQ-off section is held and outside indivisible guest-emulation or device-publication transactions. Teardown paths are the priority: `as_destroy`, process exit page release, VM pool release and failed-creation unwinding (f0-41 could not cover them), heap reclaim walks, `chain_at` on long cached chains, cache dirty scans in `cache_writeback_tick` (f1-82 already batches the writes: check the scan itself). Where a transaction cannot be split (VGA harvest/exchange), bound it by construction (maximum bytes per transaction) and document the bound and its physical maximum; do not insert a point inside it.
3. **Host evidence.** Extend `tests/host/test_kernel_latency.py` and the VM lifecycle/fs harnesses: long cleanup (maximum VM teardown after a failed creation and after a normal stop), fragmented cached FAT chains (131072 clusters, random order), all-dirty 8 MiB cache scan, maximum task and page counts; the negative control of f0-41 (110 ms without points) stays. Assert per site: longest modeled span ≤ 2 ms-equivalent, total work within +10 % of the unbounded version. Keep the f0-41 16-page creation points.
4. **Audit table.** For every site: file:function, loop bound, points added or transaction bound, host worst span before/after, physical maximum, remaining unqualified paths (explicitly listed, never silently dropped).
5. **Verification.** `ASAN_OPTIONS=detect_leaks=0 bash scripts/test/host_kernel_tests.sh`, `ASAN_OPTIONS=detect_leaks=0 bash scripts/test/host_fs_tests.sh` (all groups, fsck and mtools comparisons), `bash tests/host/audio/run.sh` (no lead growth from the lifecycle replays), `python3 scripts/build_kernel.py`. Report `build/codex/f0-44-report.md`.

## Constraints

Use `rg` and `sed`, never `semble`. No QEMU, no `systemd-run`, no image builds, no commits, no diary edits, host tests one at a time with `nice -n 19`. No new `panic()` paths; no `#ifndef NDEBUG` guards that change production behaviour (the kernel does not define NDEBUG). Do not touch `task.c` scheduling or `sync.c` (f0-45 runs in parallel) beyond a cost-model helper.
