## Task

1. **Find how the bind of a real full-speed BOT device can stop the whole system.** The bind runs in the controller's `usb-host` worker (`task_create_kernel(..., P_DEVICE)`) after `max_lun`: INQUIRY through `command_policy`, TEST UNIT READY, READ CAPACITY, SYNCHRONIZE CACHE, then the mount (`fs_lock_take(&store->vfs.lock)`). Audit: every loop in `usb_storage.c`, `usb_core.c`, `uhci.c` (TD/QH walker of f1-56, bulk NAK handling of f1-57, `usb_sleep`, `usb_wait_register`) for an unbounded wait or a spin that never sleeps; every lock held across a transfer wait (`transfer_lock` is an `fs_lock`: who else takes it or waits on it — the disk log writer, the desktop's storage/media queries that AutoPlay triggers, `usb_storage_service`); the lock-order checker the kernel already has; interrupts disabled around DMA bounce handling; a TD max length or buffer size that lets the HC DMA past the INQUIRY/CAPACITY buffers (36/8 bytes with a 64-byte bulk packet). Decide from the code which of these can produce a system-wide freeze (PS/2 input dead, disk log stopped) and fix every candidate, not only the first.
2. **Bounded by construction:** the bind must finish or fail within 5 s; each bulk step has a deadline; the worker sleeps, never spins; no lock of the storage/VFS class is held while waiting for a transfer; a failed or timed-out bind quarantines the device and leaves input and other controllers alive. A host regression with (a) a model stick that NAKs bulk IN forever, (b) one that never completes the CSW, (c) one that STALLs INQUIRY, each with a concurrent client taking the VFS lock and the disk-log writer running: the desktop-side task must keep running (scheduler replay) and the device must end quarantined with records.
3. **Records that survive a freeze:** emit one `[usb-storage] stage=<name> addr=..` record at `klog` level before each step (max_lun, inquiry, ready, capacity, flush, mount) and make the disk log flush synchronously while a bind is in progress (or flush per record for this subsystem), so the next T23 log names the exact step. Mind the serial path cost: these are few records.
4. **QEMU regression `usb-input-uhci`:** reproduce the "terminal evidence before declared stimuli completed" with the runner model (`tests/host/test_runner_usb.py`, the gate counters of runner-04, the probe stage counters of f2-58) — what in f1-57 (poll cadence, PE recovery, 8-byte requests, debounce) changed the timing so the probe's END preceded the stimuli; fix the driver or the probe pacing, not the runner's expectations.
