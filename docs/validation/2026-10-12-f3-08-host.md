# f3-08: host verification decisions

Scope: `docs/directives/f3-08-review-fixes.md`; host evidence only. No image,
QEMU, hardware qualification, commits or diary entries in this worktree.

Sources checked before implementation on 2026-10-12:

- [Intel SDM Vol. 3B, §18.2.3 and §18.3.1.4](https://www.intel.com/content/dam/support/us/en/documents/processors/pentium4/sb/253669.pdf):
  BS identifies single-step completion even when the instruction cleared TF;
  other debug causes may coexist. Consume the armed step once, retain watchpoint
  dispatch, and do not assume MOV/POP SS produces an immediate debug trap.
- [Intel SDM Vol. 2](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-2b-manual.pdf)
  and [manual catalogue](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html):
  operand/address sizes determine immediates and ModR/M displacement lengths;
  LOCK on MOV and string instructions faults. Flags-save recognition must decode
  from an established boundary; unknown encodings refuse recognition. The VGA
  continuation may conservatively leave LOCK instructions to native execution.
- [Windows 95 interrupt-flag compatibility](https://devblogs.microsoft.com/oldnewthing/20160411-00/?p=93281/):
  keep the existing saved-image TF technique and physical IOPL/IF policy.
- [libx86emu upstream instruction implementation](https://raw.githubusercontent.com/wfeldt/libx86emu/master/ops.c):
  the host CPU adapter reports BS for modeled single steps and copies the
  resulting TF, including flags-clearing POPF/IRET. An independent media-free
  host fixture executes both operand sizes and the MOV/POP SS delayed step.
- [ACPI 6.6 §20](https://uefi.org/specs/ACPI/6.6/20_AML_Specification.html):
  decode the complete PkgLength, including its own encoding, and walk bounded
  AML terms. Skip Buffer/Package/Method payloads and non-root scopes as units;
  never resume byte scanning in unknown terms. Validate the declared `_S5`
  elements inside the package before using either sleep type.
- [ACPI 6.6 §4.7.2.5](https://uefi.org/specs/ACPI/6.6/04_ACPI_Hardware_Specification.html)
  and [§7.4.2](https://uefi.org/specs/ACPI/6.6/07_Power_and_Performance_Mgmt.html):
  ownership requires SCI_EN; require both present PM1 control blocks before
  writing sleep controls. A failed handshake logs and follows the directive's
  reboot fallback, after storage synchronization has succeeded.
- [Intel ICH4 datasheet §14.2.2–14.2.7](https://www.intel.com/content/dam/www/public/us/en/documents/datasheets/82801db-io-controller-hub-4-datasheet.pdf):
  CIV/PIV/PICB validate DMA progress; a cursor error is not proof of an exhausted
  silent queue. Track actual nonzero published PCM and distinguish validated
  DCH exhaustion from invalid observations/timeouts. Keep fatal backend reset
  and quarantine behavior for unproved drains.
