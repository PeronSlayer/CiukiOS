# Quake EXEC rejection and disk-cache regression controls

Research checked on 2026-10-15 before implementation:

- [FreeDOS's executable loader](https://github.com/FDOS/kernel/blob/master/kernel/task.c)
  (`DosExeLoader`) iterates `exRelocItems` times. With no relocations it never
  reads a relocation record, regardless of `exRelocTable`. CiukiDOS's
  `int21_exec_validate_mz_reloc_table` instead checks the unused offset even
  when the count is zero. Keep the header-size and nonempty-table bounds,
  but accept an empty relocation table without inspecting its offset.
- [DJGPP's DOS stub](https://github.com/jwt27/djgpp-cvs/blob/master/src/stub/stub.asm)
  queries the DPMI host with INT 2Fh/1687h after DOS has loaded its real-mode
  image. A DOS EXEC rejection therefore precedes any DPMI entry; changing
  protected-mode nested frames or the guest's memory quota cannot fix it.
- [SeaBIOS disk services](https://github.com/coreboot/seabios/blob/master/src/disk.c)
  keep sector completion distinct from read-ahead. Retain the F3-24 immutable
  base cache and overlay-first reads, and test requests across its windows,
  the actual cut-image end, two independent images and VM-slot reuse.

The supplied serial log for image
`aae6a1704e2d2a8996f5e3c651b34afa0b87d5609c213383ae77305043bb26f4`
contains `RUNREC FAIL E000B` (hex decoded from its guest record), after all
sixteen game payload hashes and the RUNREC hash. The existing read-only
`build/f0/games/CIUKIGAM.IMG` has 52656 sectors: FATs at 73/201, root at 329,
data at 361, eight sectors per cluster, QUAKE directory cluster 4 and
QUAKE.EXE cluster 5968 (LBA 48089), size 404480. Its MZ header has
`e_cparhdr=32`, `e_crlc=0`, and `e_lfarlc=0x0A0D` (the beginning of the
embedded stub comment). The unconditional bounds check rejects 2573 > 512
and returns DOS error 11, matching RUNREC's observed failure.

This validator predates the merges named in the directive (`git log -L`
attributes it to `1dd520ab`). The supplied evidence establishes a startup
blocker, not when the reported regression began or which earlier image
passed. The cache boundary tests must not be represented as reproducing
cache corruption if they pass unchanged. No QEMU, image build or diary is
part of this worktree's validation; the lead owns image qualification.

The host fixture uses these real coordinates, the 99-cluster contiguous EXE
chain (5968 through 6066), and the exact first 28 header bytes. Other file
content is deterministic synthetic data; this is neither a replacement
game image nor evidence of Quake execution. It exercises production
`dosvm_disk.c` and BIOS reads, including a three-sector request at LBA 48127,
overlay rewrites within a cached window, the 48-sector final window,
zero-fill and overlay writes beyond the cut base, and image/generation
isolation. The disk checks pass before the fix. The same harness executes
the exact production 16-bit relocation validator extracted and assembled
alone: Quake's header fails before the fix and passes after it. Header-size,
nonempty-table extent, excessive count and arithmetic-overflow rejection
remain covered.

Startup screen records now accept either `CBI_F_VERBOSE` or
`CBI_F_DIAG_VERBOSE`. Tests exercise both verbose hardware flags and
`CBI_F_TEST_REQUEST | CBI_F_DIAG_VERBOSE`, including IRQ deferral, five-second
cadence, no output catch-up, active text page, arbitrary hex characters,
stop-on-graphics behavior and the existing 240-byte record limit. A quiet
boot and a test-request flag alone still produce no startup screen records.

The required kernel host suite ran once with
`ASAN_OPTIONS=detect_leaks=0 nice -n 19 bash scripts/test/host_kernel_tests.sh`
and exited 0. Its DOS VM harness passed 8107465 checks, maximum record 237
bytes. The optional full-DOS boot replay was skipped because this worktree
has no built DOSBOOT image; the isolated production validator did execute
under libx86emu. Full verbatim output and the before-fix rejection are in
`build/codex/f3-25-report.md`. The lead must rebuild the canonical image,
including its guest DOS payloads, then qualify `quake-qemu-t23`,
