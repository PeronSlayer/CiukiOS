# CiukWeb HTTPS, CSS, JavaScript and desktop responsiveness

Status: validated; the full shipping-image gate has passed.

## Defects isolated

The browser's cryptography and JavaScript run in a preemptible DPMI worker.
Moving this work out of the desktop exposed a separate physical IRQ problem:
the packet driver could re-enter while its guest had executed CLI. The Jemm
profile kept physical IF set, but reflected PCI level interrupts directly
instead of observing the guest's logical IF. Crynwr's receive ISR unmasks its
line before clearing its reentry guard, relying on CLI to protect that gap.
A second interrupt in the gap returns through the guard without EOI. An
orphaned IRQ10 then blocks mouse IRQ12 and correctly prevents a VM switch.

The bounded `web-stack-10` capture shows the desktop in its STI/HLT idle loop,
physical slave ISR `04`, the NE2000 receive status outstanding, and Crynwr's
`in_recv_isr` back at zero. The current handler is at `2442:0873`, reached
through vector `72`; the unmask and guard-clear sequence is visible directly
in the saved DOS memory. This agrees with the source-level race. The capture
does not trace every instruction of the interrupt that triggered it.

The earlier GPU change alone did not remove this race. GPU/RNG polling now
uses the PCI function's INTx-disable bit and reads ISR status, following the
[Virtio polling contract](../design/virtio-polling-interrupts.md). Network
ownership and level-interrupt delivery are described in the
[IRQ design](../design/network-irq-ownership.md).

Two separate JavaScript integration defects were found. MicroQuickJS requires
a NUL immediately after each source span, so the adapter now owns a bounded,
terminated copy. More importantly, the DOS ROM-table relocation treated any
word looking like an address as a pointer. The generated table was at
`0x59f0..0x7f5c`: the trailing `Id` bytes of `getElementById` form `0x6449`,
which was incorrectly relocated. Both 64-bit and 32-bit Linux engine tests
passed because their table addresses do not overlap those character values.
The target fix must relocate only explicitly generated pointer entries.

Browser layout also measured bold words using normal-font advances. The
measurement API now initializes its style flags and uses the same font as
the painter, preventing words from consuming their intervening spaces.

Additionally, background worker idle polling under `DPMIRUN.COM /B` initially
failed to yield VM time slices because DJGPP's `__dpmi_yield()` passed a zeroed
RMCS frame (`rFlags = 0`) to `INT 31h AX=0300h`, causing `vm_yield2f` to skip
the `HLT` transition due to a strict logical IF check on the simulated frame.
The worker now explicitly sets `rFlags = 0x200` upon simulated real-mode yield,
and `vm_yield2f` unconditionally transitions to monitored `HLT`, allowing Jemm
profile 11 to yield CPU time slices back to the desktop VM cleanly (yielding
48,000+ times during integration runs while keeping desktop cursor latency under ~0.40s).

A subsequent CSS engine defect was isolated on large public pages such as
`https://www.google.com/`:
1. Leading whitespace before at-rules (such as `\n@media`) was buffered into the
   selector buffer, preventing the at-rule detector (`!selector_len && c == '@'`)
   from matching. Media blocks with nested braces desynchronized the declaration
   parser, causing `WEBSTYLE_STATUS_ERROR` at sheet end.
2. The style sheet exceeded the previous 16 KiB and 128-rule limits.
   `webstyle.c` now uses a shared 8 KiB declaration pool with property compaction
   that discards unsupported properties prior to storage, expanding rule capacity
   to 256 rules and sheet limits to 32 KiB while reducing DGROUP usage from
   53,696 bytes to 44,704 bytes.
3. Nested `<div>` tags previously incurred unconditional paragraph line breaks (6px),
   pushing the Google search form and buttons off-screen. `div` tags now line break
   only when content exists or explicit CSS margin is specified, and observe computed
   `display: inline` / `inline-block`.
4. Added `<center>` block formatting and centered image alignment, and fixed table
   margin restoration upon `</table>` tag closure.

## Gate

`scripts/tests/qemu_web_stack.py` uses a reflink of the canonical full image,
one capped Linux QEMU/KVM instance and an ephemeral test CA added only to
that copy. It exercises a trusted TLS page, external CSS, ordered inline and
external scripts, DOM text changes, `document.write`, PNG/JPEG/GIF images,
wrong-IP and expired certificates, script budget interruption and cooperative
worker teardown. Optional `--public` checks the production CA bundle against
`https://example.com/` and `https://www.google.com/`; `--doom` checks local Doom
startup/new game/normal exit after browser teardown. Commercial game data remains local.

Pointer samples detect a multi-second freeze; screenshot acquisition takes
roughly 0.38 seconds itself. They are not sub-frame input-latency measurements
and cannot establish an absolute absence of visual stutter.

Host sanitizer results already available: 101 WebNet checks, the real
MicroQuickJS adapter on both pointer widths, bounded page-adapter checks, CSS
selector/cascade checks and image codec malformed-input fixtures. Target
behavior remains a separate gate.

## Feature boundary

TLS 1.2 requires the installed trust bundle, a valid UTC clock and VirtIO RNG.
CSS and DOM support are bounded subsets; TLS 1.3, a full DOM/event loop,
general modern-site compatibility, Adam7 PNG and progressive JPEG are not
implemented. GIF displays its first frame. These changes do not establish
Internet Explorer equivalence or physical-hardware qualification.
