# F2-45 compositor row painting — host validation

The directive is `docs/directives/f2-45-compositor-performance.md`. These
changes preserve the shared theme painter, portrait, Tango store, pixel
rounding, and damage geometry. Hardware timing remains the lead's gate.

## Sources and implementation decisions

- [Intel Software Developer's Manual, RDTSC and serializing instructions](https://cdrdv2-public.intel.com/868137/325462-089-sdm-vol-1-2abcd-3abcd-4.pdf):
  RDTSC alone does not serialize execution. The host harness puts CPUID
  before and after each timestamp, pins itself to one permitted CPU, warms
  the caches, and reports the median of nine batches. The printed
  `cycles_per_pixel` is TSC ticks per output pixel, not a measurement of
  core-clock cycles on an invariant-TSC host.
- [Clang strict aliasing documentation](https://clang.llvm.org/docs/UsersManual.html#strict-aliasing)
  and [GCC optimization options](https://gcc.gnu.org/onlinedocs/gcc/Optimize-Options.html):
  the checked-in app builder requests `-O2`; its SDK wrapper also applies
  `--target=i686-unknown-elf`, `-march=pentiumpro`, `-fno-strict-aliasing`,
  `-fno-builtin`, and no SSE/MMX. Host timing uses scalar code by default
  to reflect these restrictions; its libc memcpy is still the host libc.
  Compiler options are not changed by this implementation.
- Repository reference: `theme.c` supplies the original frame, font,
  icon blending and shadow rules. Frame rasters are generated by that
  painter, with only the opaque caption and edge spans cached. Rounded
  corners are painted against the current scene. Four bounded slots fall
  back to the original painter on allocation failure or unusual geometry.
- Repository reference: the previous compositor discards the X byte of
  client XRGB pixels. An unconditional client memcpy would change that
  behavior. A clipped, unrolled row copy keeps that normalization in one
  pass. Cached backgrounds and frame spans use memcpy; wide solid fills
  can reuse their first painted row.
- [Mutter's upstream opaque-region clipping](https://mail.gnome.org/archives/commits-list/2020-June/msg09229.html):
  only known opaque regions may hide painting below them. The compositor
  can omit background/window spans covered by a later external XRGB client
  well, retaining shadows and rounded corners elsewhere. Rectangle
  subdivision is bounded; excessive fragmentation uses the full clip.
- The integer blend uses two independent 16-bit red/blue lanes. After
  adding the original rounding constant 127, each lane is at most 65152.
  In this range `(v + 1 + (v >> 8)) >> 8` equals `v / 255`, so rounding
  is unchanged. The original theme painter is the pixel oracle.

## Reproducible host checks

```sh
nice -n 19 python3 -B tests/host/desktop/test_compositor_performance.py --benchmark --frames 128
nice -n 19 python3 -B -m unittest discover -s tests/host/desktop -t tests/host -v
```

Run each command separately. Timing does not assert a wall-clock threshold
inside a unit test. The benchmark scene has a pre-rendered Ciuki wallpaper,
four overlapping windows (including an off-screen right edge), Start menu,
taskbar, Tango icons and approved Ciuki identity, and software cursor at
1024x768. Its three theme SHA-256 goldens were obtained from the original
renderer before editing it. Tiled/one-pixel captures and independent frame,
shadow, font and icon comparisons exercise clipping, cache invalidation,
allocation failure, changing underlays, UTF-8, and arbitrary X bytes.

Clock ticks already damage only the clock box (and date/tooltip regions
when required); Start and title hover already damage their own boxes.
These paths and the tray/taskbar layout are unchanged. The benchmark
harness asserts the bounded clock and hover damage directly.

Actual before/after timing, complete test results, qualification limits and
the acceptance status are recorded in `build/codex/f2-45-report.md`.
The final host suite passed 76 tests (five payload/build checks skipped).
Scalar Clang timing improved from 3.359 to 1.164 TSC ticks per pixel for
Platinum (2.89×); Blue improved 2.84× and Classic 98 improved 3.37×.
The 4× host gate is not met; the T23 ≤25 ms gate remains unqualified.
No QEMU, image build, hardware run, diary entry or commit is part of this
host validation.
