# F3-10: T23 DOOM menu investigation

Static and host investigation of `docs/directives/f3-10-doom-t23-menu-freeze.md`.
The quiet T23 observation identifies a symptom, not the instruction or failed
device. Attribution requires the lead's next boot-menu `L` capture. No QEMU or
hardware execution is part of this work.

Research checked before implementation:

- [DPMI virtual interrupts](https://www.delorie.com/djgpp/doc/dpmi/ch4.4.1.html)
  and [hardware interrupts](https://www.delorie.com/djgpp/doc/dpmi/ch4.4.2.html):
  physical IF can remain set while virtual IF blocks guest IRQs. A hooked IRQ
  enters on a locked stack with virtual IF clear. Diagnose both flags, both
  PICs, nesting and the original PC; never force IF on to hide a stall.
  The repository's `dpmi_deliver` uses the protected-mode vector table and
  reflects default handlers to V86. Native and firmware keyboard producers
  both feed the same focused-window KEY transport and virtual 8042.
- [id's DOOM main loop](https://github.com/id-Software/DOOM/blob/master/linuxdoom-1.10/d_main.c)
  and [tic loop](https://github.com/id-Software/DOOM/blob/master/linuxdoom-1.10/d_net.c):
  animation/input depend on tic progress; sound runs in the main loop.
  These released files describe the common game loop, not the proprietary
  DOS DMX implementation. The DOS timer/register sequences and distinction
  between 140 Hz service and 35 Hz game tics are documented by the existing
  F3-06/F3-09 byte replay investigation. PIT port writes are virtual; the
  physical scheduler timer remains 1 kHz. A menu replay must continue after
  startup and inject actual 8042 make/break bytes, rather than BIOS text.
- [Creative hardware guide](https://pdos.csail.mit.edu/6.828/2018/readings/hardware/SoundBlaster.pdf),
  chapters 2 and 3: DMA counters progress during playback, with an interrupt
  at each block boundary; DSP acknowledgement and PIC EOI are separate.
  `dosvm_tick` advances DMA even with guest IF clear or no host audio sink.
  Observe channel address/count, cumulative transfers, DSP state, generated
  IRQ edges and delivered IRQs; a modulo position alone can alias a full ring.
- [Intel SDM Vol. 3A](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-3a-part-1-manual.pdf),
  sections 4.8 and 4.10: clearing a dirty bit requires translation
  invalidation before expecting it to be set again. `video_harvest` calls
  `as_map`, which executes INVLPG for the active CR3. A different address
  space receives a CR3 reload when resumed. Test repeated stores to the
  same page, both contexts, and presenter cadence. Mode 13h/Mode Y uses
  VM-owned RAM and synthetic INT 10h; it never changes the physical VBE mode.

Implementation decisions: add bounded two-second diagnostic snapshots after
the first graphics mode, retaining the interrupted frame before dispatch.
Copy timer/device state with IRQs disabled, restore physical IF before UART
output, and never print from `dosvm_tick`. Keep the F3-09 startup budgets
separate so WAD loading cannot consume the menu samples. Guard runtime VM
evidence at its callers using the selected-and-begun record state. Preserve
the record service's premature-evidence rejection for actual test mistakes.
Guest-port parsing and verdict latches continue to work in quiet boots.

The faster host replay (40,000 instructions per simulated millisecond)
reproduces a post-startup virtual-IF stall. Its missed saved-flags CLI is at
`01DF:00247543`, reached from DOS/4GW's 16-bit return epilogue at
`00FF:000006C9` (`POP DS/ES/FS/GS; POPAD; ADD ESP,6; IRETD`). The prior
forward proof rejects the changed code selector and code/stack default sizes;
its 32-byte root snapshot also cannot contain this return frame. Watcom's
result copier then uses stack stores, LEAVE and RET-with-cleanup before the
save/CLI. The unarmed POPFD cannot restore virtual IF. The replay eventually
spins at `01DF:0025219A`, with pending IRQ0/IRQ1/SB7, no ISR, but advancing DMA.
This reproduces a defect; attribution of the physical T23 remains pending.

[Intel's instruction reference](https://www.intel.com/content/dam/support/us/en/documents/processors/pentium4/sb/25366621.pdf)
(IRET/IRETD, Vol. 2A pp. 3-484 onward) separates operand size from stack size
and checks the return selector's low 16 bits. The implemented fix walks only
a bounded, non-writing extender epilogue (16 instructions, 64 stack bytes),
validates the same-ring, cross-selector IRET image and first RET/caller code addresses,
and sets TF in that image. Up to 512 actual instruction boundaries are then
collected through #DB. The current opcode is read at an actual CPU boundary;
stop before PUSHF/POPF, CLI/STI, software interrupts, SS loads, far/system
transfers. Inspect all legacy prefixes, including REP/LOCK, before classifying
the opcode. Ordinary instructions use the CPU's decoder and fault checks,
not the limited static forward-proof decoder. A fault cancels owned tracking. The flag image is consequently saved with TF clear.
The existing exact-image save/CLI rule can then arm that image, following
the [Windows 95 compatibility method](https://devblogs.microsoft.com/oldnewthing/20160411-00/?p=93281).
No instruction in an IF-clear critical section is stepped; exhaustion does
not enable IF. The original control-flow proof and snapshot remain unchanged.

Both 64 and 128 steps exhausted before the menu's CLI in the recorded replay;
256 reaches it and passes the menu; the longer sound workload requires the
near-return extension and the final 512-step ceiling below. Tracking includes client identity and nesting
depth as well as CS/SS: a nested callback can reuse both selectors. Otherwise
the callback cancels tracking while the parent's saved frame still carries
TF, generating a spurious client #DB on return. IRQ/callback/child contexts
pause the parent budget; returning to that context resumes it. Simultaneous
enabled watchpoints retain their client exception. Existing TF, VM/NT or
privilege transitions, invalid targets and wrapping ADD SP are refused.
Same-selector IRET is refused: before it executes, a physical IRQ cannot
distinguish the epilogue context from the target using CS/SS/depth/client.

Host tests cover the extender epilogue, exact image arming, cap exhaustion,
unsafe/prefixed opcodes, normal near indirect calls/shifts/REP, nested IRQ/callback/child scope, real watchpoints,
and IF-clear behavior. Heartbeats also cover a guest halted with virtual IF
clear: the sleeping worker samples its retained frame every two seconds.

The longer local sound workload also reaches a missed save/CLI at
`01DF:00247221`: tracking can stop at the preceding flags save, or exhaust
256 steps in the sound call path. A later flags restore is itself a known
boundary, but the old forward proof cannot cross the remaining near epilogues.
[Intel Vol. 2B RET](https://www.intel.com/content/dam/support/us/en/documents/processors/pentium4/sb/25366721.pdf),
pp. 4-253 onward, specifies a near return within CS, with operand-sized target
and stack-address-sized cleanup; it does not save TF or change IF. The same
bounded non-writing epilogue check can validate its live return slot and seed
live TF at the already-known current PC. This avoids an arbitrary scan or
backward signature and lets the next save boundary be acquired after a restore.
The observed restore PC `0024766D` computes a register result (MOV/SHL/ADD)
before ADD ESP, three register pops and RET 12. Permit complete register-only
computations and reads that do not assign SP; reject memory writes and unknown
SP assignments. A fresh near-return seed sets live TF immediately at that
known boundary and validates the future caller slot, rather than patching a
deferred flags image in a same-selector return.
Use the same scope/unsafe-instruction guards and a 512-instruction ceiling;
never acquire these boundaries while virtual IF is clear.

Ranked checks, exact record fields and host results are in
`build/codex/f3-10-report.md`.

Owned #DB handling clears a retired STI shadow before its early return;
otherwise the shadow can extend through the tracked epilogue and suppress
virtual IRQ delivery. The new host check covers this ordering.
