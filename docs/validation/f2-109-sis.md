# SiS 300 and 315/330 native 2D port

Implementation research and decisions for directive f2-109. Runtime hardware
qualification remains with the lead; host models cannot qualify physical cards.

Repository comparison: part A has synchronous FILL/COPY/PATTERN and monochrome
cursor hooks, native-only generic DM9 comparisons, guarded CPU fallback,
validated framebuffer leases and versioned driver identity. Part C's new
INVERT/MONO/KEYED/LINE ABI is absent. No public ABI is changed by this port.

Use separate 300 and 315/330 PCI tables; exclude XGI and later 6342. Preserve
VBE modes. Validate exact framebuffer ownership and 16-bit RGB565 or 32-bit
XRGB8888 geometry. Refuse 24-bit, unproved firmware state and unsupported
coordinates before submission. Never enable bus mastering, AGP or host DMA.
Keep source and destination bases equal for automatic-overlap copies.
Activation pixel checks run exclusively through `fbdev_accel_probe`.
Quarantine disables new work but only bounded engine idle and cursor-disable
readback authorize CPU access. A failed proof retains the rejecting guard.

The family census and part C semantics are absent at this branch's base;
their authoritative files were read in the lead checkout without modifying it.
The family-result row is recorded in `docs/design/display-driver-model.md`.

## Implemented boundary

| Driver | PCI vendor 1039, explicit devices | Commands and qualification |
| --- | --- | --- |
| `sis300`, **SiS 300 / 540 / 630** | `0300 5300 6300` | FILL/COPY/SYNC, legacy PATTERN and monochrome cursor. Explicit X/Y copy directions, three consecutive all-engine/queue idle observations and a checked 300 MMIO FIFO. |
| `sis315`, **SiS 315 / 330** | `0310 0315 0325 5315 6325 0330 6330` | Same hooks, automatic overlap with identical zero bitmap bases, depth flags rather than 300 direction bits, four consecutive idle observations, idle before each MMIO operand. |

Both use VBE for modes, RGB565 or XRGB8888, at most 2048 pixels per axis,
8-byte-aligned pitch, and a complete validated visible allocation. Probe is
PCI-only. Start rechecks the exact framebuffer lease and generation, excludes
RAM/kernel aliases and wrapping/overlapping apertures, claims relocated VGA
ports and a UC register window, and reserves a disjoint cursor page. The 315
also reserves exactly 512 KiB of local VRAM for its MMIO queue, using firmware
VRAM metadata. It does not enable PCI bus mastering or submit host/AGP DMA.
These are device transport reservations, not changed system memory limits.

The firmware gates currently refuse panning, CRT2/bridge output, interlace,
doublescan, a depth mismatch, disabled linear/MMIO decode, an existing 300
TurboQueue, and 315 AGP/VRAM queue modes. The driver unlocks extended registers
only inside the exclusive activation callback and restores the prior lock
state after a clean refusal or successful stop. Unknown silicon and `6342`
are refused. Unsupported modes use the software engine through part A.

Activation compares a saved 16x16 block with the production software engine:
fill and contrasting seed, overlapping copies both ways, then a screen-origin
MSB-left pattern. Restore occurs only after idle. A transparent cursor test
checks base, colours, position, enable and final hide through registers.
Diagnostic draws do not set the generic presenter's `native_used` counter.
The monochrome cursor converts the legacy coverage/image planes into a 64x64
MSB-first AND/image store; replacement hides first and leaves it hidden.

All waits have a clock deadline and a 100,000-read frozen-clock cap. With a
presenter pause hook, completion waits have a 20 ms deadline and yield at
1 ms boundaries (also periodically with a frozen clock). Without a pause
hook, including activation and fallback, each poll is capped at 1 ms.
Quarantine blocks submissions immediately, hides the cursor, revokes native
capabilities and retains unsafe mappings/claims. A later idle proof includes
cursor-disable readback before cached CPU readiness becomes true. Stop also
restores queue/module state and verifies readback; its registry wrapper revokes
the cursor/register mappings and releases proven-idle claims before firmware.
An unproved release or stop fails closed. Serial summaries are rate bounded.

The durable files are `C:/system/settings/sis300.cfg` and `sis315.cfg`, with
driver/PCI identity in their contents. Begin requires successful write,
commit and close before issuing one activation authorization. Every nonempty
or unreadable record blocks activation; retained legacy `accel.cfg` is also
preserved and blocks activation. This is a conservative family-level marker,
not the future part B central keyed-marker migration. File I/O occurs outside
the presenter. A failed start retains its marker and same-boot refusal.

Part A lacks new INVERT/MONO/KEYED/LINE/batch/ARGB signatures and numbers.
The exact RGB-mask INVERT primitive is implemented privately and tested,
including preservation of X bits; it is not advertised through an invented
ABI. WRITE is left to software because the chosen Linux imageblit is software.
New part C COPY reserved-bit normalization must be qualified with its adapter;
the present hooks preserve part A's raw native-format COPY behavior.

The H page previously skipped drivers without a configuration sweep. Its
generic dispatcher now runs `fbdev_accel_diagnostic` directly for such drivers,
requiring native FILL/COPY evidence. Existing configuration-sweep behavior is
unchanged. The family advertises no mode provider and no private sweep.
Device Manager and Control Panel obtain the exact display names above from
the existing versioned generic records; there are no family-name UI branches.

## Host evidence

`nice -n 19 env CIUKI_SIS_SANITIZERS=undefined python3 -B tests/host/test_sis_display.py`
passes: 555,745 checks, zero failures; three i686 objects with canonical kernel
flags, 19 unique external symbols checked by `nm`, and successful partial link.
The independent register interpreter does not call software draw helpers;
production `swdib` provides the comparison pixels. Coverage includes both
depths, 49 overlap directions, exact register widths/order, pattern origin,
single/double invert, cursor storage/negative positions/replacement, read-only
nomination and ownership refusals, marker failures, frozen-clock/deadline and
cancellation waits, dead MMIO, partial-copy faults, cursor-disable failure,
quarantine, resource rollback, stop/remapping and generic identity/usage.

The part A display suite passes seven tests, including 1,703 ABI oracle checks
and 87 software byte goldens. DM12 passes two tests. Display modes pass six
tests. Credits pass eight tests. The existing Savage section of
`scripts/test/host_kernel_tests.sh` passes with zero failures, preserving its
existing sanitizer environment. The hardware-page runtime test passes,
including optional-sweep dispatch, missing native evidence and error paths.

The new suite defaults to ASan+UBSan with normal leak detection. Its default
run cannot pass in this sandbox: LeakSanitizer reports a fatal ptrace-scope
restriction. No leak-detection suppression was added. The explicit UBSan
run above is separate evidence; ASan with leak checking remains a lead check.

No QEMU, systemd scope, image build or hardware run was performed. The lead
must qualify actual 300, 315/330 and integrated derivatives, including native
DM9 draw/cursor evidence, firmware gate behavior, stops and mode changes.
Host models establish encoding and policy, not electrical/register timing or
support for an untested physical card. Exact commands and limitations are in
`build/codex/f2-109-report.md`; source provenance is in the driver's `import.json`.
