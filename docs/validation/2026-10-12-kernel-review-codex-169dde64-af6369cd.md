**1. DPMI virtual IF**

- **P1 — `src/kernel/vm/dpmi_dispatch.c:343,475`: misses restoration when the stepped instruction clears TF.** An armed POPFD followed immediately by another POPFD loading TF=0 still produces a single-step exception, because TF was set when the second instruction began. Saved EFLAGS now has TF clear, so `flags_restored()` refuses the trap. Virtual IF remains disabled; the default exception path can terminate the VM. Recognize DR6.BS, including when no watchpoints are installed: `dosvm.c:240` currently supplies zero unless `dr7` is nonzero. The host test manually injects TF and misses this case. [Intel single-step semantics](https://www.intel.com/content/dam/support/us/en/documents/processors/pentium4/sb/253669.pdf).
- **P2 — `dpmi_dispatch.c:318,333`: backward signatures can match immediate data.** With 16-bit PM, EFLAGS=0202h and AX=0202h, execute `MOV BX,589Ch; CLI` (`BB 9C 58 FA`). The immediate is mistaken for `PUSHF; POP AX`, corrupting AX to 0302h. An immediate ending in 9Ch can similarly cause unrelated stack data to be modified.
- **Hardware/TCG risks:** `if_armed` remains VM-wide and persistent, allowing later unrelated TF exceptions to be consumed. Debugger single-stepping is explicitly excluded by the acceptance amendment. This technique restores IF one instruction late; MOV/POP SS can delay #DB further. Injected trap frames do not establish real Pentium III behavior. [Windows 95 technique](https://devblogs.microsoft.com/oldnewthing/20160411-00/?p=93281/).
- **Test:** actual 16/32-bit POPF/IRET execution, nested disabled saves, immediate false signatures, POPF followed by CLI/INT/#PF/POPF clearing TF/MOV SS, simultaneous BS and watchpoint hits, nested-client cleanup. Check IRQ/EOI ordering and physical IF=1, IOPL=0.

**2. VGA burst and 3DAh timing**

- **P1 — `src/kernel/vm/dosvm_vga.c:355,381–384`: partial bus effects survive discarded CPU state.** After the initial aperture fault, execute `REP MOVSB` with DS=ES=9FFFh, SI=DI=0010h, CX=2, DF=1. The first iteration modifies A0000h; the second destination, 9FFFFh, is refused. The burst discards updated registers, then native execution repeats the first iteration. With VGA rotate-count 1 and logical XOR, an initial byte 01h becomes 81h on the abandoned attempt and 41h on replay, rather than 81h. Preflight accesses or commit completed REP elements before stopping.
- **P2 — `dosvm_vga.c:381`: continuation suppresses native invalid-opcode faults.** `vga_x86.c:596` ignores LOCK, and register MOV forms are accepted. An aperture store followed by `F0 89 D8` (`LOCK MOV AX,BX`) executes through the burst instead of raising #UD on Pentium III and TCG. Reject unsupported prefix/form combinations before execution. [Intel fault reference](https://cdrdv2-public.intel.com/868137/325462-089-sdm-vol-1-2abcd-3abcd-4.pdf).
- **Timing risk — `dosvm_vga.c:70`: blanking phase stops following time once entered.** Pause polling mid-blank and resume a second later: the old read sequence resumes. Read floors, fixed horizontal frequency and ignored retrace/blanking registers are documented approximations. Their durations differ with T23 trap cost and TCG scheduling; they do not provide faithful programmed CRTC timing. [CRTC fields](https://www.scs.stanford.edu/10wi-cs140/pintos/specs/freevga/vga/crtcreg.htm).
- **Test:** boundary-crossing REP in both directions; rotating/logical VGA writes; register, latch and VRAM equivalence; invalid LOCK; TF/shadows/IRQ arrival. Measure maximum kernel residence and audio/heartbeat delays. Exercise 449/525-line totals, overflow bits, intermittent polling, timing changes mid-blank and Wolf3D’s five-read loop.

**4. Quiet boot, loader and power**

- **P1 — `src/kernel/core/power.c:235`: shutdown retries bypass failed synchronization.** `storage_sync()` at `fs/mount.c:426` sets `stopped=true` after boot-log shutdown errors, including EBUSY during an active drain. `storage_shutdown()` also sets it before committing. The first power request returns an error; the second skips synchronization and reboots/powers off with dirty data or open files. Preserve and return the terminal shutdown error.
- **P1 — `power.c:56–63,87–100`: `_S5` parsing lacks package and namespace validation.** PkgLength is never decoded. The byte scan can accept a pattern inside a Buffer, a nested-scope `_S5`, or elements outside the declared package. Wrong sleep types can request another state. `power_test.c:93` actually expects success for a zero-length package. Require a validated root object and package extent. [AML grammar](https://uefi.org/specs/ACPI/6.6/20_AML_Specification.html).
- **P2 — `power.c:209–216`: failed ACPI ownership transfer still reaches PM writes.** SCI_EN remaining clear after timeout—or a missing handshake—does not prevent sleep programming. PM1b SCI_EN is not checked. QEMU ignores SCI_EN in its shutdown handler, so QEMU success masks this hardware failure. [ACPI ownership](https://uefi.org/specs/ACPI/6.6/05_ACPI_Software_Programming_Model.html), [QEMU implementation](https://raw.githubusercontent.com/qemu/qemu/master/hw/acpi/core.c).
- **Hardware risks:** omission of `_PTS`/`_GTS` is explicit in the contract, but T23 preparation requirements remain unqualified. Its actual tables have not been inspected. Validate GAS width/offset, PM1 control length and extended-field handling. [Sleep sequence](https://uefi.org/specs/ACPI/6.6/16_Waking_and_Sleeping.html).
- **Boot risks:** no demonstrated bit-11/A20 collision. `probes.c:1052` tests desktop PID existence, not a painted frame, and cannot wake during IF=0 or an indefinitely non-yielding kernel stall. Its one-shot watchdog retains a task/stack forever at `:1056`.

Power tests must cover unauthorized calls, busy files, flush failure then retry, concurrent requests, malformed AML, SCI timeout and T23 cold shutdown followed by a clean FAT mount.
