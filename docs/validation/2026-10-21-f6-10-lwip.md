The build verifies the archive, source list, patch hashes and cached extraction;

The three recorded patches prevent TCP PCB eviction on exhaustion, drain DNS
cache/pending state on server changes, and replace the loopback callback's
incompatible function-pointer cast. Upstream sources are changed only through
these patches. BSD notices for the compiled sources and 70 transitive upstream
headers are retained in `docs/licenses/lwip-2.2.1-NOTICES.txt`; the image recipe
installs the notices and import record. No image was built to test that recipe.

The WIP already contained the principal port and native API. Review completed
the ABI/POSIX/SDK documentation, fixed queued-operation fd checks, name snapshots,
option output bounds, socket/control ownership details and DNS cancellation
reuse. Link notifications now use their reserved messages; address loss wakes
affected connected sockets. Copied physical output carries the NIC generation,
retains backpressure and discards quarantined/stale work. Common poll covers
files (including `/dev` as a directory), channels, input and sockets; channel
queue changes publish its wake predicate. The native ARP helpers remain only
for the selected f6-01 driver probe, which owns/stops its device; normal ingress
belongs to lwIP.

The native extension is calls 78–89, with 90 returning ENOSYS. Existing syscall
numbers and public time types are preserved. Eight worker request payloads and
eight user-copy payloads bound scratch to 512 KiB. Scalar/control syscalls use
small stack metadata; sockname uses a coherent cached address snapshot, without
depending on an available I/O request. Close/shutdown capacity is reserved in
each socket. Normal, core and control workers plus the existing NIC worker use
four permanent kernel tasks; the port's seven task slots plus that NIC task
enforce the eight-task ceiling.

## Object and memory measurements

The target check compiles 51 translation units with the actual i686 production
flags, links the network objects relocatably, emits a map and compiler record
layouts, and runs the production FPU/SIMD instruction audit. This is not a full
kernel link or a runtime 128 MiB admission measurement.

| Object | i686 bytes | Native host bytes |
| --- | ---: | ---: |
| pbuf header | 16 | 24 |
| pbuf pool entry, before pool-base alignment slack | 1,552 | 1,560 |
| TCP PCB | 160 | 216 |
| UDP PCB | 32 | 48 |
| netconn | 44 | 80 |
| CiukiOS socket object | 136 | 168 |
| Mailbox, including its 64 pointer slots | 384 | 592 |
| Worker request, including 32 KiB payload | 32,868 | 32,904 |

Target static accounting: heap array 1,048,603 bytes (within 1,028 KiB), fixed
pool backing arrays 218,116 bytes (within 508 KiB), and 95,476 bytes of
port/socket/request metadata including one page for globals (within 256 KiB). The copied user/worker payloads
are exactly 524,288 bytes. Physical framework state is 52,624 bytes and copied
outgoing queues are 48,880 bytes; these fit the 256 KiB shared-frame allowance.

The complete network-object link contains 148,920 bytes text/rodata, eight bytes
data and 1,987,980 bytes BSS. Rounding each section to pages, adding the full
288 KiB task allowance, 256 KiB NIC DMA allowance, 256 KiB deferred DOS-bridge
allowance, one extra allocator page for each of 64 process fd-generation arrays
and one ledger page gives **3,231,744 bytes**, below **4,194,304 bytes**.
The target test enforces this bound and the heap/pool/scratch buckets.

The `net` owner receives the page-aligned static network BSS and NIC DMA pages.
Admission promises the total 1,024 pages after moving the resident BSS, so the
ledger's resident-credit calculation cannot cancel the remaining reservation.
Stacks remain visible under the common stack owner; the network ceiling above
includes their full allowance as well. Existing high-water emergency reserves
are checked before activation. Installed/E820/resident/free measurements on the
canonical 128 MiB image and hardware still belong to the lead.

Entropy follows the approved non-cryptographic SplitMix64 decision: mix the
kernel clock/RTC seed, PIT phase, TSC samples at stack initialization and adapter
attachment, and adapter MAC bytes. Only the isolated host fixture injects a
fixed seed. There is no cryptographic or TLS-security claim.

## Verification outcome and limits

All focused runtime harnesses reached their behavioral PASS assertions without
ASan/UBSan diagnostics. Every sanitized process then exited unsuccessfully when
LeakSanitizer attempted its ptrace-based final scan in this sandbox. Leak
detection was never disabled. These results are **not green sanitizer runs**;
the lead must repeat them in an environment allowing the final scan.

The real-stack harness covers sys_arch contention/FIFO/null/full/timeout/wrap,
TCP/UDP native calls, input/output bounds, accepted-fd validation, poll over
mixed objects, cancellation and pin cleanup, close/reuse generations, connect
refusal/SO_ERROR, Ethernet retransmission/FIN, copied/chained pbuf ownership,
zero datagrams/truncation/broadcast, DHCP malformed options/ACD/NAK/T1/T2/expiry/
link recovery, DNS malformed replies/cache/generation/four pending requests/
ten-second caller deadline, all fixed pools/heap exhausted, non-evicting TCP
allocation and 10,000 create/close cycles returning heap/netconn/UDP PCB use to
baseline. Remaining TCP TIME_WAIT and internal DHCP/timer/core-message entries
are bounded and reported separately from public objects.

The separate production descriptor/process harness covers close, dup, shared
NONBLOCK, per-fd CLOEXEC, file-call dispatch/errors and spawn inheritance. The
bridge harness covers queue copy/full/FIFO/budget/backpressure/stale generations/
quarantine. The SDK wrapper harness uses the actual wrapper sources with a
native-host trap/address shim; public layout compilation uses i686 separately.
Direct i386 Linux execution was blocked by sandbox SIGSYS, so it is not claimed.

The ABI oracle reached **1,640** checks; the existing eight-NIC register/DMA/ARP
harness reached **1,729,989** checks; the common ledger harness reached **22,947**
checks before the same final leak-scan failure. The target compile/instruction
audit, offline import/notice and license-payload inventory check, SDK layout
compilation, generated API reference check and
`nice -n 19 make CAP= apps` completed successfully. The requested report at
`build/codex/f6-10-report.md` contains exact commands, exit results and the
row-by-row acceptance status. T1–T3, canonical-image SHA-256/128 MiB runtime
accounting and physical T23 confirmation remain unrun by Codex.
