The complete network-object link contains 148,920 bytes text/rodata, eight bytes

and one ledger page gives **3,231,744 bytes**, below **4,194,304 bytes**.
The target test enforces this bound and the heap/pool/scratch buckets.

The `net` owner receives the page-aligned static network BSS and NIC DMA pages.
Admission promises the total 1,024 pages after moving the resident BSS, so the
ledger's resident-credit calculation cannot cancel the remaining reservation.
Stacks remain visible under the common stack owner; the network ceiling above
includes their full allowance as well. Existing high-water emergency reserves
are checked before activation. Installed/E820/resident/free measurements on the
canonical 128 MiB image and hardware still belong to the lead.

Entropy follows the approved non-cryptographic SplitMix64 decision: mix the
kernel clock/RTC seed, PIT phase, TSC samples at stack initialization and adapter
attachment, and adapter MAC bytes. Only the isolated host fixture injects a
fixed seed. There is no cryptographic or TLS-security claim.

This section supersedes the earlier implementation measurements for the amended
source state. It applies the eleven findings in the lead's Amendment 1 above

The following primary-source checks guided the amendment:

- [Pinned api_msg.c](https://raw.githubusercontent.com/lwip-tcpip/lwip/STABLE-2_2_1_RELEASE/src/api/api_msg.c)
  emits an ERROR notification on successful full shutdown as well as on an
  actual transport error. The port now retains EOF/HUP without creating an errno
  for ERR_OK. [Pinned api_lib.c](https://raw.githubusercontent.com/lwip-tcpip/lwip/STABLE-2_2_1_RELEASE/src/api/api_lib.c)
  initializes an additional close poll; the lead's configuration solution uses
  500 to select two 500 ms polls while keeping internal completion waits intact.
- [Pinned netif.c](https://raw.githubusercontent.com/lwip-tcpip/lwip/STABLE-2_2_1_RELEASE/src/core/netif.c)
  invokes transport address-change handling before the status callback. Retained
  endpoint/route addresses now identify already-aborted TCP sockets and listeners;
  affected receives, sends and accepts return ENETDOWN after DHCP expiry/NAK.
- [Pinned dhcp.c](https://raw.githubusercontent.com/lwip-tcpip/lwip/STABLE-2_2_1_RELEASE/src/core/ipv4/dhcp.c)
  can fail DHCP object/PCB allocation, and ACK handling updates only provided DNS
  slots. Startup failure is now separate from applied carrier, visible through
  net_stack_dhcp_error(), with retries paced at one monotonic second. Recorded
  patch 0004 clears omitted DNS slots through the existing DNS generation/cache
  invalidation path, including same-address renewals. Four recorded patches now
  exist; upstream cache files were not edited directly.
- [Pinned TCP](https://raw.githubusercontent.com/lwip-tcpip/lwip/STABLE-2_2_1_RELEASE/src/core/tcp.c)
  and [UDP](https://raw.githubusercontent.com/lwip-tcpip/lwip/STABLE-2_2_1_RELEASE/src/core/udp.c)
  consume RAND while initializing ephemeral-port starts. Physical adapter
  discovery now precedes stack initialization; the primary MAC is mixed before
  tcpip_init. Safe-mode loopback stack behavior is preserved, and failed stack
  admission stops previously attached devices.

Native calls retain a socket operation reference and fd generation at initial
validation, before user copies/pins. Poll similarly captures object identities
before pinning outputs. Cancellation/deadline state travels with queued work;
the worker checks it immediately before consuming/mutating sequential calls,
including after preparatory internal getaddr waits. Cancelled request storage
survives until completion drains; lwIP's internal semaphore waits are preserved.
Connect completion is independent of clearable SO_ERROR.

The copied driver handoff is now `src/kernel/net/lwip_handoff.c` and retains its
lwIP ingress consumer. The reserved `bridge.c` path is free for f6-11's additive,
type-filtered DOS tap. The NIC worker yields after bounded TX service before
its first RX poll, preserving the sixteen-frame dispatch limit with two NICs.

### Close-limit exception requiring a lead decision

The persistent FIN-allocation exhaustion fixture holds all 256 TCP segment
entries unavailable. The public socket/netconn is reclaimed in under one second,
but its raw TCP PCB remains TF_CLOSEPEND beyond **1,050 ms**. This is a separate
upstream path: tcp_close_shutdown_fin() converts FIN ERR_MEM to ERR_OK, so the
sequential close poll timeout is never entered. Changing the configured poll
count cannot bound this raw state. The fixture aborts the retained raw PCB only
in its own cleanup; no production cleanup workaround was added.

Finding 8 therefore remains open for a lead decision on whether the one-second
transport requirement includes that raw PCB, and, if so, on bounded port/core
cleanup glue or another explicitly reviewed change. The lead specifically chose
a configuration/poll fix rather than an upstream close patch; this delivery
records the demonstrated limit instead of silently changing that decision.
