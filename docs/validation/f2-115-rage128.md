# Rage 128 native 2D port

The implementation uses Haiku **r1beta5**, commit
`a1f00118db8b858feb73f64ac4dc3d038b82bf9b`:

- [`rage128_draw.cpp`](https://github.com/haiku/haiku/blob/r1beta5/src/add-ons/accelerants/ati/rage128_draw.cpp): FIFO setup, FILL, directional COPY and INVERT packets.
- [`rage128_init.cpp`](https://github.com/haiku/haiku/blob/r1beta5/src/add-ons/accelerants/ati/rage128_init.cpp): FIFO-empty, GUI-idle and pixel-cache-flush ordering.
- [`rage128_cursor.cpp`](https://github.com/haiku/haiku/blob/r1beta5/src/add-ons/accelerants/ati/rage128_cursor.cpp): 64 by 64 AND/XOR storage, cursor locking and negative-coordinate offsets.
- [`rage128.h`](https://github.com/haiku/haiku/blob/r1beta5/src/add-ons/accelerants/ati/rage128.h) and [`rage128_mode.cpp`](https://github.com/haiku/haiku/blob/r1beta5/src/add-ons/accelerants/ati/rage128_mode.cpp): register definitions and linear CRTC format/pitch.
- Kernel [`ati/driver.cpp`](https://github.com/haiku/haiku/blob/r1beta5/src/add-ons/kernel/drivers/graphics/ati/driver.cpp): explicit Rage 128 PCI whitelist (including Pro and Mobility; no Mach64/Radeon match).

Additional register reference: X.Org `xf86-video-r128`, commit
[`d05022a1c398787d3f21d023a8251cb128ba9f9f`, `src/r128_reg.h`](https://github.com/freedesktop-unofficial-mirror/xorg__driver__xf86-video-r128/blob/d05022a1c398787d3f21d023a8251cb128ba9f9f/src/r128_reg.h).
That header identifies ATI manuals RRG-G04100-C revision 0.04 and SDK-G04000
revision 0.01. Those manuals were not retrieved independently; the audited
upstream register definitions are the register reference used here.

[QEMU v9.2.0 `hw/display/ati.c`](https://github.com/qemu/qemu/blob/v9.2.0/hw/display/ati.c)
and [`ati_2d.c`](https://github.com/qemu/qemu/blob/v9.2.0/hw/display/ati_2d.c)
are research references only. They implement a limited synchronous FILL/COPY
model and add CRTC offset to default offset on Pro. Requiring zero active
CRTC offset avoids divergent addressing. Emulator support is not physical
qualification. No QEMU code is imported.

The owner's read-only Windows 98 Resource Kit, `wrkc28_8.htm`, Graphics
Subsystem, and `wrkc26_5.htm`, Setting Graphics Compatibility Options, were
read. Their DIB/minidriver split and independently disabled cursor/blits
support the existing generic software fallback. No book text is imported.

## Decisions before implementation

The branch contains f2-101 part A. Its synchronous hooks and the existing
generic native-only saved-block comparison remain authoritative. Keep VBE
mode setting. Only linear RGB565/RGB555/XRGB8888 with a representable padded
pitch can activate. Probe and eligibility are read-only; resource claims and
engine initialization happen after the durable attempt marker. Verify the
CRTC origin, dimensions, format and pitch before issuing engine commands.

Replace the donor's infinite reset retries with a monotonic deadline,
iteration limit and presenter pause callbacks. Do not import the PLL/reset,
bus-master, DMA, AGP, mode or overlay paths. Timeout disables submissions;
CPU access requires FIFO empty, GUI idle, pixel cache flushed and cursor
hidden. An unproved completion retains the rejecting guard and leases.
COPY faults are never replayed by the driver.

The donor has no PATTERN/WRITE/MONO/KEYED/SCALED/LINE path selected by this
contract. Keep those hooks absent. INVERT is private and host tested pending
f2-101d's generic hook/capability allocation; do not invent an ABI bit.
The legacy cursor uses an opaque mask, so convert AND=`~mask`,
XOR=`image & mask`, in MSB-left bytes. Reserve and map a separate VRAM page
outside scanout; without it, leave the cursor capability absent. SET hides
first; clipped negative positions use the donor's even offsets. Odd negative
origins are refused before state changes, since the donor would round them
and violate exact positioning. Unrepresentable positions likewise fail cleanly.

Each imported fragment retains its source notice. The import manifest is
`src/kernel/drivers/video/rage128/import.json`; donor downloads remain under
ignored `build/research/f2-115/`.

## Evidence

`nice -n 19 python3 -B tests/host/test_rage128.py` passes under UBSan:
eight engine groups and five registry/lifecycle groups. The independent MMIO
model checks FILL/COPY packets, all four overlap quadrants, padded pitch,
RGB555/565/XRGB8888 pixels against `swdib`, private INVERT, cursor plane bytes
and palette conversion, hide-before-replace, signed-position refusal, FIFO,
GUI/cache timeouts, frozen clock, sliced waits, stale generations and guards.
Lifecycle fixtures cover all 47 donor PCI entries, ambiguous ownership,
safe mode/`accel=0`, unsupported layouts, resource and mapping failures,
durable marker I/O failures, retained markers, quarantine, safe stop/restart,
generic identity/counters and dispatch to the native-only H-page comparison.

The complete part A display-model suite passes (seven tests), including
the 1,703-check i686 ABI oracle and freestanding translation units. DM12
name enforcement, credits, device inventory, mode/checkpoint fixtures and
the existing Savage register/presenter regression pass. No public SDK or
ABI header changes were needed. The existing per-driver attempt marker is
not migrated; `r128.cfg` conservatively blocks any retained Rage 128 attempt
and includes the driver and PCI IDs in its record.

The optional ASan invocation with default leak detection cannot finish in
this sandbox: LeakSanitizer reports its ptrace restriction. Leak detection
was not disabled for this suite. Complete commands, exit results and logs
are recorded in `build/codex/f2-115-report.md`.

Runtime and physical evidence remain with the lead. No image build, QEMU
or systemd scope ran. In particular, the strict native CRTC/zero-origin
proof may refuse firmware modes that expose only the emulated VBE state;
the lead must establish which `ati-vga` VBE modes also configure the native
CRTC. Do not relax that proof merely to bind an emulator. Physical negative
cursor positioning and cache behavior still require qualification.
