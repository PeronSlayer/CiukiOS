# f7: Quake III Arena demo on the Win32 subsystem (2026-10-25)

Host evidence for the bring-up of the Quake III Arena demo (id Software,
point release 1.11) and the steps the lead runs in QEMU. Design and
decisions: `docs/design/win32-personality-contract.md`, section "f7: Quake
III Arena demo". No QEMU, image or hardware run is part of this record.

### Demo playback (`demo demo001`, timedemo)

`test_timedemo_demo001_headless` (`CIUKI_Q3A_TIMEDEMO=3`, then `=0`;
chain of 21:08-21:25 CET), `+set logfile 2 +set r_mode N +set nextdemo
quit +set timedemo 1 +demo demo001`, the same image and DLLs as the menu
test. The level loads (`Loading vm file vm/cgame.qvm.`, `...loaded 5823
faces, 189 meshes, 49 trisurfs, 37 flares`, `CL_InitCGame: 13.48 seconds`,
`232 msec to draw all images`), the demo plays to its end (the frag
messages of the eight bots in the log) and the program quits with code 0
through `nextdemo`. Every frame reached the lease (1379 frames: 33 of the
loading screens, 1346 of the demo), none refused.

| Mode | Console result | Lease frames | Wall time of the run |

| `r_mode 3`, 640x480x32 | `1346 frames, 732.6 seconds: 1.8 fps` | 1379 in 746.5 s | 751 s |
| `r_mode 0`, 320x240x32 | `1346 frames, 256.7 seconds: 5.2 fps` | 1379 in 261.1 s | 265 s |

The arena frames of a hand run of the same demo (`q3-frames/f00512.ppm`,

the HUD (health, armour, ammo, the score 100/12/8 of the leader) and the
player name tags: the 3D path renders correctly; it is slow.

SIGPROF samples of the timedemo (the 60 hottest 64-byte blocks, 92% of
the samples at 640x480):

| Function | 640x480 (747,811 samples) | 320x240 (261,738 samples) |
| --- | --- | --- |
| `sw_triangle` (fill loop) | 34.5% | 24.4% |
| `k32_urem` (`__aullrem`: `coordinate()`, GL_REPEAT `int64 % 65536` per texel fetch) | 30.3% | 22.4% |
| `k32_udiv` (`__aulldiv`) + `__aulldiv` | 8.1% + 1.4% | 5.8% + 1.0% |
| `sample_level` | 4.0% | 2.7% |
| `gdi_sdiv` / `gdi_srem` (`__alldiv`/`__allrem`) | 2.4% | 1.8% |
| `glPostProcess`, `glopVertex`, `sw_s3tc`, `sw_fragment`, `convert` | about 1.8% | about 3.4% |
| adapter (`wait_word` idle, the sampler) | 9.3% | 27.0% |

So two thirds of the arena's CPU time is the per-pixel fill: the span loop
and, above all, the 64-bit remainder for texture coordinate wrapping; with
its texture sizes powers of two, `coordinate()` can mask instead of
dividing, and the per-channel `int64 / area` in `interpolate()` can be
replaced by incremental steps along the span. These are for the f7-glperf
worker (`sdk/libgl/software/renderer.c`); this change does not touch it.
At 320x240 the fill drops to a third and the per-frame constant (vertex
processing, the 1,665 GL calls, the lease copy) shows as the rest.

### GL call profile per frame

Method (`h1_game.c`, test-only): after `opengl32.dll`'s
`DLL_PROCESS_ATTACH` the adapter redirects the export table of the mapped
image to 8-byte counting thunks written into the image's `.reloc` section
(dead after the load; `GetProcAddress` accepts only RVAs inside a section),
and routes `wglGetProcAddress` through a wrapper so the extension entry
points Quake III fetches are counted too. Only the program's calls are
counted (opengl32's internal calls do not cross the export table). 391
names hooked.

## QEMU checklist for the lead

On an image built from this change (the installer fix of the other worker
merged, so that VISE installs into `C:\Q3Ademo`):

1. Desktop -> folder "Quake III Arena Demo" -> run `Q3ADemo.exe`, accept the
   licence, keep `C:\Q3Ademo`, finish. Serial: no `missing-export`.
2. Start -> Programs -> Quake 3 Arena Demo -> the Quake III item. Expect
   the display to switch to 640x480 (full screen, the desktop hidden), the
   id logo cinematic, then the main menu. Serial: `[win32] load ...
   quake3.exe`, no `missing-export` and no `stub` record for quake3's
   modules, the `opengl32.dll` info record `software render=640x480
   display=...`, the display grant of the lease.
3. Mouse and keyboard: the menu cursor follows the mouse (DirectInput),
   the menu sounds play (DirectSound), Esc/Enter work.
4. DEMOS -> demo001: the arena demo plays with sound.
5. Console (Shift+Esc or the key left of 1): `timedemo 1`, then
   `demo demo001`; at the end the console prints
   `N frames, S seconds: R fps`; record R (the host software renderer's
   figures are in "Demo playback" above; QEMU TCG runs the same code).
   Without typing: an item or a Run line
   `C:\Q3Ademo\quake3.exe +set logfile 2 +set nextdemo quit +set timedemo 1 +demo demo001`
   plays the demo as fast as it renders, writes the line to
   `C:\Q3Ademo\demoq3\qconsole.log` and quits (`nextdemo` is executed by
   `CL_NextDemo` when a demo completes). Also `r_fullscreen 0;
   vid_restart` (a 640x480 captioned window on the desktop at the desktop
   mode) and `r_fullscreen 1; vid_restart` (back to full screen).
   Modes: `r_mode 0; vid_restart` (320x240, scaled by the presenter),
   `r_mode 4` (800x600) and `r_mode 6` (1024x768) switch the lease mode;
   `r_mode 5` (960x720) is refused (`...calling CDS: failed`) and the game
   falls back through `EnumDisplaySettings` as its own code does.
6. Alt+Tab to the desktop and back: the lease is revoked and regranted, the
   game continues.
7. EXIT from the menu: the desktop returns at its own mode; serial
   `[win32] exit` for quake3.exe with code 0.
8. Files -> `C:\Q3Ademo` -> double-click `quake3.exe`: it starts the same
   way (it runs in its own folder).
9. Copy `C:\Q3Ademo\demoq3\qconsole.log` when `+set logfile 2` was given
   (Start-menu item properties, or the console `logfile 2` before step 4).
