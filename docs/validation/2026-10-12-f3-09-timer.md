# F3-09: T23 DOOM timer investigation

This is a static/host investigation of directive
`docs/directives/f3-09-doom-t23-timer-hang.md`. Hardware attribution remains
pending the lead's serial capture; no QEMU or hardware execution is claimed.

## Sources and implementation decisions

- [Intel SDM Vol. 3B, 253669](https://www.intel.com/content/dam/support/us/en/documents/processors/pentium4/sb/253669.pdf),
  sections 18.2.3 and 18.3.1.4: DR6 status persists until software clears it;
  breakpoint status can include disabled slots. BS identifies single stepping
  even when the retired instruction cleared TF. `arch_debug_take()` already
  reads and clears DR6 before `dosvm_trap()` enables interrupts. Filter B0–B3
  by this VM's allocated, enabled watchpoints before classifying a guest #DB;
  retain raw DR6 for diagnostics. Preserve simultaneous enabled watchpoint
  events and BS. Do not infer BS from saved TF.
  Also drain status when a DPMI worker is scheduled in: native user #DB
  handling does not consume DR6, so a prior task's BS must not accompany
  this client's later breakpoint. The VM trap captures its own status before
  interrupts or scheduling can occur.
- [Intel SDM Vol. 3A](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-3a-part-1-manual.pdf),
  sections 6.8.3, 6.9, 6.12.1.2, 20.2.5 and 20.2.7: MOV/POP SS suppress
  debugging and interrupt delivery through the next instruction; trap-class
  #DB precedes a concurrent maskable IRQ. Interrupt entry clears live TF;
  the saved frame retains the interrupted flags. Kernel IRET restores the
  guest at IOPL 0 with physical IF set. A physical IRQ must not erase a
  previously proven PUSHF/POP boundary before the trapped CLI. Preserve that
  proof only when conservative forward decoding reaches the IRQ address.
  The sound replay also exposes a backward call/return path: seed 248205h
  calls 2483B0h, then returns to the caller before DMX's save/CLI at 247F15h.
  A linear walk cannot prove that save. Extend the proof with bounded direct
  control-flow decoding and checked stack effects. Root returns use a small
  stack snapshot captured with the original boundary; reject unknown stack
  assignments, indirect transfers and writes that could alter that snapshot
  or a decoded call's return slot. Absolute DS stores outside those ranges
  preserve the proof; segment changes revoke the known DS base. Keep the
  exact flags-image check and never match backward
  byte signatures. Budget: 32 paths, 64 visited states, 4096 decoded bytes,
  four direct call levels; exhaustion leaves the image untouched.
- [DPMI 0.9 specification](https://www.phatcode.net/res/262/files/dpmi09.html),
  sections 2.1, 2.3, 2.4.1, 3.1.2, 10.2 and 10.6: virtual devices are valid;
  0201h installs the real-mode vector and 0205h the protected-mode vector.
  Hooked hardware IRQs use the protected-mode handler even from V86, on the
  host's locked stack; default handlers reflect to real mode. Keep this
  routing and the host's separate physical timer/scheduler unchanged.
- [Windows 95 interrupt-flag compatibility](https://devblogs.microsoft.com/oldnewthing/20160411-00/?p=93281):
  the existing saved-image TF remedy remains necessary because ring-3 POPF
  cannot restore IF. This is the Windows 95 DOS-session pattern, not NTVDM.
- [QEMU 11.1.1 breakpoint helper](https://github.com/qemu/qemu/blob/v11.1.1/target/i386/tcg/system/bpt_helper.c):
  `check_hw_breakpoints` replaces the low breakpoint-status bits when it
  updates DR6; `helper_set_dr` preserves required fixed bits on writes.
  A TCG pass is not proof that the Pentium III cannot supply additional
  disabled-slot status. Do not assume TCG automatically clears BS.

The timer path is `timer_irq -> sched_tick -> dosvm_tick -> dosvm_pit_advance
-> dosvm_irq_raise`, then `dosvm_trap -> dpmi_deliver`. Virtual port writes
reach `dosvm_pit_port`, never the physical PIT. PIC mask, in-service priority,
virtual IF and STI shadows all gate delivery. No memory limits change.

Verbose (`CBI_F_VERBOSE`, boot menu L) diagnostics must use the existing
record framing without needing a selected test probe. They must print with
physical interrupts enabled, never inside the host timer IRQ. Quiet boot
adds no diagnostics. Per-VM budgets bound vector, PIT, IRQ0, #DB, flags and
pending-timer records; immediate fault records include the original PC.
Clock/gate samples begin after the first complete channel-0 reload, so WAD
loading cannot consume them. That event also reserves a second PM #DB/flags
sample window and an IRQ0 epoch. At most four epoch changes are permitted:
32 vector rows, 24 PIT rows, 50 IRQ0 rows, 64 PM and eight V86 #DB rows,
128 flags rows, ten clock/gate pairs, one immediate fault row (327 total).
Record output uses physical IF=1; the timer IRQ itself never prints.

Host verification and the ranked hardware checks are recorded in
`build/codex/f3-09-report.md`.
