# F3-23: nested protected-mode IRQ stacks

Research checked before implementation on 2026-10-15:

The [DPMI stack specification](https://www.delorie.com/djgpp/doc/dpmi/ch4.3.html)
requires nested protected-mode interrupts to continue on the current locked
stack. If a handler selects a private locked stack, that stack remains current
until it switches back. The [hardware interrupt rules](https://www.delorie.com/djgpp/doc/dpmi/ch4.4.2.html)
require entry with virtual IF and TF clear. Neither rule permits overwriting a
suspended handler's stack or acknowledging its PIC service on return.

The [Intel 8259A datasheet](https://openwatcom.org/ftp/devel/docs/8259A.pdf),
pages 15–16, distinguishes acknowledgement from EOI. In normal priority order,
IRQ 0 can preempt IRQ 7. With ISR=81h a non-specific EOI clears IRQ 0 first;
another clears IRQ 7. A specific EOI names its service bit. Auto-EOI applies
only when programmed in ICW4. The physical record has auto-EOI and special
mask mode disabled. Decision: retain these PIC rules and repair PM frame
construction, without clearing ISR on a timeout or handler return.

`dpmi_enter_pm_handler` always selected DPMI_HOST_SS. `dpmi_push_record` only
lowered the host stack cursor when the interrupted SS was DPMI_HOST_SS.
Consequently, after a handler pushed registers and selected a private stack,
a nested IRQ reused host stack bytes containing those suspended registers.
The same unconditional selection existed for a nested processor exception.
Decision: while the current client's locked PM entry is active, construct the
nested frame below its current SS:ESP. Validate the complete frame range before
writing it. First entries and entries from real mode retain the host stack.

The pinned DOOM executable contains the private stack switch at 24659Ah
(`LSS ESP,[EDX+8]`), its return at 2465A0h (`LSS ESP,[ESP]`), and the common
IRQ wrapper at 2461F0h. The dispatcher decrements its shared stack counter
at 246528h and may omit early and late EOI when the counter is exhausted.
These bytes were read from the vendored archive, using the LE mapping
documented in the F3-15 validation. They establish that the affected stack
transition is used by this guest; the physical logs do not contain a complete
instruction or saved-stack trace establishing the exact corrupt register.

The extender's vector 08h stub at 00FF:0020 dispatches to the 32-bit IRQ
wrapper at 01DF:2461F0, which saves registers and calls the common dispatcher.
For IRQ 7 the dispatcher first reads ISR to distinguish a spurious request.
It can send early non-specific EOI at 246565h, enables virtual interrupts at
24656Dh, calls its callback on the private stack, restores the previous
stack, and tests whether to send late EOI before returning through the
wrapper's IRETD. A callback result of one instead chains through the saved
previous handler. The stack counter and mode bits determine which EOI path
runs. The log does not trace those branches or their OUT values; it cannot
identify which saved register or branch caused the missing EOIs.

The a738204a disk log has ISR=81h, IRR=83h, IMR=78h and depth zero at lines
2629–2630. At line 2644 the guest is still running with virtual IF enabled.
IRQ 7 can remain in service while the higher-priority timer is acknowledged.
Further timer, keyboard and sound requests then remain latched. Returning
from a PM handler does not send EOI, so these bits correctly block delivery
after the handlers unwind. The serial capture is fragmented and supplies no
additional complete EOI sequence.

The [Creative programming guide](https://pdos.csail.mit.edu/6.828/2018/readings/hardware/SoundBlaster.pdf),
chapter 2, distinguishes DSP acknowledgement from PIC EOI. Decision: measure
an unserviced DSP line from its first asserted edge, rather than the latest
auto-init block boundary. Later blocks do not restart this age. After more
than 500 ms, the timer path saves one ISR/IRR/IMR snapshot without formatting
or output. The worker prints one `irq_wait` row ahead of the ordinary audio
queue, outside suspended guest IRQ chains. A queued snapshot survives DSP
acknowledgement before printing. The row describes unserviced IRQ state,
including a handler that was entered but did not acknowledge the DSP; it
does not claim that a PIC acceptance is the DSP acknowledgement. Evidence
is limited to sixteen snapshots per VM, with one pending snapshot slot.

`ret_step` records a monitor-owned debug retirement and decrements its bounded
instruction budget. `ret_limit` clears TF when that budget ends. Neither
boundary waits for a handler return or changes ISR, masks or virtual IF.
Their latest recorded PCs can survive after the handler chain has returned;
they are not evidence that the return tracker itself stopped the PIC.

Host replay results and the remaining QEMU and T23 checks are recorded in
`build/codex/f3-23-report.md`. Physical attribution remains subject to those
checks; a synthetic stack replay cannot establish the machine's exact timing.

On base revision `309007c68ffc8c37731867344f1edbd72e08c60b`, replacing only
the PM dispatch translation unit with its original version makes both the
16-bit and 32-bit negative controls reach ISR=81h, IRR=83h, IMR=78h and then
fail the saved-stack-byte comparison. With the fix, all four client/stack
width combinations retain those bytes, execute the two guest EOIs, unwind
both frames and deliver the pending timer. The replay's matching PIC snapshot
is taken at depth two, before EOI; it does not recreate the physical machine's
depth-zero stall. PIC register controls independently verify non-specific,
specific and programmed auto-EOI behavior.

`nice -n 19 env ASAN_OPTIONS=detect_leaks=0 bash scripts/test/host_kernel_tests.sh`
exited zero, including 8,086,467 DOS VM checks and the new stack, rejection,
exception and sound-watchdog cases. AddressSanitizer and UndefinedBehaviorSanitizer
were enabled. The optional whole-guest batch skipped because this worktree
has no built DOSBOOT.IMG. Both changed translation units compile with the
production i686/Pentium Pro flags and 4096-byte frame limit. `git diff --check`
passed. QEMU and T23 acceptance remain for the lead on a newly hashed image.
