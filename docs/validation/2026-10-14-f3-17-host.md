# f3-17: DOS idle detection and the foreground budget

Directive: `docs/directives/f3-17-dos-idle-detection-win9x.md`.
Host checks only; QEMU and T23 acceptance belong to the lead.

## Research and decision (before implementation, 2026-10-14)

- Microsoft's [VMM DDK, scheduler and VPICD services](https://www.pcjs.org/documents/books/mspl13/win/w3ddkvxd/),
  chapters 24/25/30: an idle VM releases its slice, foreground and background
  priorities differ, and device events wake VMs. `Call_When_Idle` describes
  system-wide idle callbacks, not the detection of one idle VM. Critical
  sections and interrupt simulation constrain suspension. This accessible
  manual is the Windows 3 enhanced-mode predecessor, not a Win95 DDK copy.
- Microsoft [KB Q130971, Windows 95 APPS.INF](https://jeffpar.github.io/kbarchive/kb/130/Q130971/)
  documents the DETECTIDLE PIF setting. It does not specify the keyboard poll
  threshold; the threshold below is CiukiOS policy, not a recovered Win9x value.
- [RBIL INT 2F/1680](https://www.delorie.com/djgpp/doc/rbinter/id/47/45.html)
  specifies AL=00 when supported and release of the remaining slice. It does
  not promise an indefinite block. [RBIL INT 28](https://www.delorie.com/djgpp/doc/rbinter/id/38/41.html)
  specifies the DOS character-input idle callout, preserved registers, and
  TSR reentrancy restrictions. Preserve the guest IVT chain for both calls.
- Upstream [DOSBox Staging DOS](https://github.com/dosbox-staging/dosbox-staging/blob/main/src/dos/dos.cpp)
  and [shell keyboard waits](https://github.com/dosbox-staging/dosbox-staging/blob/main/src/shell/shell_cmds.cpp)
  use `CALLBACK_Idle` during waits. This is a comparison with an emulator,
  not evidence about Windows NT NTVDM or the exact MS-DOS 7 COMMAND binary.
  The exact MS-DOS 7 implementation and a Win95 DDK service manual were not
  independently recovered; no claim of byte-identical behavior is made.
- [Intel SDM](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html)
  HLT/STI semantics and the [Intel 8254](https://www.scs.stanford.edu/22wi-cs212/pintos/specs/8254.pdf)
  require retaining virtual IF, interrupt shadows, PIC arbitration and guest
  timer progress while the worker sleeps.

Repository comparison: `rq_pop` reserves eight ticks in ten for the focused
DOS worker without observing idle state. `dosvm_wait` polls at one millisecond;
HLT retries at ten milliseconds. CiukiDOS already returns success for 1680h
but its input functions and the separate COMMAND.COM editor do not emit idle
callouts. T23 image fb3147dc measured vm_permille=811, guest_permille=794
while spinning; this proves allocation/CPU use, not the eventual improvement.

Decision: use event-driven kwait sleeps for cooperative INT 28/2F1680,
empty BIOS waits, repeated empty INT 16/01/11 returns (eight within one host
tick), and HLT with virtual IF enabled. Keep IVT reflection and IRQ delivery
unchanged. Default PM16/PM32 interrupts bypass the real-mode INT callback;
observe their committed DPMI reflection records in `dosvm_trap` and track
keyboard returns in the appropriate mode, without editing DPMI dispatch.
Sleeps end on VM input/device/presentation events or a deadline
no later than the next guest PIT period (rounded to host milliseconds,
55 ms fallback with no armed timer). Keyboard polling is observed at the
caller's return boundary, including hooked real-mode handlers. Busy guests
without idle signals retain the existing foreground/background quanta.
Suppress focus reservation while sleeping and for ten milliseconds after an
idle wait; use a one-tick quantum during that interval. Do not change memory
limits, DPMI dispatch, the V86 core or the VGA models.

`vm_perf_share` retains its CPU shares and adds interval idle block counts,
an idle reason bit mask (1=2f1680, 2=28h, 4=16h, 8=hlt), and busy_permille
(scheduled guest plus monitor CPU time / wall time). Per-reason interval
counts are emitted separately to respect the 240-byte record limit.

## Validation

The C host suite, DOS personality T1 checks, real-DOS libx86emu replay,
idle/focus sanitizer vectors and i686 compilation pass. The broad Python
run completed 540 tests with two missing-prerequisite errors (the pinned Lua
archive and the canonical files-payload.elf), plus 24 skips. Detailed commands
and results are in `build/codex/f3-17-report.md`.
No host replay proves vm_permille < 30 or
desktop frame p95: the lead must measure both on the integrated image,
alongside unchanged DOOM share, input, timers, audio IRQs and window cleanup.
