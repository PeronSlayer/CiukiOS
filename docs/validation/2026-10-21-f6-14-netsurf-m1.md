# NetSurf M1 local frontend — implementation and host validation

Directive: [f6-14](../directives/f6-14-netsurf-m1-frontend-file.md), with the
[f6-13 lead decisions](../directives/f6-13-netsurf-port-plan.md#lead-decisions-on-the-plan-2026-10-21-docsdesignnetsurf-port-planmd-merged-on-main).
This record covers host evidence only. It does not close the F6 browser gate.

## Sources checked before implementation

- [NetSurf releases](https://www.netsurf-browser.org/downloads/source/) and
  [developer documentation](https://www.netsurf-browser.org/documentation/develop):
  use the pinned 3.11 release, not current upstream HEAD. All implementation
  decisions were checked against that archive's actual headers and Makefiles.
- [Framebuffer build documentation](https://github.com/netsurf-browser/netsurf/blob/master/docs/building-Framebuffer.md)
  and [LibNSFB](https://www.netsurf-browser.org/projects/libnsfb/): retain the
  framebuffer plotters and fbtk content region; add a separate Ciuki v3 surface.
  The older web documentation is not the build recipe for this release.
- [Parserutils upstream](https://github.com/netsurf-browser/libparserutils):
  `WITHOUT_ICONV_FILTER` selects internal codecs. NetSurf's separate iconv calls
  still require an adapter. The port uses actual decoder/encoder calls through
  UCS4 big-endian buffers, strict UTF-8 validation and the four approved external
  encodings. US-ASCII remains an internal parser encoding.
- [newlib OS interface](https://sourceware.org/newlib/libc.html#Syscalls):
  availability of a header is not evidence of an implemented service. The SDK's
  unqualified `sys/select.h` conflicts with its public types. A private fd-set
  representation preserves NetSurf callback signatures without adding select or
  socket services. Missing access/realpath are handled by a checked file adapter,
  not successful stubs. The F2 filesystem has no symlinks.
- [zlib 1.3.1 manual](https://zlib.net/manual.html) and
  [libpng release information](https://www.libpng.org/pub/png/libpng.html):
  pinned target zlib is mandatory for Messages. The message generator links
  separately built pinned host zlib. Pinned host libpng is also built, with
  identical generation/compilation CPPFLAGS; the replacement Tango/Ciuki asset
  pipeline uses the existing deterministic project PNG decoders instead of
  upstream convert_image. PNG/JPEG content stays disabled. No download occurs.
- [Perl interpreter environment](https://perldoc.perl.org/perlrun#PERL_PERTURB_KEYS):
  the release's entity generator uses unsorted hash keys. The first independent
  comparison isolated different output to Hubbub's generated entity table.
  Fix both `PERL_HASH_SEED=0` and `PERL_PERTURB_KEYS=0` for build generators;
  `PYTHONHASHSEED=0` is fixed as well. This setting applies to host generators,
  not browser runtime hash security policy.

The original source viewer links in f6-13 were inaccessible to the web tool;
the verified local release and official project mirrors supplied the API details.
No HTTP/TLS behavior is implemented or claimed by this directive.

## Build and patch decisions

`sdk/netsurf/build.py` checks archive byte counts and SHA-256 even on cache hits.
It retains pristine regular files under `build/external/`; archive links are not
extracted. Independent build directories copy those sources and apply the ordered
patch set with zero fuzz. Tool/input hashes and installed payload hashes govern
the cache. Cross package discovery sees only the target staging prefix.

`0001-offline-sdk.patch` has these purposes:

1. Skip compiler probes when the SDK recipe supplies the toolchain; fix feature
   choices and host/target separation. Retain supplied Unicode/PSL data. The
   release omits Hubbub's gperf output and this host has no gperf: a deterministic
   ASCII-folded binary lookup is generated from the pinned element table instead.
2. Select the Ciuki surface and SDK font adapter; retain constructors using the
   existing whole-archive link, verified in the final ELF. Generate framebuffer
   chrome/scroll assets from Tango and the exact approved Ciuki portrait.
3. Replace NetSurf's iconv section with the parserutils adapter. Use C locale,
   numeric time conversion, checked native paths, fopen-based resource readability,
   the private fd-set and numeric mkdir mode for the F2 subset. Exclude curl headers
   when curl is disabled; no public networking ABI changes result.
4. Bind the upstream GUI tables to libdeskui chrome, shared clipboard, picker,
   download refusal, hotlist and bounded profile. Preserve distinct Unicode TEXT
   events so codepoints cannot be mistaken for libnsfb navigation/mouse keycodes.
5. Make scheduler turns process one callback. Stream local files in 16 KiB turns,
   with an 8 MiB file/data admission bound and explicit errors. Local directory
   listings are refused; use the existing desktop picker. Disable file-backed mmap.
6. Bound decoded bitmap allocations to 2 MiB aggregate and 1024 pixels per axis,
   clear new bitmap memory, and reject oversized layout trees/runs. Add monotonic
   long-layout checks and propagate failure instead of presenting partial layout.
7. Propagate hotlist/Choices write and close errors before atomic profile replacement.
   Clean up fbtk/resource vectors at exit. No new kernel panic paths are added.

The image adapter stages `/Programs/netsurf`, `/system/netsurf`, its `Resources/`
copy and notices under `/system/licenses`. A new profile lives at
`/Documents/NetSurf` (`C:\Documents\NetSurf`): Choices, Bookmarks.html (500 entries),
History.html (2000 entries). History import and writes are bounded, UTF-8 URLs
are escaped, and temp + fsync + rename preserves the old destination on a write
or rename failure. This does not claim crash durability beyond F2's semantics.
No desktop launcher is added before M4.
History also has a 128 KiB raw-URL budget and 1 MiB serialized-file budget;
oldest entries are evicted when either bound or the 2000-entry limit is reached.
Bookmarks are admitted at 512 KiB/500 entries, Choices at 64 KiB.

## Focused host commands

Run one command at a time; never use discovery:

```sh
nice -n 19 python3 -B -m unittest tests.host.netsurf.test_surface
nice -n 19 python3 -B -m unittest tests.host.netsurf.test_local.ProfileTests
nice -n 19 python3 -B -m unittest tests.host.netsurf.test_local.LocalTests
nice -n 19 make CAP= apps
nice -n 19 python3 -B -m unittest tests.host.netsurf.test_local.ReproducibilityTests
```

Rendering uses the real framebuffer frontend with libnsfb RAM, the SDK font
adapter, the pinned parsing/layout/image libraries, and three authored local
fixtures. Goldens were visually inspected before recording SHA-256 values in
`tests/host/netsurf/goldens.json`. The supported subset shown is CSS2 floats,
margins/borders, UTF-8 styled text, decoded GIF/BMP, tables and form controls.
Additional tests cover data/about pages and a file larger than one body slice.
The text about-page battery covers about, welcome, credits, licence, config,
Choices, testament, blank and imagecache. A 20,000-byte text run tests explicit
layout rejection. Layout errors are deferred until the reformat callback
unwinds, cancelled on destruction, and guarded from redraw/input meanwhile;
reporting them synchronously invalidated a content reference during READY.

The surface fixture exercises v3 byte encoding, colour order, clipped/unioned
damage, map ownership, resize acknowledgement/failure/OOM/stale serials,
generation rejection, text/modifier/repeat/pointer mapping and descriptor cleanup.
The font fixture checks all four encodings, invalid/truncated UTF-8, decoder
fragmentation, widths, hit testing, splits, scaling, missing glyphs and clipping.
The profile fixture checks retention, restart, escaping, corruption and failed
write/rename preservation.

On this sandbox, the four ASan/UBSan C fixtures reach their success assertions,
then LeakSanitizer fails because its ptrace-based teardown check is prohibited.
`detect_leaks=1` remains enabled. Those complete sanitizer commands are **blocked**,
not green. The lead must rerun them in a compatible host environment.

## Qualification limits

The session report in `build/codex/f6-14-report.md` contains exact command results,
output hashes and build evidence. No QEMU, systemd scope, image build, commit or
diary change is part of this worktree task.

Native v3 window/chrome behavior, disk error UX, real per-process memory/stack
high-water and the 128 MiB T23 admission remain lead qualification. Host fixture
layout times below 1 ms do not prove the 100 ms bound on the T23. The admission
gate rejects more than 8192 boxes, depth 64, 8192-byte text runs, 64 table columns,
or 128 KiB total layout text; it checks the 75 ms deadline at layout stages,
blocks and lines. Min/max computation and individual upstream operations are
still synchronous. The lead must review those limits and measure worst-case
latency before claiming a universal 100 ms responsiveness guarantee. The 32 MiB
resident target is provisional, not a new kernel-enforced allocation ceiling.
