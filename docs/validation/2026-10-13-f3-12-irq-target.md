# F3-12: DOOM IRQ0 target and restore boundary

Research checked before implementation on 2026-10-13:

- [DPMI 0.9, function 0205h](https://www.delorie.com/djgpp/doc/dpmi/api/310205.html)
  installs a protected-mode interrupt vector; 0203h installs an exception
  handler. The T23 log's `0087:6d70` record is **0203h**, not 0205h.
  Decision: log each successful 0205h for vectors 08h–0Fh independently of
  the startup trace budget, including the descriptor and its ownership.
- [DPMI hardware interrupts](https://www.delorie.com/djgpp/doc/dpmi/ch4.4.2.html)
  enter a locked stack with virtual IF and TF clear.
  [Virtual interrupts](https://www.delorie.com/djgpp/doc/dpmi/ch4.4.1.html)
  distinguish physical IF from virtual IF; POPF at CPL3/IOPL0 cannot set IF.
  Retain the existing checked saved-image compatibility mechanism and
  transactional delivery; a rejected target must leave the PIC pending.
- [Intel 8259A datasheet](https://pdos.csail.mit.edu/6.828/2010/readings/hardware/8259A.pdf)
  specifies that ISR persists until guest EOI (except programmed AEOI).
  No timeout, automatic EOI or changed mask is an acceptable fix.

The existing `pic_stall` record stores the latest delivery target and the
latest monitor boundary independently. `boundary=if_restore` does not prove
that the recorded IRQ was delivered after that boundary. The T23 capture
also reports `depth=0`: no DPMI hardware-handler record remains suspended.
Repeated startup `vm_irq0` records already target `00ff:0020`.

The shipped DOOM shareware host replay resolves selector 00FFh to an allocated
client code descriptor (LDT index 31, owner 1, base 0011BCB0h, limit 5E3Fh,
access FAh, 16-bit code). Offset 20h calls the extender dispatcher at 550h
and supplies vector 08h as inline data. Ciuki's default reflection selector
is 1FFFh, not 00FFh. The replay's client IRQ0 path reaches `01df:2461f0`,
then `2464e8` (CLI), and the EOI at `246565` before its callback.
These descriptor values are replay evidence, not a reconstruction of an
unlogged descriptor from the physical machine.

## Reproduced mechanism and implementation decision

`core/output.c` deliberately polls the serial transmitter with physical IF
enabled. A roughly 200-byte 38400-baud, 8N1 line costs about 52 ms, comparable
to the initial PIT period (55 ms). The old guest harness assigned diagnostics
zero time. Advancing the real virtual PIT during those writes reproduces the
T23's distinctive four-handler CLI sequence, then ISR0=IRR0=1 at depth zero
**before** the saved-flags restore. No guest instructions need modification.

The first three DMX handler entries decrement the private stack counter
at 002A23E8h from 4 to 3/2/1, send early EOI at 00246565h and enable virtual
interrupts. Logging their CLI at 002464E8h creates another pending timer
edge. The fourth entry decrements the counter to zero and skips early EOI.
On return it increments the counter to one; the late-EOI test at 002465EDh
tests that incremented value for zero and the handler's mode bit 1, so it
also skips late EOI. All four handlers IRET; ISR0 remains set. Later POPFD
compatibility correctly restores VIF at 00247FACh, but ISR0 blocks delivery.
This is consistent with a real PIC; timing out ISR would conceal the error.

Decision: retain the guest and PIC behavior. Buffer routine VM diagnostic
snapshots while any hardware-interrupt transition is suspended, including
its nested real-mode calls and callbacks. Drain them after the outermost
handler returns, before the next delivery. Use bounded per-VM storage and
report overflow explicitly. Keep the stalled-handler diagnostic available;
do not turn logging into a reason to mask IRQs, stop the PIT, delay guest
EOI or recover an ISR automatically. Replay with UART time as well as the
existing pending-edge injection; physical acceptance still belongs to the
lead's T23 retest.

## Host evidence

Base revision: `0aa23f421b10bdd054b33ddb1b5a2c192af025b3`.
The read-only shipped `CIUKIGAM.IMG` used for these replays is 7,262,208 bytes,
SHA-256 `491c78c1e299b443278f90d41413bd0c782794232d6935758a46f0db719bb7c3`.
Its manifest identifies the 709,905-byte DOOM.EXE as SHA-256
`b8020523561a5ad9706e009a52d61c578f37faafd85ac471962308406292ce27`.
Guest disk writes use the host runner's temporary COW file.

The final differential replay uses the same host harness, descriptor
diagnostics and guest bytes on both sides. Only `dosvm.c` is replaced by
the base revision for the failing side. `GUEST_UART_BAUD=38400` charges ten
wire bits per diagnostic byte (including framing and CRLF) to the existing
virtual PIT/device clock; physical IF is asserted enabled. The retained
`GUEST_IRQ0_RESTORE=0x247fac` hook also advances the PIT at the armed #DB,
before virtual-IF restoration.

With `GUEST_VERBOSE=1 GUEST_UART_BAUD=38400 GUEST_SLICE=40000
GUEST_IRQ0_RESTORE=0x247fac GUEST_BUDGET=500000000 GUEST_MENU_SOUND=1`,
the command is `menu:\RUNREC.COM \DOOM DOOM.EXE -config CIUKI.CFG`,
expected program `RUNREC`.

Before the fix, startup fails with zero unexpected traps. At the restore
hook ISR0 is **already set**. The subsequent production diagnostic is:

```text
event=pic_stall vm=1 gen=1 pic=0 irq=0 ms=1001 cs=01df eip=002483e2 isr=01 irr=01 imr=f8 vec=08 to=00ff:00000020 boundary=if_restore at=01df:00247fac pm=1 depth=0 ae=0 sm=0
```

This matches the T23's PC, target, boundary and PIC/depth signature. It
does not reproduce its absolute delivery count or wall-clock schedule.
A temporary trace of the failing handler chain measured counter values
4/3/2/1 at entry, early EOI only at depths 1/2/3, and IRQ returns through
depths 3/2/1/0 with ISR0=IRR0=1 throughout. That trace also reproduces the
T23's alternating `2482d9`/`2465b2` records 6–13; those PCs are the timer
callback and handler exit, not evidence of changing the PM vector.

After the fix, ISR0 is clear at the same forced restore edge and the
sound-enabled replay passes:

- Video startup: 145,856,846 instructions; 293 PM timer interrupts.
- Menu open, Down, close: all three image comparisons pass, eight IRQ1s
  and eight key bytes; 125 IRQ0s, 29 flips, 27,536 DMA units, 97 SB edges.
- Further 2,400 ms: 307 IRQ0s, 77 flips, 56,629 DMA units, 217 SB edges.
- Overall: 281,320,002 instructions, 3,286,194 traps, zero unexpected
  traps; no `pic_stall` or queue overflow. The `-nosound` replay also passes.

UART-enabled timer assertions account for PIC edge coalescing during
serial output: deliveries must lie between runnable-time and wall-time
bounds at 140 Hz (eight-tick phase tolerance). The original narrow bounds
are unchanged when UART timing is disabled. Image, keyboard and sound
progress assertions remain required.
