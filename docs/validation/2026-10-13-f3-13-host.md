# f3-13: DOS launch visibility and presenter cost

Scope: `docs/directives/f3-13-dosbox-loading-and-speed.md`. Host checks only;
the lead owns QEMU and T23 qualification. No changes to VM memory limits.

Sources checked before implementation (2026-10-13):

- [Intel SDM, volumes 2 and 3](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html):
  page dirty bits describe CPU stores; clearing them requires invalidating the
  translation before subsequent stores. Harvest with interrupts disabled on
  this single-CPU kernel, retain writable mappings for presentation, and close
  them before operations that need latch semantics or mutate the plane model.
- [FreeVGA display memory](https://www.scs.stanford.edu/15wi-cs140/pintos/specs/freevga/vga/vgamem.htm)
  and [DOSBox-X chained VGA implementation](https://github.com/joncampbell123/dosbox-x/blob/dosbox-x-v2025.05.03/src/hardware/vga_memory.cpp):
  retain this repository's physical plane offsets and chain-4 eligibility;
  conversion must preserve CRTC addressing, pan, splits, DAC mask and blanking.
  Share row setup between the reference decoder and the fast indexed decoder.
- [id Software DOOM `doomdef.h`](https://github.com/id-Software/DOOM/blob/master/linuxdoom-1.10/doomdef.h)
  defines 35 simulation tics per second. This is a target, not evidence of
  displayed frames. Report changed presentations and CRTC completion writes
  separately; timedemo and host throughput do not prove a T23 frame rate.
- [id Software Wolf3D `ID_VL_A.ASM`](https://github.com/id-Software/wolf3d/blob/master/WOLFSRC/ID_VL_A.ASM)
  and [`ID_SD.C`](https://github.com/id-Software/wolf3d/blob/master/WOLFSRC/ID_SD.C):
  planar writes and start-address/retrace polling remain valid. Do not force
  planar games into chain-4 or alter their PIT/IRQ timing for speed.
- [DOS EXEC interface (RBIL release 61 mirror)](https://ftp.osfree.org/doku/en%3Adocs%3Ados%3Aapi%3Aint21%3A4b):
  INT 21h/4B00h executes a child. An owner-armed launch can observe that
  boundary without replacing DOS execution or changing the child's registers.

Additional primary-source cross-check completed on 2026-10-14:
[Microsoft MS-DOS 4.0 `EXEC.ASM`](https://github.com/microsoft/MS-DOS/blob/main/v4.0/src/DOS/EXEC.ASM)
documents load/execute function 0 and error returns, and routes failures to
the DOS error-return service. This supports observing the completed EXEC IRET
and carry flag. Direct retrieval of the RBIL mirror and pinned DOSBox-X page
was unavailable; the initial indexed RBIL reference and the existing f3-07
physical-plane contract were cross-checked against the repository and host
goldens. No plane representation was changed.

Repository findings: f3-07 already provides a direct chain-4 window, but the
window presenter closes it each frame. The presenter limits all output to
33 ms, scans damage for both scaled destination rows, and expands DAC colours
per destination pixel. Normal-boot detailed diagnostics are already gated by
`CBI_F_VERBOSE`; retain that gate. Measurements and final host results are in
`build/codex/f3-13-report.md`.

Implementation decisions:

- Use the existing libdeskui theme and catalogue Tango icon for command loading.
  Type `CLS` through the guest shell before the directory/program lines so a
  text program cannot expose the boot screen. Boot TTY bytes remain in a bounded
  per-VM 2048-byte log; STATUS exposes the last console context on startup error.
  Collection emits the retained boot log as hexadecimal `vm_boot_log` records
  in verbose boot. Nothing prints while recording those bytes.
  No physical video, guest command patch or alternative mascot is introduced.
- Retain chain-4 PTEs while presenting, bulk-harvest physical plane spans,
  convert four indexed dots per CRTC address, and expand colours with a cached
  256-entry XRGB lookup. Dirty source rows are grouped into 8-line bands; the
  native client sends only the resulting contiguous destination band runs.
- A CRTC completion write can present immediately. Chain-4 without completion
  writes samples pending stores at programmed refresh. No generic VGA register
  can prove that an arbitrary game finished a complete linear frame; the host
  poll is a fallback, and hardware frame-rate evidence remains required.
- Measurements use calibrated serialized TSC readings only in verbose boot.
  A fixed ring retains sixteen complete per-second intervals and dumps them
  on VM collection. Sampling performs no UART I/O. Existing detailed startup
  traces still contribute to monitor time; their measured polled-output time
  is reported separately. The native surface presentation is timed separately
  from the VM worker. Direct pages are dirty-page observations (4096-byte upper
  bounds), not an exact count of native store instructions. Converted bytes
  count source palette indices; `rows * 2560` is the surface transfer volume.
  Guest time is the active interval outside `dosvm_trap`, including common
  entry/return overhead; it is not a retired-instruction counter. Model/window
  transitions also harvest dirty pages when coherence requires it. A clean
  unchanged frame skips row dependency scans at the native client's poll rate.
