# F4-13 DOS VM audio on hardware

Research checked before implementation, 2026-10-13. Hardware and QEMU
qualification remain the lead's responsibility.

## Findings and implementation decision

The supplied T23 transcript for image `e86305de` contains native backend
failures before game playback: lines 112–113 (`published=160 retired=152`,
cursor 31, count 0) and 196–199 (`published=9 retired=1`, cursor 8,
count 448, diagnostic tone returns -5). Initialization success and an audible
startup sound therefore do not prove that the backend remained ready.
`audio_fail` clears `audio.ready`; a subsequently created VM cannot attach
its F4 consumer and discards PCM/events. There were no records distinguishing
that case from failed guest discovery.

The exact failed register comparison is not recoverable from this transcript:
PIV and status were not recorded. Do not claim a hardware root cause beyond
the observed backend failure until the new image is qualified.

- [Intel ICH3 datasheet, sections 13.2.2–13.2.6](https://www.intel.com.br/content/dam/doc/datasheet/82801ca-io-controller-hub-3-datasheet.pdf):
  CIV identifies the current descriptor, PICB the samples still to fetch,
  and PIV the prefetched descriptor. DCH/CELV identify a real drained halt.
- [Linux v6.12 intel8x0, snd_intel8x0_pcm_pointer](https://github.com/torvalds/linux/blob/v6.12/sound/pci/intel8x0.c#L931):
  retries zero PICB, checks CIV around the count read, and explicitly handles
  the count reloading before the base index updates. CiukiOS instead accepted
  a zero running count and failed on the subsequent apparent regression.
  Retry those transitional observations without committing fetched/retired
  counters, bounded to two milliseconds; retain genuine halt, invalid cursor,
  impossible progress and persistent-regression failures.
- [QEMU v9.2 AC97 model](https://github.com/qemu/qemu/blob/v9.2.0/hw/audio/ac97.c):
  CIV/PIV advance together in the model. A passing QEMU run alone cannot
  exercise a physical descriptor handoff. Keep separate host register replays.
- [TI PC16550D datasheet (vendor document mirrored by Mouser), FIFO polled operation and LSR bit 5](https://www.mouser.com/datasheet/2/405/pc16550d-443503.pdf):
  THRE means the transmit FIFO is empty; a detected 16550 FIFO admits up to
  16 bytes at once. During native playback queue complete serial records in
  fixed 8 KiB storage and let the existing millisecond timer send at most one
  FIFO burst without waiting. A non-FIFO UART sends one byte per turn.
  Keep synchronous early boot and panic output. Overflow drops a complete
  record and emits an explicit serial drop notice; never allocate, wait for
  UART space, or format a record in the timer hook.
- [Creative Sound Blaster hardware guide, chapters 2–4 and 6](https://pdos.csail.mit.edu/6.828/2018/readings/hardware/SoundBlaster.pdf):
  reset/AAh, E1h version, 40h time constant, 14h single cycle, 48h/1Ch
  auto-init, Cxh/Bxh playback and DMA acknowledgements match the existing
  virtual DSP 4.05. Preserve A220/IRQ7/DMA1,5 and virtual IRQ semantics.
- [Wolf3D ID_SD.C](https://github.com/id-Software/wolf3d/blob/master/WOLFSRC/ID_SD.C):
  AdLib timer detection precedes SB detection and BLASTER parsing;
  SDL_StartSB programs D1h and time constant 114 (about 7042 Hz),
  SDL_SBPlaySeg uses DMA mode 49h and DSP 14h, and the ISR reads 22Eh.
  [WL_MAIN.C ReadConfig](https://github.com/id-Software/wolf3d/blob/master/WOLFSRC/WL_MAIN.C#L83)
  chooses AdLib effects/music and SB digitized effects when no CONFIG exists
  and detection succeeds. The pinned shareware package installs no CONFIG.WL1.
- [DOOM M_LoadDefaults](https://github.com/id-Software/DOOM/blob/master/linuxdoom-1.10/m_misc.c):
  the generated CIUKI.CFG selects music/effects device 3, port 544, IRQ7,
  DMA1 and volume 8. The desktop command supplies `-config CIUKI.CFG` and
  does not disable sound. DMX was excluded from id's source release;
  DOOM-style DSP replays are protocol replays, not execution of DMX itself.

The VM source already converts guest PCM to its 48 kHz timeline, synthesizes
OPL2/3 with the integer DBOPL port, and converts that timeline to a 44.1 kHz
physical backend with persistent rational phase. Keep those paths and verify
both output rates. New diagnostics must snapshot in IRQ sections and emit
only in the VM worker outside guest hardware-interrupt chains. Never print
from the virtual DMA/DSP timer or synthesis/refill code. Native playback
diagnostic printing must not stall the refill worker during active playback.
