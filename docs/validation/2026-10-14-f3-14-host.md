# f3-14: DOS monitor costs and focused CPU budget

Directive: `docs/directives/f3-14-dos-speed-t23.md`. Host checks only;
the lead owns QEMU and T23 measurements. No VM memory limits change.

Sources checked before implementation (2026-10-14):

- [Intel SDM](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html),
  volumes 2/3: RDTSC is not serializing on P6; retain the existing CPUID/TSC
  clock and gate it on verbose boot. A cleared page dirty bit needs TLB
  invalidation. STI and SS loads inhibit interrupts through their successor;
  software shadows must survive until that instruction completes. REP I/O is
  restartable, with index/count advanced only for completed elements.
- [Intel 8259A datasheet](https://www.pcjs.org/documents/datasheets/intel/INTEL_8259A_PIC.pdf):
  arbitration observes IRR, IMR, ISR and rotation; EOI releases service,
  never manufactures a new timer edge. Fast paths must preserve cascade,
  special mask, poll, spurious IRQ and automatic EOI semantics.
- [Intel 8254 datasheet](https://www.scs.stanford.edu/22wi-cs212/pintos/specs/8254.pdf):
  periodic reloads and mode-3 half-cycle changes remain clock based. Avoid
  quotient/remainder work only when the next period boundary is not crossed.
- [FreeVGA sequencer](https://www.scs.stanford.edu/22wi-cs212/pintos/specs/freevga/vga/seqreg.htm)
  and [graphics controller](https://www.scs.stanford.edu/22wi-cs212/pintos/specs/freevga/vga/graphreg.htm):
  preserve chain-4 addressing, map masks, read-map selection and latch
  semantics. Batch checked output instructions in order; never grant access
  to physical ports or force a planar game into a linear mode.

Repository/evidence findings before implementation:

- `vm_perf_v86 cause=0..10` means INT, IRET, PUSHF, POPF, CLI, STI, IN,
  OUT, INS, OUTS, HLT. These are real-mode instruction counts, not an
  exhaustive exit classification. Protected-mode I/O is absent from them.
- The supplied n=55 excerpt lacks its CPU/interval rows. n=56 in the actual
  T23 log is 1012 ms: 18 flips/presentations, 23019 GP, 1280 PF, 53 timer
  and 39 other exits; guest 73692 us, monitor 301843 us, presenter 158226 us.
  Guest/worker CPU is 19.62%; worker/wall is 37.11%; guest/wall is 7.28%.
  Monitor time dominates measured worker CPU (80.38%). No per-cause time
  exists: a specific handler's dominance cannot be established from counts.
- The same sample harvests 13715 times and reports 18002 dirty pages. The
  graphics heartbeat says chain=0/direct=1/linear=0: this is planar VGA,
  not steady-state mode 13h. Mapping invariants must remain intact.
- The focused worker quantum is capped at 8 ms, below the normal 10 ms.
  A quantum alone does not reserve 80% with multiple runnable peers.

Implementation decisions:

- Add a bounded verbose-only table of complete trap costs, including time
  before device classification, and suspend accounting across task switches.
  Separate real-mode PUSHF/POPF/CLI/STI and both real/protected HLT costs.
  Report elapsed time, presented/harvested/flip rates, worker/wall and
  guest/wall shares. Keep all sample output deferred until collection.
- Batch bounded VGA outputs only with checked instruction boundaries and
  memory, no guest TF/watchpoints or software shadow, and no pending enabled
  IRQ or scheduler request. Preserve scalar fault fallback and REP progress.
- Fast-path virtual PIT, PIC and keyboard routing; preserve registered port
  overrides and the full register models. Avoid unnecessary periodic timer
  division and full PIC diagnostic-state copies during arbitration.
- Keep direct chain-4 mappings through display-only/redundant register writes;
  close them before actual memory-semantic changes or model consumers.
- Reserve 8 of each 10 scheduler ticks for a runnable focused window worker,
  while device priority and starvation boosts retain precedence. Native work
  gets bounded service opportunities; blocking workers release their budget.
  Hardware device/kernel load can still prevent 80%: measure the new shares.
- Keep real-mode shadows without TF while no deliverable IRQ exists. Once an
  IRQ is pending, step only the outstanding shadow; retain the MOV-SS/TCG
  successor rule. PM flags restoration and return-boundary tracking remain
  correctness mechanisms, independent of diagnostics.

Host results and remaining hardware gates: `build/codex/f3-14-report.md`.

Host validation completed:

- Full kernel host suites, five VGA goldens and the independent VGA vectors
  pass with ASan/UBSan. Workload host controls pass (8 tests), DOS VM Python
  controls pass (7), and VGA x86 controls pass (4), run sequentially.
- The deterministic V86/PM32 DAC plus sequencer replay reduces GP exits
  774 -> 13 with exact bytes and no VGA PF. REP/DF/width, pending IRQ,
  TF/watchpoint/IF guards, partial protected-page faults and direct stores
  are checked. The production scheduler gives a focused VM 800/1000 ticks
  with five normal peers and with five interactive peers; each peer gets 40.
- An actual DOOM startup replay on libx86emu passes against pristine HEAD
  and the changed sources. Total exits fall 338552 -> 338538, idle RM DB
  14 -> 0; GP remains 230721. This executable's output sequences retain
  scalar execution. Routing/arbitration time savings need T23 measurement.
  The host runner uses model VGA writes and an instruction clock; neither
  its PF count nor its simulated time qualifies hardware mapping or FPS.
- Standard guest probes and the libx86emu TCG-behaviour model pass, with no
  unexpected CPU events. No QEMU process or image build was run. Changed
  units and their shared-header consumers compile for i686 and pass the
  integer/FPU audit.

The 8/10 scheduler reservation preserves device precedence and cannot
guarantee 80% measured worker CPU under arbitrary device load or long
nonpreemptible native kernel work. The new `vm_permille` reports that gap.
DOOM 35 FPS, Wolf3D 70 FPS, CPU share and the integrated QEMU gate remain
lead-owned hardware/integration acceptance, pending fresh image evidence.
