# F3-15: protected-mode virtual IF recovery

Research checked before implementation on 2026-10-14:

- [Intel SDM](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html),
  Vol. 2 POPF/IRET and Vol. 3 protected-mode virtual interrupts: CPL 3,
  IOPL 0 silently prevents POPF/IRET changing physical IF. PVI helps CLI/STI
  only. Keep the portable trap path; optional PVI is deferred.
- [DPMI virtual interrupts](https://www.delorie.com/djgpp/doc/dpmi/ch4.4.1.html)
  and functions [0900h](https://www.delorie.com/djgpp/doc/dpmi/api/310900.html),
  [0901h](https://www.delorie.com/djgpp/doc/dpmi/api/310901.html),
  [0902h](https://www.delorie.com/djgpp/doc/dpmi/api/310902.html): compliant
  clients restore virtual IF explicitly. Legacy extender games need a
  compatibility policy beyond this specification.
- [Microsoft's Windows 95 implementation account](https://devblogs.microsoft.com/oldnewthing/20160411-00/?p=93281):
  set TF in a verified saved flags image at CLI, then restore virtual IF at
  the subsequent debug trap. This is a Win9x DOS-box policy, unrelated to NTVDM.
- [DOSEMU upstream dpmi.c](https://raw.githubusercontent.com/dosemu2/dosemu2/devel/src/dosext/dpmi/dpmi.c),
  CLI handling and `dpmi_timer`: recognizes legacy save/CLI patterns and
  optionally reenables interrupts after a CLI timeout when POPF was missed.
- [Windows 95 DDK VPICD descriptor](https://techshelps.github.io/MSDN/WIN95DDK/HTML/S34DA.HTM):
  virtual IRQ return timeouts prevent hangs. This does not specify a POPF
  detector or justify acknowledging a virtual PIC without a handler frame.

Decision: keep verified saved-image arming as the cheap path, but when an
arbitrated unmasked IRQ is pending with PM virtual IF clear, acquire actual
CPU boundaries with monitor-owned TF. Inspect POPF/POPFD/IRET/IRETD images
before stepping and restore virtual IF only after the CPU reports retirement
with DR6.BS. Stop before flags saves, SS shadows, software interrupts and
context transfers using the existing return-step safety rules; no monitor TF
may be saved by PUSHF. STI retains its existing one-instruction shadow.

A restore may already have retired before the first pending edge. Therefore
stepping alone cannot make the reported spin impossible. Use a compatibility
escape after 4096 retired steps or 100 ms of pending-IRQ wait, including waits
at unsafe tracing boundaries. Record an explicit forced recovery, distinct
from an observed restore. The 100 ms watchdog snapshots the original state
before recovery. This can shorten an unusually long intentional CLI section;
it is a legacy-game compatibility policy, not architectural IF semantics.
Never clear ISR, forge EOI, change masks or acknowledge before constructing
the complete existing handler frame. Debugger traps remain client events.

The T23 evidence shows pending unmasked IRQ0/IRQ1/IRQ7, no ISR, continuing
guest execution and PIT/DMA time, but virtual IF permanently clear. It proves
an interrupt-delivery gate failure; it does not prove VGA or scheduling causes.
The three logged seeds are previous trap boundaries, not save/CLI addresses.
The matching CLI PCs are 2464E8h, 2482D9h and 2465B2h. Static extraction of
the pinned DOOM.EXE (SHA-256
`b8020523561a5ad9706e009a52d61c578f37faafd85ac471962308406292ce27`)
finds those CLI bytes at file offsets 554FCh, 572EDh and 555C6h respectively.
Their common runtime/file displacement is 1F0FECh. The seeds at 248205h,
24821Dh and 2482DAh map to 57219h, 57231h and 572EEh. None of these IRQ-path
CLIs has an adjacent PUSHFD save. Fabricating a flags-image match would be
wrong: the handler/callback must eventually restore through STI or IRETD.
Host vectors will replay their extracted bytes and the return frame.

The inner ZIP is the concatenation of DOOMS_19.1 and DOOMS_19.2 in the
vendored outer ZIP. The bound payload MZ starts at 25214h, LE at 27ACCh;
LE object 1 has original base 10000h, size 44F71h, page size 1000h and
first data page at MZ-relative 1CE00h (file offset 42014h). The common
displacement above implies runtime object base 233000h. These header and
page-map values provide the file-to-runtime mapping independently of
backwards instruction decoding. The three CLI slices retained in the
tests are:

```
2464E8: FA 89 EA 1E 07 8D 04 D5 00 00 00 00 01 D0
2482D9: FA 31 DB 31 D2 66 8B 1D 30 88 02 00 A1 20 88 02 00
        F7 F3 85 D2 0F 94 C0 25 FF 00 00 00 5D 5F 5E 5A 59 5B C3
2465B2: FA A1 F0 83 02 00 05 00 10 00 00 8B 1D E8 83 02 00
        A3 F0 83 02 00
```

The callback's entire arithmetic and return epilogue is executed by
libx86emu against production monitor memory. The handler slices end
before their branch-heavy bodies and use a supplied same-ring IRETD
continuation. This is instruction/monitor evidence, not a whole-game replay.
The IRQ wrapper in the original executable ends with
`0F A9 0F A1 07 1F 61 CF` (POP GS/FS/ES/DS; POPAD; IRETD).

`arm_flags_image` now compares PUSHFD's legal AC/ID high bits as well as
the status flags, while retaining the forward-boundary proof. The fallback
does not manufacture matches for the three plain IRQ-path CLIs. Its own BS
traps cannot trigger the saved-image detector. A timed escape keeps the
saved-image TF owner alive until that image is eventually restored, so the
patched image cannot later raise an orphaned client #DB. A client-supplied
TF image, watchpoint, VM/NT return, invalid target or unreadable stack is
not claimed by tracing. Faults do not count as retired restores.

Performance decision: the source samples earlier intervals but its final
dump retains only the last sixteen (81 collected intervals would start
at n=66). The supplied clean log begins partway through the n=66 dump and
does not retain its `vm_perf_samples total` header; it cannot establish an
exact total or sampler start time. Retain the first four intervals
plus the latest twelve in the same fixed storage, sample during startup and
guest IRQ execution, and continue dumping outside the running game. This
preserves first-second evidence without UART writes in the frame budget.

Host verification and the lead's remaining QEMU/T23 gates are recorded in
`build/codex/f3-15-report.md`. The arbiter includes PIC masks, priorities,
cascade and ISR blocking: recovery does not override those gates. The
100 ms age starts when the worker first sees this recoverable pending-IRQ
condition. Physical timer exits bound a running PM spin; no timer-hook UART
output was added. Diagnostics use the existing guest-IRQ deferral queue and
a maximum of sixteen snapshots per VM. Quiet boots use the same recovery.
`pc=CS:EIP`, `seed=valid:CS:EIP` and `arm` keep the gate row compact;
the image row's `ok=code,stack` flags describe its guarded reads and
`path=trap` identifies the implementation. Full-width generation, sequence
and 64-bit age controls verify both complete rows fit the 240-byte envelope.
