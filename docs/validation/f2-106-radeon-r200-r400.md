# Radeon R200/R300/R4xx MMIO extension

## Research and implementation decisions

The binding family/command contracts are read from the lead checkout: they
are absent from this worktree's f2-103 base. The f2-106 directive has no
appended amendments. Display-model Amendment 1 and the family contract's
lead decisions apply. This document records host evidence only.

- [Linux v6.12 `radeon_base.c`](https://github.com/torvalds/linux/blob/v6.12/drivers/video/fbdev/aty/radeon_base.c),
  `radeonfb_pci_table`, together with `aty/ati_ids.h` and `radeonfb.h`:
  enumerate discrete primary R200/RV250/RV280, R300/R350/RV350/RV380 and
  R420/R423 functions explicitly. Exclude integrated RS/Xpress, secondary
  functions, R500 and unmatched refreshes. The aggregate pack census includes
  secondary functions and is not an activation whitelist.
- [Linux v6.12 `radeon_accel.c`](https://github.com/torvalds/linux/blob/v6.12/drivers/video/fbdev/aty/radeon_accel.c),
  `radeonfb_engine_init`, and
  [`include/video/radeon.h`](https://github.com/torvalds/linux/blob/v6.12/include/video/radeon.h):
  R300 variants preserve `RB2D_DSTCACHE_MODE` and enable AUTOFLUSH and
  DISABLE_IGNORE_PE. R200 uses the earlier zero-mode setup. Keep the
  generation-specific setup, verify its readback and refuse inaccessible
  registers. Do not import engine reset, PLL, CP, DMA or GART code.
  Added generations verify the entire MC framebuffer window (base and top), not only its base;
  constrain visible bytes and cursor storage to that window. The original
  twelve R100 IDs remain unchanged; RN50 is not added by this extension.
- [X.Org ATI `xf86-video-ati-6.14.6`, `src/radeon_accelfuncs.c`](https://github.com/freedesktop-unofficial-mirror/xorg__driver__xf86-video-ati/blob/xf86-video-ati-6.14.6/src/radeon_accelfuncs.c),
  `RADEONSetupForMono8x8PatternFill`, `RADEONSubsequentMono8x8PatternFillRect`,
  `RADEONSetupForScanlineImageWrite`, `RADEONSubsequentScanlineImageWriteRect`
  and `RADEONSubsequentScanline`, with
  [`radeon_reg.h`](https://github.com/freedesktop-unofficial-mirror/xorg__driver__xf86-video-ati/blob/xf86-video-ati-6.14.6/src/radeon_reg.h):
  port only the little-endian MMIO branch. Pack MSB-left pattern bytes
  explicitly. Upload complete, bounded single-row packets that fit an empty
  64-slot FIFO, including padded pixels and terminal HOST_DATA_LAST writes;
  clip padding and wait for completion after each row. Wider calls refuse
  before submission and use the existing software dispatcher.
- [X.Org ATI `xf86-video-ati-6.14.6`, `src/radeon_cursor.c`](https://github.com/freedesktop-unofficial-mirror/xorg__driver__xf86-video-ati/blob/xf86-video-ati-6.14.6/src/radeon_cursor.c):
  the pre-AVIVO cursor register/locking path is shared across these groups.
  Preserve Ciuki's coverage/selector semantics, separate VRAM lease and
  hide-before-replace; this is not an ARGB capability. Pre-AVIVO cursor
  offsets remain relative to VRAM, including with a nonzero 2D MC base.
- [X.Org UMS feature matrix](https://www.x.org/RadeonFeatureUMS/):
  distinguishes R100/R200/R300/R400 XAA support; it does not establish that
  a host fixture qualifies physical cards. Each group must pass its own
  saved-pixel native comparison before becoming active. Optional pattern and
  upload capabilities have separate runtime comparison gates.
- Windows 98 Resource Kit, chapter 24, `wrkc24_3.htm`, "Display Driver
  Overview", read in the owner's read-only extraction: keep the DIB-style
  software reference/fallback in the generic dispatcher. A timeout is not
  permission for CPU access; cached idle proof remains mandatory.

Shell downloads were denied DNS access. The exact pinned Linux/X.Org donor
files already researched for f2-103 were copied read-only into this
worktree's `build/research/`; their SHA-256 values are checked against the
existing source manifest. Online primary-source checks used the web tool.

Only existing part A pattern/WRITE/monochrome-cursor hooks are exposed.
MONO/INVERT/KEYED/LINE and ARGB dispatch depend on the separate f2-101d hook
and capability allocation; no public ABI numbers are invented here.

The hardware display name is `ATI Radeon R100/R200/R300/R4xx`. The existing
generic device inventory and Control Panel engine query carry that name;
no new application-side PCI table or driver-specific UI policy is required.
The result row is in the existing display-model contract's family table.

The initial upload bound is 48 dwords per row (96 pixels at 16 bpp, 64 at
24 bpp, 48 at 32 bpp). All setup plus payload fits an empty FIFO. Oversized
calls punt before submission. The engine completes each row before polling
or releasing the presenter; failures after any row retain partial-operation
semantics. No offscreen rows or ARGB cursor are advertised. Nonzero chip-local
bases have rectangle, pattern, upload and cursor fixture coverage.
Upload also checks a whole-transfer deadline between rows and releases the
presenter after 1 ms or sixteen completed rows, including with a frozen clock.

[QEMU v9.2.0 `hw/display/ati.c`](https://github.com/qemu/qemu/blob/v9.2.0/hw/display/ati.c)
implements `CNFG_MEMSIZE` but not `MC_FB_LOCATION`. Preserve the existing
zero-base R100 proof using that size plus the firmware/PCI lease bounds;
do not interpret the unimplemented zero register as a 64 KiB aperture.
The added R200/R300/R4xx groups require consistent MC base/top bounds.

The implementation has 84 explicit PCI IDs: 12 existing R100, 17 R200,
39 R300 and 16 R4xx. Nine representative added chips run the complete host
matrix. These are source/host coverage counts, not physical qualification.

The web tool could not retrieve the separately named `include/drm/drm_pciids.h`
or XA generated chipset headers at the pinned tags; shell downloads also
failed DNS. The whitelist therefore uses the narrower inspected Linux fbdev
PCI table and its pinned `ati_ids.h`, rather than expanding from the pack.
AMD's R3xx 3D document was inaccessible (401); the X.Org R5xx acceleration
PDF returned 403 and is not used as proof for earlier 2D silicon. The
successfully inspected Linux/X.Org register references are the register
authority for this port.

## Verification

Sequential `nice -n 19` host runs passed: `test_radeon2d.py` (2 tests),
`test_display_driver_model.py` (7, including 1,703 ABI layout checks),
`test_display_driver_names.py` (2), `test_hardware_check.py` (8),
`test_presenter_display.py` (4), the kernel-switch/checkpoint cases of
`test_display_modes.py` (2), and `test_credits.py` (8). The unchanged Savage
register/presenter fixture passed with its repository ASan/UBSan settings.
The Radeon target check compiled three production i686 objects with the
canonical flags; `nm` found ten unique external definitions, no duplicates.

The register model covers all four pixel formats, all four copy directions,
pattern origin and bit order, exact host-data sequences, padding/clipping,
native-only activation/DM9 failures, clean software punts, upload deadlines
and frozen-clock slices, cursor faults and unsafe quarantine. It tests nine
representative added chips and the retained R100 path; every whitelist ID
also receives a read-only probe/ownership check. Runtime native comparisons
have no hidden software drawing.

The optional `CIUKI_DISPLAY_ASAN=1` Radeon run completed its assertions with
zero failures but exited unsuccessfully when LeakSanitizer could not use
ptrace in the sandbox. Leak checking was not disabled; this is incomplete
sanitizer evidence. No public ABI/SDK header changed. Physical qualification,
lead integration/build and additional part C operation ports remain pending.
Exact commands, results, source links and handoff items are recorded in
`build/codex/f2-106-report.md`.
