# F3-11: IRQ0 in-service investigation

Host investigation of `docs/directives/f3-11-doom-irq0-in-service-stall.md`.
The T23 stall is **not reproduced or attributed** by the host evidence below.
Hardware acceptance remains open; do not describe the consistency fix as a
verified DOOM hardware fix.

Research checked on 2026-10-13 before implementing the consistency fix:

- [Intel 8259A datasheet, December 1988](https://pdos.csail.mit.edu/6.828/2010/readings/hardware/8259A.pdf),
  interrupt sequence and fully nested/EOI modes (pp. 7–8, 15): acknowledgement
  consumes IRR and establishes ISR; an outstanding ISR blocks requests of
  equal/lower priority until EOI. AEOI ends service at acknowledgement.
  Decision: the virtual CPU must have a complete handler frame before the
  virtual PIC acknowledges. A failed frame construction cannot claim delivery.
  Preserve pending requests, priorities, guest EOI and masks; never time out
  an ISR bit by sending EOI automatically.
- [Intel SDM Vol. 3B, section 18.3.1.4](https://cdrdv2-public.intel.com/825748/253669-sdm-vol-3b.pdf):
  setting TF with POPF delays single-step until the following instruction;
  MOV/POP SS inhibits single-step through its successor. Decision: replay
  the saved-image #DB with BS present and a simultaneous PIT edge, and label
  the monitor's TF owners in diagnostics rather than suppressing valid traps.

## Repository findings and changes

`dpmi_deliver` acknowledged and counted an interrupt before calling
`dpmi_enter_pm_handler` or `dpmi_to_real_int`. A stale selector, exhausted
locked stack, rejected PM frame write or invalid real reflection can leave
the original CPU frame unchanged but IRQ0 consumed, ISR0 set and delivery
count incremented. The new host test fails this invariant on the original
dispatch and passes with acknowledgement/counting after successful construction.
Arbitration, construction and acknowledgement now share one short IRQ-disabled
transaction. The constructors perform bounded checked memory transfers without
sleeping or printing. This fixes a real error path. In normal `dosvm_trap`,
however, that error stops the VM; it does **not** explain a client continuing
to spin with the observed T23 record. No DB path discarding an injected frame
has been reproduced.

EOI emulation in `v86_io`/`dosvm_pic_register` has no armed/shadow filter.
The production-trap replay covers EOI with these states set and virtual IF
clear, the next pending IRQ, and both host IRQ returns. These checks pass
on the original implementation too. The reported master IMR=F8 leaves IRQ0
unmasked; the ordinary non-AEOI/non-specific EOI path is covered. Neither
swallowed EOI nor EOI applied to a different virtual PIC has been demonstrated.

`GUEST_IRQ0_RESTORE=0x247fac` in the DOOM libx86emu harness advances the real
virtual PIT by eight milliseconds immediately before the armed PM #DB at
that exact PC. It changes no guest instructions and fails if the boundary
was not reached. On the original dispatch at 40,000 instructions/ms:

```
restore edge: pc=01df:00247fac vif=0 armed=1 irr=01 isr=00 edges=57->58
menu replay: PASS ms=1200 irq0=168 irq1=8 bytes=8 images=1/1/1
menu sustain: PASS ms=2400 irq0=336 flips=84 dma_units=52920
```

Thus arm → restore #DB → simultaneous IRQ0 edge is insufficient to reproduce
the hardware stall. A slower 1,000-instructions/ms run also services IRQ0 but
fails the menu pixel test (one flip in 1,200 simulated ms). An unforced
4,000-instructions/ms run services IRQ0 but misses the restored-title digest.
These are different host timing failures, without the reported ISR0 freeze;
they must not be counted as a before/after stall reproduction.

## TF ownership and cost

The reported first real-mode DB PCs are reproduced exactly by the original
DOOM replay: `0000:7C51`, `0800:0013`, `0300:00A8`, `132E:010B`,
`13D7:0112`, `1753:010B`. They are SS/successor boundary traps, not a
permanently single-stepped VM. `if_armed` belongs to the DPMI saved-image
mechanism; it does not describe V86 boundary tracking or PM return tracing.

`v86_prepare_return` sets TF only for an SS/STI shadow or a deliverable
pending IRQ. The successor clears the shadow, delivery clears TF, and the
next return clears TF when neither condition exists. V86 PUSHF hides monitor
TF; even an arbitrary register value loaded by POPF cannot preserve TF past
the monitor return. New host checks exercise all these paths. PM return
tracking retains its existing maximum 512 instructions per seed and stops
before flags saves/loads, CLI/STI and SS/context transfers. The limit is per
seed, not a lifetime limit; repeated short functions can still incur repeated
bounded tracing. The guest harness counts real-mode, flags-image, owned-return
and other DB traps so that this cost is measurable.

The final forced-edge sound/menu run executes 309,920,004 guest instructions
with 4,939,511 monitor traps. DB ownership counts are **14 real-mode boundaries,
17 flags restores, 4,608,932 return boundaries, zero other DB traps**. Return
tracing is 1.49% of guest instructions (about one DB per 67 instructions).
That is substantial exception overhead despite each seed's cap; it is not
a measurement of T23 wall time or proof that tracing explains its 20-second
startup. No new global tracing budget or compatibility policy was introduced.

Verbose `group=vm_db` adds `step=rm_ss`, `rm_irq`, `pm_flags`, `pm_return` or
`client`; `rm_tf` identifies a real-mode BS without a matching shadow/pending
IRQ. PM return ownership checks CS/SS/client/depth. This makes `armed=0`
meaningful without adding per-instruction logs.

## Stall diagnostic

Each PIC acceptance (including poll) timestamps the service episode. EOI and
reinitialization clear the reported bit; a new acceptance restarts its age,
including EOI/reinjection within a single monitor trap. The worker checks both
PICs on trap entry and while sleeping in guest HLT. With verbose boot enabled,
an ISR bit older than 1,000 host ticks produces:

```
[dosvm] event=pic_stall vm=1 gen=1 pic=0 irq=0 ms=1001 cs=01df eip=002483e2 isr=01 irr=01 imr=f8 vec=08 to=00ff:00000020 boundary=if_restore at=01df:00247fac
```

`vec` and `to` identify the last delivered vector and target; `boundary`/`at`
retain the last flags or return-tracking event even after the older trace
budgets run out. `pm`, `depth`, `ae` and `sm` distinguish mode/nesting and
PIC AEOI/special-mask state. The diagnostic prints with physical IF enabled, once per
service episode, at most 32 times per VM lifetime. It does not acknowledge,
clear, mask or deliver interrupts. Host tests cover strict >1s timing, repeated
samples, EOI/reinjection, AEOI, poll, both PICs, reinit, clock wrap, quiet boot,
full-width fields and the lifetime cap.
