# F3-16: planar VGA direct-window investigation and host replay

Directive: `docs/directives/f3-16-vga-planar-direct-window.md`. This record
contains host evidence; QEMU and T23 acceptance belong to the lead.

## Sources checked before implementation

- [FreeVGA memory access](https://www.scs.stanford.edu/22wi-cs212/pintos/specs/freevga/vga/vgamem.htm)
  and [sequencer registers](https://www.scs.stanford.edu/22wi-cs212/pintos/specs/freevga/vga/seqreg.htm):
  read mode 0 returns the read-map plane, independently of the write map mask.
  Every CPU read loads all four latches. Write mode 1 ignores CPU data and
  writes those latches. Ordinary write mode 0 is an identity store only with
  set/reset disabled, no rotation/logical operation and bit mask FFh.
- [Abrash chapter 47](https://www.phatcode.net/res/224/files/html/ch47/47-01.html),
  [chapter 48](https://www.phatcode.net/res/224/files/html/ch48/48-01.html):
  unchained 256-colour modes address four independent planes; latch copies
  transfer four different source bytes, rather than broadcasting a CPU byte.
- [Wolf3D ID_VL.C](https://github.com/id-Software/wolf3d/blob/master/WOLFSRC/ID_VL.C)
  (`VL_DePlaneVGA`, `VL_MemToScreen`, `VL_LatchToScreen`) and
  [WL_SCALE.C](https://github.com/id-Software/wolf3d/blob/master/WOLFSRC/WL_SCALE.C)
  (`BuildCompScale`, `ScaleLine`): the scaler reads texture bytes from RAM
  and stores vertically at stride 80 into A000, with single or multiple
  enabled planes. The latch blitter selects write mode 1/map mask 15 and
  uses video-to-video REP MOVSB; it restores write mode 0 afterwards.
- [DOSBox 0.74-3 upstream memory handlers](https://sources.debian.org/src/dosbox/0.74-3/src/hardware/vga_memory.cpp/):
  unchained reads explicitly load the four-byte latch; write modes compute
  each selected plane's result from the latch and graphics registers.
- [Intel SDM Vol. 3A](https://cdrdv2-public.intel.com/874249/253668-090-sdm-vol-3a.pdf),
  paging and invalidation sections (5.8/5.10 in revision 090): page dirty
  bits track writes at 4 KiB granularity. Clearing D requires invalidating
  the translation before the guest resumes. Legacy IA-32 paging provides
  one physical translation for reads and writes; writable pages are readable.
  The existing `as_map` clears D and executes INVLPG when that address space
  is active; a later CR3 switch invalidates an inactive space's translations.

The public id DOOM source is the Linux port and has no DOS `i_ibm.c`.
The four 16000-byte plane passes/CRTC 0C/0D replay follows the directive's
specified DOS pattern; it is not an executable or a measured game trace.

## Findings and implementation constraints

The supplied T23 sample (`fb3147dc`) has 226 presentations, 103 start-address
high writes, 7031 dirty plane pages, 23812 aperture faults, chain=0 and
linear=0. It establishes planar operation and substantial trapped traffic;
it does not classify the faulting instructions or prove that plane switching
alone caused the faults. The old one-plane path already maps all sixteen
A000 pages writable and harvests only D pages. `planes` counts harvested
pages (`video_flushes`), not map-mask changes (`video_maps`).

Two required semantics cannot be obtained from an ordinary writable shadow
and page dirty bits alone:

1. A store into write plane 1 followed by a native read with read map 0 must
   return plane 0, and must load four latches. A shared read/write mapping
   returns its own stored byte and cannot observe the read's address.
2. With mask 3 and unequal plane contents, copying an entire dirty shadow page
   into both planes overwrites bytes the guest never wrote. A shadow diff also
   misses a store equal to the seed value, which must still update the other
   plane. A page D bit cannot identify those bytes.

Preserve the full model for latch-dependent write modes, rotation/logical
operations, set/reset, partial bit masks and sparse multi-plane stores. Do
not claim that a page-copy broadcast or a mapped read implements those
semantics. Record harvest CPU cost and dirty-page counts separately from
present CPU cost; all performance diagnostics remain verbose-only and
per-second output remains deferred.

## Implemented subset

- Keep the existing single-plane and chain-4 mappings and their D-page
  harvests. No shadow broadcast, byte-diff approximation, or new eligibility
  rule is introduced: those cannot satisfy the exactness requirements above.
- Harvest the current mapping before either CRTC start-address byte is
  written, including redundant writes. Clean pages and other planes are not
  marked. Both colour and monochrome CRTC port pairs use this boundary.
- A frame digest now synchronizes without closing the aperture. Previously
  a planar digest left it supervisor-only until a changed register reopened
  it, because `dosvm_vga_retry` admits only chain-4. A snapshot in the middle
  of a plane pass could therefore strand subsequent stores. This is a
  demonstrated host path, not an attribution of the T23 log's faults.
- Count complete harvest CPU time, including clean-page scans and D-bit
  invalidation. Add deferred `vm_perf_harvest` rows (`dirty_pages`,
  `harvest_us`) and a coherent cumulative `vm_beat_vga_mem` heartbeat row
  (`harvests`, `dirty_pages`, `harvest_us`). Companion rows preserve the
  existing fields and the 240-byte record envelope. Present time includes
  harvests performed inside present; the two times are not additive.
- Add the production presenter/replay benchmark to the sequential kernel
  host script. Native host stores resolve the actual PTE frame, including
  the model's static host planes, instead of bypassing the mapping.

Current eligibility is deliberately unchanged:

| Access state | Current path | Reason/limit |
| --- | --- | --- |
| Unchained, one plane, ordinary mode 0 | Existing direct plane | Stores are exact; native reads have the limitations above. |
| Identity 320x200 chain-4 | Existing direct linear backing | Harvest deinterleaves dirty pages; native latch loads are not observed. |
| Multiple planes, ordinary mode 0 | Trapped model/bounded scaler burst | Partial and same-value stores need exact byte identity. |
| Write mode 1 | Trapped model | Four independent latch bytes; never a CPU-byte broadcast. |
| Write modes 2/3, set/reset, rotation/logic, partial bit mask, read mode 1 | Trapped model | CPU data is transformed or depends on latches. |

Thus the dominant wider Wolf3D strips and latch copies are **still trapped**.
The universal exact-native-read requirement is **still unmet** by the old
direct path. This subset does not close F3-16. Completing it needs a revised,
cross-reviewed directive specifying how to observe native reads and precise
multi-plane writes, or an explicit restriction to verified write-only paths.
Even the latter does not make sparse multi-plane page broadcasts exact.

## Replay method

`tests/host/dosvm_present_bench.c` runs 120 frames per replay with production
ports, paging, decoder, burst path, harvests and presenter. The host substitutes
native CPU loads/stores and hardware PTE D updates, as in the existing workload
harness; these are not measured hardware page faults or game FPS.

DOOM uses masks 1/2/4/8, 16000-byte stores per plane, three aligned video
pages and CRTC 0D/0C writes. Each pass touches four pages, giving 16 dirty
pages and four nonempty harvests per frame. Wolf3D uses the existing compiled
scaler replay at heights 300/100/50 and strip widths 4/2/1. A further latch
case copies a 32x32 image by 32 REP MOVSB rows of eight bytes, with distinct
contents in all four planes. Each replay checks independently expected plane
bytes; the latch case also checks the final four latches.

Timing uses CLOCK_MONOTONIC at the host TSC seam with a 1 GHz conversion,
ASan/UBSan and `-O2`. Baseline uses HEAD's `dosvm_vga.c` with only the harvest
clock added, the same current harness/counter definitions and the same build
flags. This isolates the CRTC/digest behavior changes without an image build.
Fault and dirty-page counts are deterministic; timings include host harness
overhead and workstation contention and do not establish a speedup on T23.

## Host validation

- Kernel host suites, presenter/replay bench, independent VGA vectors and
  all five video goldens pass with ASan/UBSan. DOS VM suite: 5,688,749
  checks, maximum record 232 bytes. LeakSanitizer is disabled because this
  sandbox cannot provide its ptrace operation; VM cleanup ledgers still run.
- `make test-host` completes kernel and loader suites, then runs 539 Python
  controls with two missing-input errors and 29 skips. The inputs are the
  pinned Lua source archive and `build/f0/files-payload.elf`; neither error
  depends on changed VGA sources. The verified archive is reused from the
  existing cache, and the already generated host files payload is temporarily
  linked at the expected path. Isolated terminal (2) and kernel stack (4)
  reruns pass. The temporary link is removed; font controls (9) pass.
- All 18 consumers of the changed internal header plus `virtual_vga.c` and
  `vga_presenter.c` compile with the canonical i686 flags and pass the
  integer/FPU/SIMD audit (20 units). `git diff --check` passes.
- The optional DOS executable host runner is skipped for unavailable
  libx86emu/DOSBOOT inputs. No QEMU, canonical image build, commit or diary.

F3-VM video/window QEMU cases, DOOM/Wolf3D QEMU twins and T23 gameplay
qualification remain lead-owned and require evidence tied to the integrated
image SHA-256. Flat gameplay faults and the 35/70 FPS targets remain open;
this change does not provide the requested general exact shadow mechanism.
